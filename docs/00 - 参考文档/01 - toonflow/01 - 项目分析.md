# Toonflow 项目全面分析

> 分析对象：`refer/Toonflow-app-master`（新版 master，版本 v1.1.8）+ `refer/Toonflow-app`（旧版 v1.0.6，作为演进对照）
> 分析日期：2026-08-09

## A. 项目定位

Toonflow 是一款 **AI 短剧/漫剧生产工具**，核心理念是"小说秒变剧集"。它把 AI 能力串成一条完整的工业化生产流水线：

> 小说 → 事件提取 → 剧本 → 资产生成 → 分镜(故事板) → 图片 → 视频合成

采用 **Apache-2.0** 开源协议，提供 **Web 服务 + Electron 桌面客户端 + Docker** 三种形态。版本由 v1.0.6（旧）演进至 v1.1.8（新），核心从"分镜/大纲两 Agent"升级为"剧本+制作两大智能体 + 技能体系 + 向量记忆"。

## B. 技术栈（新版 v1.1.8）

1. **后端框架**：Express 5 + `express-ws`（REST WebSocket）+ **socket.io**（AI 对话，`/api/socket/*`），入口见 [app.ts](file:///c:/Users/qsevn/Desktop/Code/duanju/refer/Toonflow-app-master/src/app.ts)
2. **AI 层**：Vercel **AI SDK v6**（`ai@6.0.67`）+ 各家 provider（@ai-sdk/openai、deepseek、google、anthropic、xai、openai-compatible、zhipu、qwen、minimax）
3. **数据层**：SQLite + **Knex** ORM + `better-sqlite3` + `sqlite3`
4. **向量化**：`@huggingface/transformers` + onnxruntime（本地 ONNX，默认 all-MiniLM-L6-v2）
5. **图像处理**：`sharp`（含按需缩略图 `/oss?size=`）
6. **验证**：`zod@4` | **安全**：`vm2`、`is-path-inside`
7. **桌面壳**：Electron 40 + `electron-builder` | **构建**：`tsx` + `sucrase` + nodemon + cross-env

> 关键差异：旧版用 `express-ws` 直连分镜/大纲 Agent；新版改为 **socket.io 命名空间**承载 scriptAgent / productionAgent 两大智能体，并引入本地向量嵌入。

## C. 架构设计亮点

### C.1 约定式路由 + 代码生成

[core.ts](file:///c:/Users/qsevn/Desktop/Code/duanju/refer/Toonflow-app-master/src/core.ts) 通过 `fast-glob` 扫描 `src/routes/**/*.ts`，自动生成 `src/router.ts`（MD5 hash 去重）。

- 文件名即路由：`addAssets.ts` → `/assets/addAssets`
- 子目录即子路径：`production/storyboard/addStoryboard.ts` → `/production/storyboard/addStoryboard`
- `index.ts` 特判为根路径；`[param]` 支持动态路由
- routes 按业务域深度嵌套：`novel/event`、`production/{assets,editImage,storyboard,workbench}`、`setting/{agentDeploy,dbConfig,vendorConfig,skillManagement,...}` 等 **20+ 个一级域**

### C.2 数据库类型自动生成

[db.ts](file:///c:/Users/qsevn/Desktop/Code/duanju/refer/Toonflow-app-master/src/utils/db.ts) 用 `@rmp135/sql-ts` 扫描实际表结构，自动生成 `src/types/database.d.ts`，保证 TS 类型与真实 schema 同步。数据库文件：Electron 下放 `userData/db.sqlite`，否则放 `cwd/db.sqlite`。

### C.3 AI 统一抽象层

[utils/ai.ts](file:///c:/Users/qsevn/Desktop/Code/duanju/refer/Toonflow-app-master/src/utils/ai.ts) 提供 `u.Ai.Text(key, think?, level?)` 统一文本入口，按业务 key（如 `scriptAgent:decisionAgent`）经 `o_agentDeploy` 分配模型，支持**思考模式**（think + level 0-3 四级）。图像/视频按厂商分发，统一处理 base64 头、URL→base64、流落盘。

### C.4 厂商体系（vendorConfig）

旧版的硬编码厂商映射，新版改为**可配置的厂商体系**：
- `o_vendorConfig` 表存厂商（id/inputValues/models/enable）
- `/setting/vendorConfig/*` 系列接口：增删改厂商/模型、启停、模型测试（text/image/video）、通过链接获取 code
- `/setting/agentDeploy/*`：按 Agent 分配模型（普通/高级两档、temperature、maxOutputTokens、批量）

### C.5 本地向量化

[embedding.ts](file:///c:/Users/qsevn/Desktop/Code/duanju/refer/Toonflow-app-master/src/utils/agent/embedding.ts) 用 @huggingface/transformers 本地跑 ONNX 嵌入模型（allowRemoteModels=false），`getEmbedding` + `cosineSimilarity` 支撑记忆 RAG。

## D. Agent 智能体设计（核心业务）

新版两大智能体均由 **决策层（runDecisionAI）+ 子 Agent（createSubAgent）** 双层构成，经 socket.io 流式交互。详见《05 智能体模块》。

### D.1 剧本智能体 scriptAgent

- **决策层**：读技能文件 `script_agent_decision.md`，组装项目信息 + 记忆，流式调用
- **子 Agent**（各读独立技能文件）：storySkeleton（故事骨架）、adaptationStrategy（改编策略）、script（剧本，输出 `<scriptItem>`）、supervision（监督）
- **业务工具**：get_novel_events / get_planData / get_novel_text / get_script_content
- **记忆**：`memories` 表 + embedding + deepRetrieve

### D.2 制作智能体 productionAgent（导演台）

- **决策层**：读 `production_agent_decision.md`，注入图像/视频模型信息
- **子 Agent**（7 个）：derive_assets / generate_assets / director_plan / storyboard_gen / storyboard_panel / storyboard_table / supervision
- **技能绑定**：按项目 `artStyle`（画风）/`directorManual`（导演手册）动态扫描 `skills/{art_skills,story_skills,production_skills}` 技能文件，注入 `activate_skill` 工具
- **业务工具**：get_flowData / add_deriveAsset / del_deriveAsset / generate_deriveAsset / generate_storyboard / add_flowData_storyboard（含串行队列防假死）

### D.3 技能体系（skill）

新版**最核心能力**，见 [skillsTools.ts](file:///c:/Users/qsevn/Desktop/Code/duanju/refer/Toonflow-app-master/src/utils/agent/skillsTools.ts)：
- 技能为 **markdown 文件**，带 frontmatter（name/description）
- `createSkillTools` 提供 `activate_skill` / `read_skill_file` 两个工具，含 `isPathInside` 路径穿越防护
- 管理接口：`/setting/skillManagement/{getSkillList,getSkillContent,saveSkillContent}`

### D.4 向量化记忆系统（Memory）

见 [memory.ts](file:///c:/Users/qsevn/Desktop/Code/duanju/refer/Toonflow-app-master/src/utils/agent/memory.ts)：
- `memories` 表 + embedding + cosineSimilarity 做 RAG
- 三级记忆：shortTerm（近期）、summaries（摘要）、rag（向量检索）
- `deepRetrieve` 工具做深度召回；自动摘要（每 3 条消息）

## F. 鉴权与交互

1. [app.ts](file:///c:/Users/qsevn/Desktop/Code/duanju/refer/Toonflow-app-master/src/app.ts)：全局 JWT 中间件，`/login/login` 白名单，tokenKey 从 `o_setting` 读取
2. **静态资源**：`/oss`（含按需缩略图 `?size=WxH|pct`）、`/skills`（仅图片，403 拦截）、`/assets`、`/web`
3. **AI 对话**：socket.io 命名空间 `/api/socket/{scriptAgent,productionAgent}`，JWT handshake 鉴权，`chat/stop/updateThinkConfig/updateContext` 事件
4. **异步任务**：图片/视频/提示词生成均异步，`taskRecord` 管理状态，前端轮询 `pollingImage` / `checkVideoStateList` 等

## G. 可借鉴点与注意事项

### G.1 值得借鉴

1. 约定式路由 + 代码生成，新增接口零配置（含深嵌套子目录）
2. 数据库类型逆向生成，避免手写类型漂移
3. **技能体系**：markdown 技能文件 + activate_skill 工具，实现"不写代码扩展 Agent 能力"
4. **厂商可配置化**：vendorConfig 把硬编码厂商改为运行时配置，扩展新模型无需改源码
5. **向量化记忆**：本地 ONNX 嵌入 + RAG + deepRetrieve，长期记忆可检索
6. Agent 双层架构（决策层 + 子 Agent）+ 流式消息协议（ResTool），生产可控
7. 按需缩略图 `/oss?size=`，前端加载性能优化

### G.2 潜在问题

1. `o_setting` 中 `tokenKey` 明文存储且较短，`o_vendorConfig` 的 apiKey 存明文，安全性较弱
2. 大量 JSON 序列化字段（`data`/`content`/`flowData`/`inputValues`）缺乏约束，schema 演进靠约定
3. `o_agentWorkData`、`memories` 等表使用 UUID/文本主键，无物理外键，引用完整性靠逻辑保证
4. 本地向量模型文件体积大，首次加载慢（尽管 allowRemoteModels=false）
5. 存在 `resTool copy.ts`、`getConfig copy.ts` 等"copy"残留文件及 `visualManual.ts`/`editDirectorlManual.ts` 拼写不一致，代码整洁度一般
6. 前端 `scanSkills.ts` 调用的 `POST /setting/skillManagement/scanSkills` 在后端**不存在**（只有 getSkillList/getSkillContent/saveSkillContent），前后端接口不一致

## H. 总结

本项目本质是把"文本理解(AI) → 视觉生成(图片/视频) → 数据编排(SQLite)"做成可扩展流水线。相较旧版 v1.0.6，新版 v1.1.8 的核心升级是：**引入技能体系（skill）、厂商可配置化（vendorConfig）、向量化记忆（Memory）、Agent 双层架构（scriptAgent/productionAgent）**。其**路由自动生成、技能可插拔、厂商配置化、类型逆向**四大机制，对短剧平台后端设计最具参考价值。
