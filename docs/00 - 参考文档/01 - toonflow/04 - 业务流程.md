# Toonflow 业务流程

> 分析对象：`refer/Toonflow-app-master`（新版 v1.1.8）
> 分析日期：2026-08-09
> 文档说明：本文档独立梳理新版 Toonflow 的核心业务流程，包括端到端生产链路、两大智能体内部机制、异步状态机、记忆与技能机制。接口清单见《03 功能模块》，表结构见《02 数据模型》，智能体见《05 智能体模块》。

## A. 核心生产流程（端到端）

```
小说原文导入 → 事件提取 → 剧本生成 → 资产提取/生成 → 分镜生成 → 图片生成 → 视频合成
(novel)      (event)    (scriptAgent)  (assets)      (storyboard) (image)   (workbench)
```

## B. 小说与事件提取流程

1. **导入**：`/novel/addNovel` 逐章写入 `o_novel`（chapterIndex/reel/chapter/chapterData）
2. **事件提取**：`/novel/event/generateEvents` 清洗小说原文，AI 抽取事件
3. **事件存储**：写入 `o_event`，通过 `o_eventChapter` 关联到 `o_novel` 章节
4. **状态跟踪**：`o_novel.eventState` 标记提取状态，前端 `/novel/getNovelEventState` 轮询

## C. 剧本智能体 scriptAgent 流程

走 socket.io `/api/socket/scriptAgent`，**决策层 + 4 子 Agent** 双层：

### C.1 决策层 runDecisionAI
1. 读取技能文件 `script_agent_decision.md` 作为 system prompt
2. 组装项目信息（名称/类型/简介/画风/画幅/章节数）+ 记忆 `buildMemPrompt`
3. `u.Ai.Text("scriptAgent:decisionAgent", think, level).stream()` 流式调用
4. 工具集 = 记忆工具（deepRetrieve）+ 业务工具（get_novel_events/get_planData/get_novel_text/get_script_content）+ 子 Agent（4 个）
5. onFinish 时把去 XML 标签后的结果写入记忆

### C.2 子 Agent 调度
| 子 Agent | 技能文件 | 输出 XML |
|---|---|---|
| storySkeleton | script_execution_skeleton.md | `<storySkeleton>` |
| adaptationStrategy | script_execution_adaptation.md | `<adaptationStrategy>` |
| script | script_execution_script.md | `<scriptItem name="剧本名">` |
| supervision | script_agent_supervision.md | 监督质量 |

- 每个子 Agent 独立 stream，经 `consumeFullStream` 消费，支持 reasoning/text-delta/error/finish
- 子 Agent 完成后 `removeAllXmlTags` 剥离 XML 存入记忆
- **剧本子 Agent**：先查 `o_script` 现有剧本（id:名称）给 LLM，避免覆盖
- **消息切换**：`ctx.msg.complete()` + `resTool.newMessage` 实现单 socket 多消息流

### C.3 数据落库
- 工作区数据写 `o_agentWorkData`（key=scriptAgent，含 storySkeleton/adaptationStrategy/script）
- 剧本写 `o_script`，通过 `/scriptAgent/setPlanData`/`updateData` 同步
- 记忆写 `memories` 表（isolationKey=${projectId}:scriptAgent）

## D. 资产生成流程

### D.1 资产提取（script/extractAssets）
1. 从 `o_script` 剧本内容按批调用 AI 识别角色/道具/场景
2. 写入 `o_assets`（type=role/tool/scene）
3. 通过 `o_scriptAssets` 关联剧本，`/script/pollScriptAssets` 轮询

### D.2 资产图像生成（assetsGenerate）
1. `/assetsGenerate/generateAssets` 启动生成，`taskRecord` 记录任务
2. 前端 `/assets/pollingImageAssets` 轮询
3. 完成后写 `o_image`，`/assets/pollingPromptAssets` 轮询提示词润色

### D.3 角色场景音频（cornerScape）
- `/cornerScape/batchBindAudio` 绑定音频，`o_assetsRole2Audio` 关联，`pollingAudio` 轮询

## E. 制作智能体 productionAgent 流程（导演台）

走 socket.io `/api/socket/productionAgent`，**决策层 + 7 子 Agent**：

### E.1 决策层
1. 读 `production_agent_decision.md`，注入项目图像/视频模型信息
2. 按项目 `artStyle`（画风）/`directorManual`（导演手册）动态扫描技能
3. 工具集 = 记忆 + 业务工具（get_flowData/add_deriveAsset/...）+ 子 Agent（7 个）

### E.2 子 Agent 调度
| 子 Agent | 技能文件 | 职责 |
|---|---|---|
| derive_assets | production_execution_derive_assets.md | 衍生资产分析写入 |
| generate_assets | production_execution_generate_assets.md | 生成衍生资产图像 |
| director_plan | production_execution_director_plan.md | 生成拍摄计划 `<scriptPlan>` |
| storyboard_gen | production_execution_storyboard_gen.md | 生成分镜 |
| storyboard_panel | production_execution_storyboard_panel.md | 分镜面板 |
| storyboard_table | production_execution_storyboard_table.md | 生成分镜表 `<storyboardTable>` |
| supervision | production_agent_supervision.md | 监督进度 |

每个子 Agent 注入 `activate_skill` 工具（画风/导演手册技能）。

### E.3 画布数据流
- `getFlowData`/`saveFlowData` 读写 `o_agentWorkData`（key=productionAgent）
- 资产/分镜经 socket 双向同步 + `o_assets`/`o_storyboard`/`o_assets2Storyboard` 落库
- 分镜图/视频经异步任务 + 轮询回填

## F. 异步任务状态机

新版所有生成类操作均异步，由 `taskRecord`（写 `o_tasks`）+ 前端轮询完成：

```
请求 ──▶ taskRecord(init) ──▶ [后台执行 AI/生成] ──▶ taskRecord(成功/失败)
                              ▲                          │
                              └──────── 前端轮询 polling ◀─┘
```

**轮询接口映射：**
| 生成类型 | 启动接口 | 轮询接口 |
|---|---|---|
| 资产图像 | `/assetsGenerate/generateAssets` | `/assets/pollingImageAssets` |
| 资产提示词 | `/assetsGenerate/polishAssetsPrompt` | `/assets/pollingPromptAssets` |
| 分镜图 | `/production/storyboard/batchGenerateImage` | `/production/storyboard/pollingImage` |
| 资产图（导演台） | `/production/assets/batchGenerateAssetsImage` | `/production/assets/pollingImage` |
| 视频 | `/production/workbench/generateVideo` | `/production/workbench/checkVideoStateList` |
| 剧本资产生成 | `/script/extractAssets` | `/script/pollScriptAssets` |

## G. 记忆与技能机制流程

### G.1 记忆写入（memory.add）
1. 插入消息到 `memories`（type=message）+ 计算 embedding（本地 ONNX）
2. 每累积 3 条未总结消息，AI 生成摘要（type=summary），标记 summarized

### G.2 记忆读取（memory.get）
- **shortTerm**：最近 5 条未总结消息
- **summaries**：最近 10 条摘要
- **rag**：对输入做 embedding，cosineSimilarity 向量搜索 top 3

### G.3 深度检索（deepRetrieve）
三级召回：向量搜摘要 → AI 判断相关性（judgeSummaryRelevance）→ 展开 relatedMessageIds 拉原始消息

### G.4 技能加载（useSkill/createSkillTools）
1. 按路径读技能 md 文件，解析 frontmatter（name/description）
2. 生成 `<available_skills>` XML（buildSkillPrompt）
3. 创建 `activate_skill`/`read_skill_file` 工具，LLM 按 description 匹配激活
4. 激活后把技能正文 + 资源打包注入上下文（isPathInside 防穿越）

## H. 关键设计模式

1. **Agent 双层架构**：决策层（runDecisionAI）统一调度，子 Agent 独立 stream + 独立消息
2. **技能可插拔**：markdown 技能文件 + activate_skill 工具，能力扩展不写代码
3. **厂商可配置**：vendorConfig 运行时配置供应商/模型，Agent 经 agentDeploy 分配
4. **向量化记忆**：本地 ONNX embedding + RAG + deepRetrieve，长期记忆可检索
5. **异步任务贯穿**：taskRecord + 轮询，避免长任务阻塞
6. **XML 结构化输出**：子 Agent 用 XML 标签（scriptItem/storySkeleton/scriptPlan/storyboardTable）分区流式渲染
7. **socket.io 双向**：AI 对话走 socket，REST 做数据 CRUD，职责分离

## I. 跨模块数据流转要点

1. **项目贯穿**：`o_project`（artStyle/directorManual/imageModel/videoModel）是全局上下文，注入各 Agent
2. **Agent 工作区枢纽**：`o_agentWorkData` 承载 scriptAgent/productionAgent 的中间产物
3. **资产多态**：`o_assets` 支持顶层（scriptId）与衍生（assetsId 指向父资产）两级，经 `o_scriptAssets`/`o_assets2Storyboard` 关联剧本/分镜
4. **记忆隔离**：memories 按 isolationKey（projectId:agentName）隔离，避免跨项目串味
5. **表前缀演进**：旧版 `t_` → 新版 `o_`，`t_taskList`→`o_tasks`，需注意跨版本迁移
