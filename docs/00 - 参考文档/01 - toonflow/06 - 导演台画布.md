# Toonflow 导演台画布（ProductionAgent 无限画布）

> 分析对象：`refer/Toonflow-web`（前端 Vue3 仓库）+ `refer/Toonflow-app-master`（新版后端，交叉核对接口与数据落库）
> 分析日期：2026-08-09
> 文档说明：本文档全面调研 Toonflow 的「导演台画布」——即 ProductionAgent（制作智能体）工作台。这是**偏前端**的核心功能，用类无限画布（VueFlow）把「剧本 → 导演计划 → 分镜表 → 资产 → 分镜图 → 视频合成」组织成可视化节点流，并通过右侧 AI 对话面板驱动生成。G 章后端接口已对照新版后端 `src/routes/production/` 目录逐接口核实。

## A. 功能定位

导演台画布（`views/production/`）是 Toonflow 生产流水线的**前端指挥中枢**，对应 README 中"分镜设计"与"视频配置"两个模块，本质是 **ProductionAgent 的图形化交互界面**：

- **核心理念**：以"类无限画布"形式组织剧本、角色、分镜、素材与视频节点，支持自由编排、回溯与并行生产，不受线性步骤限制
- **交互形态**：左侧无限画布（节点流）+ 右侧 AI 对话面板（ProductionAgent）
- **数据流**：用户在对话面板指挥 AI，AI 流式返回结构化内容，实时渲染到画布各节点；图片/视频生成通过异步任务 + 轮询回填

## B. 技术实现

### B.1 核心技术栈

| 技术 | 用途 |
|---|---|
| **Vue Flow**（`@vue-flow/core` / background / controls） | 无限画布渲染、节点/边/缩放/平移 |
| **Pinia**（`stores/productionAgent.ts`） | 画布数据状态 + ProductionAgent 会话 |
| **socket.io-client**（`utils/useChat.ts`） | 与后端 `socket/productionAgent` 建立 AI 对话长连接 |
| **tdesign-vue-next** | UI 组件（t-card/t-chat/t-image/t-button） |
| **md-editor-v3** | 剧本/计划/分镜表的 Markdown 预览与编辑 |
| **vue-clip-track** | 视频合成轨道编辑 |

### B.2 页面结构（`views/production/index.vue`）

`<VueFlow>` 包裹的无限画布，含：
- **6 类固定节点**：`script`（剧本）、`scriptPlan`（导演计划）、`storyboardTable`（分镜表）、`assets`（资产）、`storyboard`（分镜图）、`workbench`（工作台/视频合成）
- **节点连线（edges）**：script→assets、script→scriptPlan→storyboardTable→storyboard→workbench 的主链路
- **浮动工具栏**：顶部集数切换器、刷新、自动布局；右侧对话面板开关
- **Background + Controls**：画布背景与缩放控制
- **新手引导**：t-guide 4 步引导（切换集数/刷新/布局/画布导航）

### B.3 关键交互能力

1. **无限画布操作**：节点拖拽、画布平移、缩放（max 10 / min 0.1）、空格+左键拖画布
2. **自动布局**：`layoutGraph()` 手动 LR 布局主链（script→...→workbench），assets 放 script 正下方，检测重叠并右移
3. **集数切换**：下拉选择剧本集数，切换时若 AI 正在生成会弹确认对话框（防丢失），切换后重新拉取 flowData 与历史
4. **性能优化**：拖拽/平移期间 `isInteracting` 状态，降低渲染复杂度（`contain: strict`、隐藏 hover 工具）；FPS 监控
5. **节点位置保持**：监听 `onNodeDragStop` 和 flowData 深监听，把节点真实位置同步回 `nodePositions`，防止数据刷新时位置回跳

## C. 数据模型（前端 FlowData）

`utils/flowBuilder.ts` 定义了画布的核心数据类型：

```typescript
interface FlowData {
  script: string;                    // 剧本（Markdown）
  scriptPlan: string;                // 导演计划（Markdown）
  storyboardTable: string;           // 分镜表（Markdown）
  assets: AssetItem[];               // 资产列表
  storyboard: Storyboard[];          // 分镜图列表
  workbench: { videoList: VideoList[] }; // 视频工作台
}

interface AssetItem {
  id: number;
  name: string;
  desc: string;
  prompt: string;
  src: string;                       // 图片 URL
  state: "未生成" | "生成中" | "已完成" | "生成失败";
  type: "role" | "tool" | "scene" | "clip";
  flowId?: number;
  derive: DeriveAsset[];             // 衍生资产
}

interface DeriveAsset {
  id: number;
  assetsId: number;
  name: string;
  prompt: string;
  desc: string;
  src: string;
  state: 同上;
  type: 同上;
}

interface Storyboard {
  id?: number;
  prompt: string;
  duration?: number;
  trackId?: number;
  associateAssetsIds?: number[];
  src: string | null;
  state: 同上;
  videoDesc: string;
  shouldGenerateImage: number;      // 是否需生成图片
}
```

**要点**：资产分为**顶层资产（AssetItem）**与**衍生资产（DeriveAsset）**两级，分镜通过 `associateAssetsIds` 关联资产图作为参考图。

## D. 六大节点详解

### D.1 Script（剧本节点）
- 只读 Markdown 预览（`MdPreview`），顶部"编辑"按钮打开 `MdEditor` 全屏编辑弹窗
- 源输出 Handle 连接 assets 与 scriptPlan
- 数据来自 ProductionAgent 流式返回的 `<script>` XML 标签

### D.2 ScriptPlan（导演计划节点）
- 导演对剧本的改编计划（Markdown），含目标/调整方案
- 支持全屏 Markdown 编辑；数据来自 `<scriptPlan>` 标签

### D.3 StoryboardTable（分镜表节点）
- 结构化分镜表（Markdown），展示镜头规划
- 支持全屏 Markdown 编辑；数据来自 `<storyboardTable>` 标签

### D.4 Assets（资产节点）
- 展示资产卡片网格，**顶层资产 → 衍生资产**两级结构
- 每张衍生资产卡可点击**触发该资产图片生成**；支持删除
- 占位态：未生成/生成中(loading)/生成失败(红字+错误原因)
- 图片支持预览、ImageTools（放大/下载等）
- 数据经后端 WS `addDeriveAsset` / `delDeriveAsset` 事件增量更新

### D.5 Storyboard（分镜图节点）— 画布最核心节点
- 以**帧网格（frameGrid）**展示分镜图，每帧有 `S01/S02...` 序号标签
- 每个分镜可勾选（Checkbox），支持**批量选择/全选/清空/批量删除**
- **帧间插入**：左右两侧 hover 出现 `+` 按钮，可在两张图之间新增分镜（编辑图片后插入）
- **图片编辑**：点击帧图打开 `editImage` 编辑组件，可编辑图片（基于原图 + 参考资产图）
- **编辑信息**：编辑分镜的 prompt / videoDesc
- **删除**：单个删除或批量删除
- **生成图片**：对选中分镜批量 `batchGenerateStoryboard`
- **预览**：`gridPreview` 生成网格拼图预览；`downLoadImage` 下载
- **缩放**：`gridScale` 控制帧网格缩放（0.1~3）
- 状态管理：未生成/生成中/已完成/生成失败（含 reason）

### D.6 Workbench（工作台节点）
- 画布上的**缩略卡**：封面图 + 播放按钮 + 渐变色占位
- 点击打开**全屏工作台对话框**，含三个子面板：
  1. **Quick Preview（快速预览）**：`preview.vue`
  2. **Video Generation（视频生成）**：`generate/index.vue`，配置视频生成、批量生成、导入视频
  3. **Video Editing（视频合成编辑）**：`editVideo/index.vue`，基于 `vue-clip-track` 的多轨道编辑（视频/图片/音频轨道），画布尺寸随项目 videoRatio（16:9=1920x1080 / 1:1=1080x1080 / 9:16=1080x1920）

## E. ProductionAgent 状态管理与数据流（stores/productionAgent.ts）

### E.1 会话管理
- 用 Pinia `defineStore(\`productionAgent-${projectId}\`)` + storeMap 缓存，**每个项目独立一个 store**
- 通过 `useChat` 连接 `socket/productionAgent`，鉴权携带 `{ isolationKey, projectId, scriptId }`
- 生命周期手动管理（`manageLifecycle: false`），支持重连

### E.2 XML 流式解析（核心机制）
`useChat` 配置了 4 个 XML 标签（`script` / `scriptPlan` / `storyboardTable` / `storyboardItem`），ProductionAgent 的输出被**结构化地包裹在 XML 标签**中：

```
onXmlTag(tag, value, attrs, status) {
  script → flowData.script
  scriptPlan → flowData.scriptPlan
  storyboardTable → flowData.storyboardTable
  (storyboardItem → 分镜数组，当前已注释)
  status=="complete" → throttled 保存 setFlowData()
}
```

**关键**：AI 流式返回过程中，各节点的内容**实时刷新**；标签完成时经节流（500ms）自动 `setFlowData` 持久化，实现边生成边保存。

### E.3 后端 WS 事件（服务端 → 前端）

| 事件 | 处理 |
|---|---|
| `connect` | 触发 getHistory 加载会话历史 |
| `getFlowData` | 把当前 flowData 序列化返回（**剥离 prompt/src/flowId 敏感字段**）给 Agent 作为上下文 |
| `addDeriveAsset` | 前端新增衍生资产到对应顶层资产 |
| `delDeriveAsset` | 前端删除衍生资产 |
| `generateDeriveAsset` | 触发批量资产生成 |
| `generateStoryboard` | 触发批量分镜生成 |
| `addStoryboard` | 前端新增分镜并调用后端 `batchAddStoryboardInfo` |

### E.4 图片生成与轮询（异步任务）

**资产生成**（`batchGenerateAssets`）：
1. 前端把命中资产置为"生成中"
2. `POST /production/assets/batchGenerateAssetsImage`
3. 返回后同步 state/src
4. **5 秒轮询** `POST /production/assets/pollingImage` 回填（有"生成中"资产才启动，无则停止）

**分镜生成**（`batchGenerateStoryboard`）：
1. `POST /production/storyboard/batchGenerateImage`（支持并发数配置、强制重生成）
2. **5 秒轮询** `POST /production/storyboard/pollingImage` 回填 state/src/reason

### E.5 持久化与历史
- **保存**：`POST /production/saveFlowData`（节流 500ms）
- **加载**：`POST /production/getFlowData`
- **历史**：`POST /agents/getMemory`（agentType=productionAgent），会话记忆按 `isolationKey` 隔离

## F. 右侧 AI 对话面板（components/rightChatBox/index.vue）

- **消息列表**：tdesign `t-chat-list`，欢迎语含"开始制作视频"建议按钮
- **输入区**（`t-chat-sender`）：发送/停止生成；AI 生成中或未连接时禁用
- **设置菜单**：重连、**清除消息记忆 / 清除摘要记忆 / 清除全部记忆**
- **思考等级**：`updateThinkConfig` 四级（关闭/轻/深/极限），经 WS 发送给后端控制推理深度
- **窗口可拖拽调宽**（resizeHandle）
- 连接状态红绿点指示

## H. 设计特点与亮点

1. **画布即流程**：用固定节点 + 连线直观呈现"剧本→计划→分镜表→分镜→视频"生产链路，所见即所得
2. **AI 流式结构化输出**：ProductionAgent 用 XML 标签包裹不同区块内容，前端按标签实时分区渲染到对应节点，实现"边说边画"
3. **双级资产体系**：顶层资产（角色/场景/道具）→ 衍生资产，分镜通过 associateAssetsIds 引用资产图保证一致性
4. **边生成边保存**：XML 标签完成即节流持久化，降低数据丢失风险
5. **异步图片生成 + 轮询回填**：图片生成不阻塞对话，5 秒轮询更新状态/URL
6. **强交互编辑**：分镜帧间插入、批量生成/删除、图片在线编辑、视频多轨合成一应俱全
7. **性能优先**：交互态降渲染复杂度、节点位置防回跳、FPS 监控、资源懒加载
8. **会话记忆**：按 isolationKey 隔离记忆，支持清除消息/摘要/全部三级清理

## I. 潜在问题与改进点

1. **`storyboardItem` XML 解析被注释**：`productionAgent.ts` 中 `storyboardItem` 分镜流式解析逻辑整段注释，仅靠 `addStoryboard` 事件 + 轮询回填，分镜无法像 script 那样实时流式出现
2. **Workbench 缩略卡与全屏弹窗数据割裂**：`node/workbench.vue` 的缩略卡只用本地 `WorkbenchData`（name/duration/cover/gradient 演示数据），与 `flowData.workbench.videoList` 未真正打通，视频列表仍走独立 `video.ts` store
3. **演示数据残留**：editVideo 大量 `mockTracks/mockMediaItems/mockAudioItems` 演示数据，尚未完全接真实数据
4. **`getFlowData` 剥离字段**：WS 回传给 Agent 的 flowData 会删除 prompt/src/flowId，Agent 拿不到图片地址，可能影响其判断（需依赖资产名引用）
5. **布局依赖 DOM 尺寸测量**：`layoutGraph` 需反复测量节点 dimensions 并做稳定校验（重试 30 次），复杂画布下布局可能偏慢
6. **节点固定不可增删**：6 类节点为固定 ID/固定连接，用户无法自定义新增节点类型，灵活性受限（poster 节点已注释禁用）
7. **多项目 store 缓存**：storeMap 按项目缓存且无销毁机制，长时间多项目切换可能内存累积
8. **AI 对话与画布生成并发**：AI 生成中切换集数需确认，但生成中的图片轮询与新集数数据可能交错，需关注竞态
9. **`saveFlowData` 分镜排序逻辑缺陷**：仅当 `data.storyboard` 存在且**全部有 id**（无新增）时才更新排序 index；若存在无 id 的新分镜，则整段排序更新被跳过，新增分镜的 index 不会被修正
10. **`getFlowData` 初始态不完整**：无 `o_agentWorkData` 记录时，返回的初始 FlowData 的 `storyboardTable` 为空、`workbench.videoList` 空、poster 被注释——首次进入画布时这些节点需靠 AI 生成后才可见
11. **`getFlowData` 性能**：对每个资产/分镜逐个 `await u.oss.getSmallImageUrl()`（串行 Promise.all 内仍并发但无上限），资产量大时加载慢；且 `assetsData` 用 `where in` 传空数组会查询异常
12. **`getStoryboardData` 标题搜索**：分镜表按 `title like` 搜索，但 `o_storyboard` 的分镜未必都有 title，搜索能力受限
13. **前端 workbench 视频轮询频率不一致**：`generate/index.vue` 用 **3 秒**轮询 `checkVideoStateList`，而资产生成分镜图用 **5 秒**轮询，两套轮询节奏并存，需注意状态同步

## J. 总结

导演台画布是 Toonflow 前端**体验最好的模块**，用「VueFlow 无限画布 + socket.io 流式 AI + XML 结构化分区渲染 + 异步图片轮询」组合，把复杂的短剧生产流程做成了一块可拖拽、可对话、可编辑、可预览合成的可视化工作台。其**「AI 输出按 XML 标签实时分区渲染到节点」**与**「画布数据流式持久化」**两大机制，对同类 AI 生产工具的前端设计极具参考价值。
