# 短剧平台设计方案优化建议书

> 依据《参考文档/toonflow》逐条对照《01 系统架构》《02 数据模型》《03 功能文档》后整理的优化建议。
> 目的：在落地前补齐设计缺口，避免返工。本文为**建议稿**，供审阅后决定是否修订各方案文档。

---

## 一、数据模型层面（优先级最高）

### 1.1 引入"集数（episodes）"维度
- **现状**：数据模型只有 `projects → narrative_units` 两级，无显式集数层级；跨集复用资产、按集编排受限。
- **参照**：Toonflow 所有业务表带 projectId，且 `o_agentWorkData` 有 `episodesId` 维度，支持按集数切换与独立工作区。
- **建议**：新增 `episodes` 集数表（project_id、集号、标题、状态、时长），`narrative_units` 挂 `episode_id`；`agent_memories`、`generation_tasks` 增加 `episode_id` 可选维度。

### 1.2 关联关系改为独立关联表
- **现状**：`storyboards.asset_refs`、`assets.files` 用 jsonb 存关联。
- **参照**：Toonflow 用 `o_scriptAssets`（剧本-资产）、`o_assets2Storyboard`（资产-分镜）、`o_assetsRole2Audio`（角色-音频）独立表，支持多对多、查询与幂等。
- **建议**：新增 `unit_assets`（单元-资产）、`storyboard_assets`（分镜-资产）、`character_voices`（角色-声音）关联表；jsonb 仅作冗余缓存。

### 1.3 补充视频轨道数据模型
- **现状**：多轨合成仅文字描述"多轨时间线"，无对应表。
- **参照**：Toonflow `o_videoTrack`/`o_video`（轨道 + 选中的视频）。
- **建议**：新增 `video_tracks`（project/episode_id、轨道类型 video/image/audio、时长、状态）与 `videos`（track_id、file_path、time、state、error）。

### 1.4 图片编辑工作流持久化
- **现状**：`generated_images` 承载资产图/分镜图，但无编辑工作流模型，且缺 `model`/`resolution` 字段。
- **参照**：Toonflow `o_image` 含 model/resolution，`o_imageFlow` 存编辑流程 JSON。
- **建议**：`generated_images` 增加 `model`、`resolution`、`edit_flow`（可选 jsonb）；新增 `image_flows` 表持久化图片编辑工作流。

### 1.5 画风库补充 prompt 字段
- **现状**：`style_library` 只有 name/preview/params。
- **参照**：Toonflow `o_artStyle` 含 `prompt`（画风提示词）。
- **建议**：`style_library` 增加 `prompt` 字段；`projects.settings` 显式引用 `style_id` 而非仅存文案。

### 1.6 记忆模型补齐隔离与摘要维度
- **现状**：`agent_memories` 有 space/project_id、scope_type，但缺隔离键与摘要关联。
- **参照**：Toonflow `memories` 含 `isolationKey`（projectId:agentName）、`relatedMessageIds`、`summarized`。
- **建议**：`agent_memories` 增加 `isolation_key`、`related_message_ids`、`summarized`、`role`/`name` 字段。

### 1.7 技能文件化管理
- **现状**：`agent_skills`/`directive_skills` 是纯表结构。
- **参照**：Toonflow 技能为 markdown 文件（path/md5/frontmatter name+description/embedding）。
- **建议**：为技能表增加 `file_path`、`md5`、`description`（frontmatter）、`embedding` 字段，支撑"技能文件化 + 版本 + RAG 检索"。

## 二、业务流程层面

### 2.1 补全"小说导入 → 事件提取"前置链路
- **现状**：流程从"剧本拆分→叙事单元"开始，缺小说来源。
- **参照**：Toonflow 完整链路 `小说 → 事件提取 → 剧本 → 资产 → 分镜 → 图片 → 视频`，含 `o_novel`/`o_event`/`o_eventChapter`。
- **建议**：数据模型新增 `novels`（章节导入）、`events`（事件）、`event_chapters`（事件-章节关联）；流程文档补充"导入小说 → 事件提取 → 生成剧本"环节。

### 2.2 显式串联"剧本资产生成（extractAssets）"
- **现状**："资产提取"接口存在但流程未显式串联。
- **参照**：Toonflow `/script/extractAssets` 从剧本自动识别角色/道具/场景写入资产，`pollScriptAssets` 轮询。
- **建议**：在创作流水线中明确"剧本 → 资产提取 → 资产生成"两步，并配套轮询接口。

### 2.3 引入"Agent 工作区数据"枢纽
- **现状**：自由画布/操作台无中间产物持久化模型。
- **参照**：Toonflow `o_agentWorkData`（project_id + episodes_id + key）承载 scriptAgent/productionAgent 中间产物。
- **建议**：新增 `agent_work_data` 表（project_id、episode_id、agent_key、data jsonb），作为画布/操作台的持久化枢纽。

## 三、接口层面

### 3.1 补齐小说/事件接口
- `POST /api/v1/novels`（导入章节）、`GET /api/v1/novels`、`GET /api/v1/novels/{id}`
- `POST /api/v1/novels/{id}/events/generate`（事件提取）、`GET /api/v1/novels/{id}/events`、`GET /api/v1/novels/{id}/event-state`（轮询）

### 3.2 补齐技能文件管理接口
- `GET /api/v1/agent-skills/files`、`GET .../{path}`、`PUT .../{path}`（对应 Toonflow `getSkillList/saveSkillContent`）

### 3.3 画风库接口维护 prompt
- 管理端 `style-library` 增删改时支持 `prompt` 字段。

---

## 四、健壮性 / 安全

### 4.1 为 jsonb 字段补充 Schema 约束
- **现状**：`data`/`content`/`result`/`params` 等大量 jsonb 字段无结构约束。
- **建议**：引入 JSON Schema 校验（如 PostgreSQL jsonb 约束或 Go 侧 zod 校验），记录字段结构约定于数据模型文档。

### 4.2 技能文件路径穿越防护
- **现状**：技能/文件读取未明确安全说明。
- **建议**：明确对技能文件读取做路径归一化与越界防护（参照 Toonflow `isPathInside`），防止路径穿越。
