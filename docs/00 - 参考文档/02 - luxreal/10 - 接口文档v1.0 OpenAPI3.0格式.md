## A. 全局约定（后端按这个写，不用再讨论）

### A1. 通用规范

| 项 | 约定 |
|----|------|
| **Base URL** | `https://api.example.com/v1`（开发环境 `http://localhost:8000/v1`） |
| **请求方法** | 查=GET；新建=POST；全量改=PUT；部分改=PATCH；删=DELETE |
| **Content-Type** | 一律 `application/json; charset=utf-8`（文件上传除外是 `multipart/form-data`） |
| **字符编码** | 全链路 UTF-8，接口里禁止出现 GBK/ISO-8859-1 |
| **时间格式** | 所有时间戳一律 **ISO 8601 带时区**：`2026-08-09T14:30:00+08:00`，后端存 TIMESTAMPTZ；**不用 Unix 时间戳，不用 YYYY-MM-DD HH:mm:ss 无时区** |
| **主键 ID** | 对外统一暴露 **UUID**（或 `task_uuid` / `txn_uuid`），**禁止直接暴露 BIGSERIAL 自增 id** 防遍历；内部外键仍用 BIGINT |
| **分页** | 列表接口一律 `?page=1&page_size=20`；响应体带 `pagination:{page,page_size,total,total_pages}` |
| **排序** | 列表接口一律 `?sort_by=created_at&order=desc`；多排序 `?sort_by=status,updated_at&order=asc,desc` |
| **软删除查询** | 列表默认不返回 deleted_at 非空数据；要查历史加 `?include_deleted=true` |
| **幂等** | 所有写接口（POST/PUT/PATCH/DELETE）请求头支持 `Idempotency-Key: <uuid>`，同 key 60s 内重复请求直接返回首次响应 |
| **限流** | 登录用户 60 次/分钟；未登录 20 次/分钟；VIP 按等级提权到 120~300；返回头 `X-RateLimit-Remaining` / `Retry-After` |

### A2. 统一响应体包装（ApiResponse<T>）

**无论成功失败，所有 HTTP 2xx/4xx/5xx 一律套这个结构**，前端只用解析一次：

```ts
type ApiResponse<T> = {
  code: number          // 业务错误码，0=成功，非0=见M节错误码字典
  message: string       // 人类可读信息，成功="ok"，失败="用户友好提示"
  data: T | null        // 响应载荷，失败=null
  request_id: string    // 每次请求唯一UUID（后端注入，出问题用户甩过来能查整条链路）
  timestamp: string     // ISO8601 响应生成时间
}

type PaginationWrapper<T> = {
  items: T[]
  pagination: { page:number; page_size:number; total:number; total_pages:number }
}

// 例：成功
{ code:0, message:"ok", data:{project_id:123}, request_id:"req-a1b2c3...", timestamp:"2026-08-09T14:30:00+08:00" }

// 例：失败
{ code:4001, message:"剧本内容不能为空（≤0字）", data:null, request_id:"req-x9y8z7...", timestamp:"..." }
```

> **后端注意**：Nginx/FastAPI 全局拦截器统一包装，不要在每个 Controller 里手写 `{code:0,...}`。错误码用 Enum 定义集中管理。

### A3. 鉴权方式（Bearer JWT）

```http
Authorization: Bearer <access_token_jwt>
```

- **Access Token**：JWT，有效期 2 小时，`sub` 字段 = user_id
- **Refresh Token**：HttpOnly Cookie，`refresh_token=xxx; Secure; SameSite=Lax; Path=/api/v1/auth; Max-Age=604800`（7天）
- **登录流程**：POST /auth/login → 返回 access_token + 种 Cookie refresh_token
- **401 后自动刷新**：前端拿到 `code=1002` → 后台 `POST /auth/refresh`（Cookie自动带）→ 拿新 access_token 重放原请求 → refresh 也 401 才踢登录页
- **登出**：前端删 access_token + `POST /auth/logout` 后端把 refresh_token 加 Redis 黑名单（直到过期）

## F. WebSocket 实时推送协议（独立于 REST · M0 P0 必做）

> **为什么必须做**：AI 生成任务是 30s ~ 10min 长任务，纯轮询体验差、服务器压力大。**所有创建任务 POST 返回 202 的接口都必须发 WS 事件**。轮询是降级兜底。

### F1. 连接方式（浏览器端）

```typescript
// 前端示例
const ws = new WebSocket(`wss://api.example.com/ws/v1/events?jwt=${access_token}&room_id=${batch_or_project_room_id}`)
// 或者 Header：Authorization: Bearer xxx（看 WS 库支持度，优先URL参数简单可靠）
// 心跳：客户端每 25s 发 {"type":"PING"}；服务端 10s 内回 {"type":"PONG"}；2次不回断了重连
```

### F2. 客户端 → 服务端消息（上行 JSON · 3种）

```typescript
// 1. 订阅指定任务进度（连接后立刻发）
{
  "type": "SUBSCRIBE",
  "task_uuids": ["t-111...", "t-222..."],  // 最多100个
  "room_ids": ["batch-xxx", "project-yyy"]  // 批量任务/项目级广播（M0只要task_uuids就行）
}

// 2. 取消订阅
{ "type": "UNSUBSCRIBE", "task_uuids": ["t-111..."] }

// 3. 心跳
{ "type": "PING", "client_ts_ms": 1760000000000 }
```

### F3. 服务端 → 客户端消息（下行 JSON · 9 种）


### F4. 断线重连策略（前端实现）

1. WebSocket `onclose` → 立即重连 1 次 → 失败等 3s → 3s → 7s → 15s（指数退避，最多 10 次后提示用户手动刷新）
2. 重连成功后：重新 SUBSCRIBE 当前页面对应的所有 task_uuids + 补发一次 PING
3. 重连期间：进度条显示「连接中断，正在重连…」+ 降级为 HTTP 轮询 GET /tasks/{uuid} 3s 一次
4. 切后台标签页：清除 WS 定时器别重连；切回前台如果 readyState!=OPEN → 立刻重连

## G. 全局错误码字典（Code 4 位数 + 分类前缀 · 后端 Enum 集中定义）

> **铁律**：`code=0` 永远=成功。非 0 一律错误。message 必须是**用户看得懂的人话**，不能是堆栈/英文。内部 debug 信息打 Sentry，不给前端。
