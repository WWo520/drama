## A. 前端技术栈 & 架构原则（M0 别乱改栈）

### A1. 技术栈（和 08 号完全一致，不讨论换）

| 层 | 选型 | 为什么不能换 |
|----|------|------------|
| **框架** | Next.js 14 App Router（Page Router 禁止用） | RSC 减少 JS 体积；Server Actions M0 不用但架构兼容；静态路由预渲染首屏快 |
| **语言** | TypeScript 5.5+（strict=true + noImplicitAny=强制） | 接口类型对接 10 号文档生成 TypeScript type，any 就失去意义 |
| **UI 组件** | shadcn/ui + Tailwind CSS 3 + lucide-react 图标 | 组件风格统一，避免一个按钮三种写法；图标统一 lucide 不许混搭 |
| **路由** | Next.js App Router 自带 + 路由段约定（M0 不用 next-intl，i18n M2 再加） | |
| **客户端状态** | Zustand 4.5（persist 中间件 + devtools） | 比 Redux Toolkit 轻 5 倍代码量；AI 产品状态读写频繁响应要快；**M0 禁止引入 Redux/MobX/Jotai** |
| **服务端缓存/远程数据** | SWR 2.2（NOT React Query / TanStack Query） | 钩子式 API 简洁；和 Zustand 配合好；自动重连+去重+重试够用；**M0不许换成TanStack Query**（团队要先学会用约定再谈别的） |
| **HTTP 客户端** | Axios 1.7 + 全局拦截器（统一 ApiResponse 解包 + code!=0 自动 Toast） | 不用 fetch，错误处理/拦截/超时比 fetch 现成 |
| **表单** | react-hook-form 7 + zod 3（zod schema 共享给前后端） | 登录/注册/创建项目等表单统一 |
| **弹窗/抽屉/侧边栏** | shadcn Dialog/Drawer + `useDialogState()`（不要裸用 useState 控制每个弹窗） | 避免每个页面 15 个 `isXxxOpen` |
| **自由画布（M1才上）** | ReactFlow 11 + zustand 再配一个单独的 `useCanvasStore` | 画布状态太重，和全局隔离，不要污染其他 store |

### A2. 状态分层原则（最容易做错 → 提前卡死）

> **黄金公式**：`能放 URL Search Params 的不放 Zustand；能放 SWR Key 的不放 Zustand；剩下（操作频繁 UI 态/跨组件共享）才放 Zustand。`

| 分层 | 存储位置 | 典型内容 | 示例 |
|------|---------|---------|------|
| **L1 持久 URL**（最推荐） | `?xxx=yyy` Search Params | 分页(page/page_size)、排序(sort/order)、筛选(status/keyword)、当前Step、当前集、当前选中的资产id/镜头id、弹窗是否打开（分享链接可复用） | `/workspace?projectId=p-xxx&episodeId=e-xxx&step=2&selected_asset_ids=cv-aaa,cv-bbb` |
| **L2 SWR 远程缓存**（次推荐） | SWR `key="api/v1/projects?page=1"` | 所有 GET 请求返回值（项目列表/资产详情/任务状态）→ SWR 统一管 3s dedupe + 缓存 + 重验证 | `useSWR('/api/v1/projects', fetcher)` |
| **L3 页面内本地 state**（第三推荐） | React `useState`（组件内） | 临时 UI：输入框值、是否 hover、单个卡片展开/折叠、input focus | `const [scriptText, setScriptText] = useState('')` |
| **L4 Zustand 全局**（**最后选择**！别什么都塞） | Zustand store + persist (localStorage 仅存必要) | ①用户登录态（access_token + user info）②当前工作台四步共享：项目/集id、资产勾选集合③WebSocket连接状态④当前积分余额⑤跨页面临时操作态（批量任务已选id跳转Step3还能看到） | `useAuthStore(s => s.accessToken)` → 存 localStorage |

> **铁律**：Zustand store 里的 state 字段数 **M0 单个 store ≤ 10，全部 store 加起来 ≤ 50**。超过了就要自查"这个能不能放回 URL/SWR"。

### C1. Step 放在 URL 里的原因（不用 Zustand 管 current_step）

```
✅ 好的做法（URL是真源）：
/workspace/project/p-123?episodeId=e-456&step=2
→ 分享链接给朋友点进来：直接进 Step2 看资产（要登录+权限）
→ 浏览器后退：回到 Step1
→ 刷新页面：step 不变

❌ 之前做错的做法：
Zustand里存 currentStep = 2
→ 刷新 = 重置 Step1
→ 分享链接 = 朋友从 Step1 开始
→ 后退 = 退到 /projects（不是Step1）
```

> **扩展原则**：所有「希望分享链接能复现」的东西，一律塞 Search Params。Step、选中资产ID、镜头ID、打开的弹窗、筛选排序——全放 URL。参数多没关系，Next.js Router 性能没问题。

### C2. SearchParams 命名约定（全项目统一，避免混用）

| 约定键名 | 类型 | 示例 | 用途 |
|---------|------|------|------|
| `step` | enum 1\|2\|3\|4 | `?step=2` | 当前工作台 Step |
| `projectId` | uuid | `?projectId=p-uuid4` | 兜底（路径里也有，但参数里写一份方便组件直接取） |
| `episodeId` | uuid | `?episodeId=e-uuid4` | 当前集（M0单集也要写死，M1多集有用） |
| `beatId` | uuid | `?beatId=b-uuid4` | 当前高亮叙事单元 |
| `shotGroupId` | uuid | `?shotGroupId=sg-uuid4` | 当前展开镜头块 |
| `shotId` | uuid | `?shotId=s-uuid4` | 当前展开镜头详情 |
| `selected_asset_ids` | `逗号分隔uuid列表` | `?selected_asset_ids=cv-aaa,cv-bbb,sc-ccc` | Step2已勾选的资产id列表（用户勾选后，切页回来还在） |
| `modal` | string enum | `?modal=batch_assets_preview` / `?modal=alipay_qr&order_no=xxx` | 当前打开的弹窗名（分享/回退时可恢复） |
| `page` / `page_size` / `keyword` / `status` | — | 同 10 号接口 | 列表页用 |
| `redirect` | encodeURIComponent | `/login?redirect=%2Fworkspace%2Fproject%2Fp-xxx` | 登录成功后跳回原页 |

## D. 路由守卫（Next.js middleware.ts + 前端双重保障·防止越权）

### D1. Next.js Middleware（服务端第一道防线 · 必须写）

```ts
// middleware.ts 根目录，匹配所有请求
// 规则（按09号M0裁剪）：
// 1. 未登录访问 (protected)/* → 307 到 /login?redirect=xxx
// 2. 已登录访问 /login / /register → 307 到 /projects
// 3. 访问 /canvas* → 404（M0不开放）；防止有人试路径
// 4. 防遍历：URL里是连续数字的疑似自增id路径 → 400（因为我们全是UUID）
// 5. 安全头：X-Content-Type-Options=nosniff / Referrer-Policy=strict-origin-when-cross-origin
```

### D2. 前端组件内路由守卫（客户端第二道 · 细粒度）

> 服务端 Middleware 只能判断有没有登录；判断"是不是项目 owner"要读数据库，所以在 Workspace 组件里做。

```tsx
// app/workspace/project/[project_id]/page.tsx
export default function WorkspaceProjectPage({ params: { project_id }, searchParams }) {
  const { data: project, error, isLoading } = useProjectDetail(project_id)
  const user = useAuthStore(s => s.user)

  // D2.1 越权拦截：不是 owner（M0无团队，owner_type必须=USER && owner_id = user.id）
  if (project && project.owner_user_id !== user?.user_id) {
    toast.error('项目不存在或无权限访问（code=2001）')
    router.replace('/projects')
    return null
  }

  // D2.2 进度顺序校验：未通过 Step1 不能直接 URL 改 step=3 跳
  const step = Number(searchParams.step ?? 1)
  if (step >= 2 && project?.episode?.current_step_num < step - 1) {
    toast.warning('请先完成 Step1 剧本拆分后再进入下一步')
    router.replace({ pathname: router.pathname, query: { ...searchParams, step: project.episode?.current_step_num ?? 1 } })
    return null
  }

  // D2.3 正常渲染：根据 step 渲染对应组件
  const StepComp = { 1: Step1ScriptSplit, 2: Step2Assets, 3: Step3VideoProduction, 4: Step4FinalPreview }[step]
  return (
    <AppShellBreadcrumb project={project} step={step}>
      <Suspense fallback={<WorkspaceSkeleton step={step} />}>
        <StepComp project={project} episodeId={searchParams.episodeId} />
      </Suspense>
    </AppShellBreadcrumb>
  )
}
```

## E. Zustand Store 划分（6 个 Store · 单一职责 · 避免单个 Store 2000行）

> **目录约定**：`src/store/*.ts`，每个文件一个 store，导出命名 `useXxxStore`。**不要搞 barrel `index.ts` export * 导致循环依赖**，直接 `import useAuthStore from '@/store/auth'`。

### Store 架构图

```
src/store/
├── auth.ts                      【🔴 L4持久化】登录态：用户信息+tokens+权限判断
├── workspace.ts                 【🔴 L4不持久化，刷新从URL取】当前工作台态：step/已勾选资产ID集合/临时编辑值
```

### E1. useAuthStore（src/store/auth.ts · 唯一 persist localStorage）

```ts
/**
 * 🔐 鉴权 Store（M0 最基础 Store，所有页先依赖它）
 * persist localStorage：access_token, user 信息（不要存 refresh_token，它是 HttpOnly Cookie）
 * 清除条件：401 code=1003 或 /auth/logout 成功 或 页面F12清缓存
 */
import { create } from 'zustand'
import { persist, devtools } from 'zustand/middleware'
import type { UserMeDTO, ResAuthLogin } from '@/types/generated-api' // 从10号OpenAPI生成的TypeScript类型

type AuthState = {
  // === State ===
  accessToken: string | null
  user: UserMeDTO | null
  isInitialized: boolean  // 页面刚打开时是否已尝试过 silentRefresh
  loginLoading: boolean
  registerLoading: boolean

  // === Actions ===
  // 登录后用后端返回值一次性填store
  onLoginSuccess: (res: ResAuthLogin['data']) => void
  // /auth/refresh 成功后只更新 accessToken
  setAccessToken: (token: string) => void
  // 用 GET /auth/me 的结果更新 user（例如充值后余额变化重新拉一次也调这个）
  setUser: (user: UserMeDTO) => void
  // 退出登录：清 store + 清 localStorage + 调 router.push('/login')
  logout: () => void
  // 初始化：页面刚打开如果有 accessToken 先验证有效性（GET /auth/me，失败 = 踢登录）
  initialize: () => Promise<void>
}

export const useAuthStore = create<AuthState>()(
  devtools(
    persist(
      (set, get) => ({
        accessToken: null,
        user: null,
        isInitialized: false,
        loginLoading: false,
        registerLoading: false,
        onLoginSuccess: ({ access_token, user }) =>
          set({ accessToken: access_token, user }),
        setAccessToken: (token) => set({ accessToken: token }),
        setUser: (user) => set({ user }),
        logout: () => {
          // 清除所有persist数据，不需要手动清localStorage
          set({ accessToken: null, user: null })
          window.location.href = '/login' // hard reload让所有store重置，避免跨store脏数据残留
        },
        initialize: async () => {
          const token = get().accessToken
          if (!token) { set({ isInitialized: true }); return }
          try {
            const me = await api.get('/auth/me') // BFF /api/v1/auth/me
            set({ user: me.data, isInitialized: true })
          } catch (e) {
            get().logout() // token无效直接踢
          }
        },
      }),
      {
        name: 'duanju-auth-store-v1', // localStorage key，每次不兼容结构改v2
        partialize: (s) => ({ accessToken: s.accessToken, user: s.user }), // 只持久化这两个，loading等不存
      }
    )
  )
)
```

### F2. SWR Fetcher 全局实现（1 份，所有 key 共用）

```ts
// src/lib/swr-fetcher.ts
import axios from '@/lib/axios' // 带拦截器的Axios实例：统一ApiResponse解包 + code!=0抛错 + 401自动refresh重放

/**
 * SWR fetcher。Key = "GET:/path" or "POST:/path||{body}"
 * 解包 10 号文档约定的 ApiResponse：{code,message,data,request_id}
 * code != 0 → throw Error(message + '::' + code)，SWR 会走 isError
 */
export async function fetcher<T = unknown>(key: string): Promise<T> {
  const [methodPath, bodyStr] = key.split('||')
  const [method, path] = methodPath.split(':') as ['GET'|'POST'|'PUT'|'PATCH'|'DELETE', string]
  const { data } = await axios.request<ApiResponse<T>>({
    method, url: path,
    data: bodyStr ? JSON.parse(bodyStr) : undefined,
  })
  if (data.code !== 0) {
    const err = new Error(data.message || '未知错误')
    ;(err as any).bizCode = data.code
    throw err
  }
  return data.data as T
}
```

### F3. 失效（Revalidate/Mutate）策略

> **核心触发点**：所有写操作（POST/PATCH/DELETE）成功后，哪些 SWR key 需要 mutate？
>
> 规则：**改了什么数据，就 mutate 对应的父级列表和自己的详情**。不用改祖先级太高层，改到刚好能刷新用户看到的列表+卡片即可。

| 写操作（POST接口） | 成功后要 mutate 的 SWR key（立刻让页面显示新数据，省得用户手动刷新） |
|-----------------|-------------------------------------------------------------|
| POST `/projects` 创建项目 | ✅ `KEY.projects_list('page=1')`（列表要加新的）✅ `KEY.auth_me`（user stat 可能变） |
| DELETE `/projects/p-xxx` | ✅ `KEY.projects_list(...)` |
| PATCH `/characters/c-xxx` 修改角色 | ✅ `KEY.assets_chars(eid)`（角色列表）✅ 如果改了绑定还可能要 shots，但 M0 暂不用 |
| POST `/assets/batch-generate` 批量生成资产 | ❌ **不用 mutate**！任务是异步的，等 WS 推子任务 SUCCESS 时**每个子任务完成**再 mutate 该资产卡片 key（不要等全批量完才刷新，体验差） |
| POST `/shots/s-xxx/generate-video` 生成视频 | ✅ WS TASK_COMPLETED 到达时 `mutate(KEY.shots_detail(s-xxx))` + `mutate(KEY.episodes_step3_summary(eid))` |
| POST `/payments/create-order` 支付 → 支付宝回调成功 | ✅ WS POINTS_BALANCE_CHANGED 到达时 `mutate(KEY.auth_me)` + `mutate(KEY.points_account)` + `mutate(KEY.points_txn('page=1'))` |

### F4. 乐观更新（Optimistic UI · 批量勾选积分扣减时提升感知）

> 适用场景：点击批量生成后，后端返回 202，但积分要等一段时间才扣。为了避免用户看到"点完按钮余额没变还显示500"疑惑，**乐观先扣 frozen_balance UI 显示**：

```ts
// 提交批量生成时
const { trigger } = useSWRMutation(KEY.assets_batch_generate, remoteBatchGen)
async function handleBatchGenClick() {
  const preview = await previewCost()
  // 乐观更新：points_account current_balance 先减，frozen 先加
  mutate(KEY.points_account, (prev: PointsAccount) => ({
    ...prev,
    current_balance: prev.current_balance - preview.net_to_freeze,
    frozen_balance: prev.frozen_balance + preview.net_to_freeze,
  }), false) // false=不要立刻走HTTP重验证，等WS结果覆盖
  
  try {
    const res = await trigger(payload)
  } catch (e) {
    // 失败回滚乐观更新（没扣成功加回去）
    mutate(KEY.points_account) // 强制重拉真实数据（简单粗暴）
  }
}
```

## H. 性能优化策略（M0 不要过早上，但是骨架要预留）

## I. 与 10 号接口文档的对接流程（自动化减少手动 copy）

> **目标**：10 号文档里写的 Request/Response TypeScript 类型不用手动写 2 遍，自动生成。

### I1. OpenAPI TypeScript 代码生成

```bash

    "gen:api": "openapi-typescript https://url-to-our-swagger-json -o src/types/generated-api.d.ts --immutable-types --additional-properties=false"
```

> 实际流程：
> 1. 后端 FastAPI 启动后自带 `/openapi.json`（FastAPI 自动生成，零成本）

### I2. 全局 Axios 拦截器（两处关键逻辑·前端只写一次）

```ts
// src/lib/axios.ts
// 请求拦截：带上 useAuthStore access_token
axiosInstance.interceptors.request.use(config => {
  const token = useAuthStore.getState().accessToken // ✅ 正确！getState()不用进React渲染循环
  if (token) config.headers.Authorization = `Bearer ${token}`
  config.headers['X-Request-Id'] = `req-${uuidv4()}`  // 后端全局ApiResponse.request_id对应，出问题给用户复制粘贴
  return config
})

// 响应拦截：解包ApiResponse + code!=0抛错 + 401自动 refresh 并重放原请求（≤1次，防止死循环）
axiosInstance.interceptors.response.use(
  (r) => {
    // code = 0 正常返回
    if (r.data?.code === 0) return r
    // 业务错误 code≠0 → toast 提示 + 抛错给 SWR
    toast.error(r.data?.message || '操作失败')
    return Promise.reject(new BizError(r.data?.code, r.data?.message, r.data?.request_id))
  },
  async (err) => {
    if (err.response?.status === 401 && err.config && !(err.config as any).__retry) {
      try {
        // code 1002 → refresh access_token
        const newToken = await refreshTokenSilently()
        // 重放原请求
        ;(err.config as any).__retry = true
        err.config.headers.Authorization = `Bearer ${newToken}`
        return axiosInstance(err.config)
      } catch {
        // refresh 也 401 = code 1003 → 踢登录
        useAuthStore.getState().logout()
      }
    }
    return Promise.reject(err)
  }
)
```
