# 短剧平台数据模型

> 基于《短剧平台初步方案》与《系统架构》设计
> 数据库：PostgreSQL ｜ 缓存/队列：Redis ｜ 文件：S3 兼容存储

---

## 一、ER 概览（核心关系）

```
user ──1:1──> space(默认个人空间)   user ──N:M──> space (成员)
space ──1:N──> member(成员/角色)     space ──1:N──> 创作资源(项目/资产/任务等)
user ──1:N──> project               project ──1:N──> narrative_unit(叙事单元)
narrative_unit ──1:N──> storyboard(分镜) ──1:N──> generation_task(生成任务)
user ──1:N──> asset(角色/场景/道具/镜头/素材)  space ──1:N──> asset
user ──1:N──> project/作品 ──1:N──> 发布审核流(publish_record)
user ──1:N──> 订单/积分流水    user ──1:N──> task_order(任务与接单)
```

---

## 四、Redis 数据用途

| 用途 | Key 示例 | 说明 |
|------|----------|------|
| 任务队列 | `queue:gen` | 生成任务待消费队列（ZSet，score=优先级+时间戳，支持按优先级弹出） |
| 任务进行中集合 | `running:tasks` | 并发控制（Set/ZSet） |
| 用户会话 | `session:{token}` | 会话态（如需要） |
| 热点缓存 | `cache:work:{id}` / `cache:space:{id}` | 读多写少数据 |
| 限流计数 | `rate:{user}:{api}` | 接口限流 |
| 分布式锁 | `lock:task:{id}` | 任务幂等/防并发 |

## 五、数据一致性要点

- **积分扣减**：事务内校验积分 ≥ 扣减额，写 `point_transactions`，防超扣。
- **订阅/积分包发放**：套餐订阅成功或积分包支付成功后，事务内发放积分并写流水，防重复发放（幂等键）。
- **任务幂等**：提交带幂等键，重复提交不重复计费。
- **队列与状态**：任务写入队列前落库（status=queued），调度器消费时加锁，防止重复执行。
- **文件生命周期**：S3 对象与业务记录关联，任务结束后按策略清理中间文件。
