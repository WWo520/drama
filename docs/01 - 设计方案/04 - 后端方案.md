### 数据真源铁律
① 枚举（project_status/task_status/payment_status ...）→ 唯一真源 = 02 数据模型 B 章 Postgres CREATE TYPE → 代码中必须使用 `go:generate go-enum` 从 CREATE TYPE SQL 自动生成 Go const，**绝不允许手写 iota 常量**
② 表字段约束（not null/default/unique 部分索引 where deleted_at is null）→ 真源=02 数据模型 → GORM/PGX 模型 tag 必须严格对齐，unique 索引必须在 DB 层建不依赖应用层查了再插防并发
③ 扣费一致性（frozen→spent→unfreeze）→ 真源=02 数据模型 generation_tasks 三字段 + point_transactions 流水 → 实现伪代码见本方案 H 章，事务内 SELECT FOR UPDATE 防超扣/死锁
④ 设计阶段不指定迁移工具：请见「第二章说明」

## 二、设计阶段说明 · 数据库迁移工具不提前固化
> ⚠️ **本方案（设计阶段）不指定任何数据库迁移工具，也不写任何具体 up/down SQL 文件名或命令。**
>
> 原方案工程结构 `migrations/` 目录保留作为目录占位，但以下内容**不固化在设计文档**，开发启动第一天由后端团队按熟悉程度任选并落地：
>
> - 迁移工具选型在以下 4 个中选：`golang-migrate / goose / sqlc / Atlas`
> - 迁移编号格式（时间戳 vs 6 位数字）、up/down 命名规范、go generate 触发方式等
> - 启动流程是否自动执行迁移（或运维手动+CI/CD pipeline 执行）
>
> 设计阶段仅提供「**建表依赖顺序**」参考（见 02 数据模型 E 章），保证按外键依赖顺序建表不报错即可。
>
> ⚠️ 同样，02 数据模型中所有「CREATE TYPE」「CREATE TABLE」「CREATE INDEX」SQL 示例是 **Schema 结构说明**，不是可直接运行的迁移脚本，开发写迁移时需要根据所选迁移工具格式自行转换（但字段/类型/约束必须100%对齐，不得修改）。

## A. 技术栈与依赖表（每个库选型理由+版本+与 luxreal Python 版对照）

### A.1 核心依赖库总览

| 领域 | Go 选型（版本） | 选型理由 | LuxReal Python 版对照 | 差异说明 |

| **数据库驱动** | pgx/v5 v5.6.0 | 纯 Go 实现 PostgreSQL 驱动，性能比 lib/pq 高 30%+，支持批量 Copy、Pipeline、Listen/Notify，pgxpool 原生连接池 | SQLAlchemy 2.0 + psycopg3 | pgx 是底层驱动，ORM 层不用 GORM，手写 Repository + SQL（M0 16 张表数量可控，手写 SQL 性能更优、可加 08 号推荐索引） |

| **鉴权 JWT** | golang-jwt/v5 v5.2.1 | 2024 年官方推荐新版（旧 dgrijalva/jwt-go 停更），支持 HS256/RS256，jwt.RegisteredClaims 标准结构 | PyJWT | JWT 双 Token 方案不变：Access 2h Bearer + Refresh 7d HttpOnly Cookie。Token 黑名单走 Redis SET EX |

### B.2 分层原则（铁律：禁止跨层反向调用）

```

  ┌────────────────────────────────────────────────────────────────────────────┐
  │  Domain.*.Service     业务逻辑层（所有权限校验第一行必调）                  │
  │  ├─> space.CheckSpacePermission(spaceID, userID, action)                   │

  │  ├─> engine/task 提交任务入队                                               │

  ┌──────────────────────┐     ┌────────────────────────────────┐

  │  ├─> pgx CRUD SQL     │     │  ├─> task    任务调度            │
  │  ├─> Redis 缓存读写    │     │  ├─> model   模型接入治理        │

  └──────────────────────┘     │  ├─> billing 积分计费底层       │

                                └────────────────────────────────┘
```

> **分层铁律**：
> 1. Handler 层绝不写 SQL，只调用 Domain.Service；绝不出现 pgxpool
> 2. Domain.Service 写业务组合，不写具体 SQL，CRUD 走 Repository；调用 Engine 层公共能力
> 3. Engine 是公共库，被多个 Domain 调用；Engine 绝不反向依赖 Domain，只依赖 Repository/pkg
> 4. Repository 只做单表/联表 SQL，不含业务判断（业务判断放 Domain）
> 5. 所有跨资源操作（扣积分+写任务+写流水）必须走 DB 事务，严禁拆分多个接口

### C.1 JWT 双 Token 方案设计

| Token 类型 | 存储方式 | 有效期 | 内容 Claims | 刷新策略 |
|-----------|---------|-------|------------|---------|
| Access Token | 前端内存（localStorage 或 Redux） | 2 小时（7200s） | `sub`=user_uuid, `space_id`=当前空间, `platform_role`=user/admin, `vip_level`=0~4, `exp`=绝对时间戳 | 返回 1002 时前端自动 POST /auth/refresh 换新 |

### C.3 CheckSpacePermission 函数签名（Go 代码示例）

```go
// internal/domain/space/permission.go

package space

import (
	"context"
	"duanju-backend/internal/repository"
	"duanju-backend/internal/pkg/errors"
	"duanju-backend/internal/pkg/constants"
)

type PermissionService struct {
	spaceMemberRepo *repository.SpaceMemberRepository
}

// SpaceAction 空间操作枚举（Go const，不用 PostgreSQL ENUM）
type SpaceAction string

const (
	ActionView      SpaceAction = "view"      // 只读：owner/admin/member/viewer 都可
	ActionEdit      SpaceAction = "edit"      // 编辑：owner/admin/member
	ActionGenerate  SpaceAction = "generate"  // 发起生成任务：owner/admin/member
	ActionManage    SpaceAction = "manage"    // 成员管理/删除：owner/admin
	ActionDelete    SpaceAction = "delete"    // 删除项目/空间：owner
	ActionBilling   SpaceAction = "billing"   // 账单/充值查看：owner/admin/billing_only
)

// SpaceRole 空间成员角色
type SpaceRole string

const (
	RoleOwner       SpaceRole = "owner"
	RoleAdmin       SpaceRole = "admin"
	RoleMember      SpaceRole = "member"  // 可编辑可生成
	RoleViewer      SpaceRole = "viewer"  // 只读
	RoleBillingOnly SpaceRole = "billing_only"
)

// CheckSpacePermission 统一权限校验入口
// 返回值：err=nil=通过；否则返回带错误码的业务错误
// 【铁律】：所有 Domain 层资源操作函数第一行必调此函数
func (s *PermissionService) CheckSpacePermission(
	ctx context.Context,
	spaceID int64,
	userID int64,
	action SpaceAction,
) error {
	if spaceID == 0 || userID == 0 {
		return errors.NewBizError(2001, "项目不存在或无权限访问")
	}

	member, err := s.spaceMemberRepo.FindBySpaceAndUser(ctx, spaceID, userID)
	if err != nil {
		return errors.NewBizError(2001, "项目不存在或无权限访问")
	}

	role := SpaceRole(member.Role)

	switch action {
	case ActionView:
		// 所有角色均可查看
		return nil
	case ActionEdit, ActionGenerate:
		if role == RoleOwner || role == RoleAdmin || role == RoleMember {
			return nil
		}
		return errors.NewBizError(2003, "无权编辑该空间资源，当前角色仅可查看")
	case ActionManage:
		if role == RoleOwner || role == RoleAdmin {
			return nil
		}
		return errors.NewBizError(2003, "无权管理该空间成员")
	case ActionDelete:
		if role == RoleOwner {
			return nil
		}
		return errors.NewBizError(2003, "仅空间所有者可删除资源")
	case ActionBilling:
		if role == RoleOwner || role == RoleAdmin || role == RoleBillingOnly {
			return nil
		}
		return errors.NewBizError(2003, "无权查看账单信息")
	default:
		return errors.NewBizError(9500, "系统内部错误：未知权限类型")
	}
}
```

### C.4 JWT 签发 + Refresh Cookie 工具代码

```go
// internal/pkg/jwt/jwt.go

package jwtutil

import (
	"net/http"
	"time"

	"github.com/gin-gonic/gin"
	"github.com/golang-jwt/jwt/v5"
	"github.com/google/uuid"
)

type Claims struct {
	UserUUID      string `json:"sub"`
	SpaceID       int64  `json:"space_id"`
	PlatformRole  string `json:"platform_role"`
	VIPLevel      int    `json:"vip_level"`
	TokenVersion  int    `json:"token_ver"`
	jwt.RegisteredClaims
}

type JWTMgr struct {
	accessSecret     []byte
	refreshSecret    []byte
	accessExpire     time.Duration  // 2h
	refreshExpire    time.Duration  // 7d
	refreshCookieDomain string
}

// IssueAccessToken 签发 Access Token（返回字符串）
func (m *JWTMgr) IssueAccessToken(userUUID string, spaceID int64,
	platformRole string, vipLevel int, tokenVer int) (string, time.Time, error) {
	exp := time.Now().Add(m.accessExpire)
	claims := Claims{
		UserUUID:     userUUID,
		SpaceID:      spaceID,
		PlatformRole: platformRole,
		VIPLevel:     vipLevel,
		TokenVersion: tokenVer,
		RegisteredClaims: jwt.RegisteredClaims{
			ExpiresAt: jwt.NewNumericDate(exp),
			IssuedAt:  jwt.NewNumericDate(time.Now()),
			Issuer:    "duanju-api",
			ID:        uuid.New().String(),
		},
	}
	token := jwt.NewWithClaims(jwt.SigningMethodHS256, claims)
	signed, err := token.SignedString(m.accessSecret)
	return signed, exp, err
}

// SetRefreshCookie 签发 Refresh Token + 种 HttpOnly Cookie
func (m *JWTMgr) SetRefreshCookie(c *gin.Context, userUUID string, tokenVer int) error {
	exp := time.Now().Add(m.refreshExpire)
	claims := Claims{
		UserUUID:     userUUID,
		TokenVersion: tokenVer,
		RegisteredClaims: jwt.RegisteredClaims{
			ExpiresAt: jwt.NewNumericDate(exp),
			IssuedAt:  jwt.NewNumericDate(time.Now()),
			ID:        uuid.New().String(),
		},
	}
	token := jwt.NewWithClaims(jwt.SigningMethodHS256, claims)
	refreshStr, err := token.SignedString(m.refreshSecret)
	if err != nil {
		return err
	}
	c.SetCookie(
		"refresh_token",
		refreshStr,
		int(m.refreshExpire.Seconds()),
		"/api/v1/auth",      // Path 限定只在 auth 接口发送，防 CSRF
		m.refreshCookieDomain,
		true,    // Secure: 生产 HTTPS 必开
		true,    // HttpOnly: JS 无法读取
	)
	return nil
}
```

### D.2 Redis 数据结构设计（ZSet 队列 + Running 集合 + 分布式锁）

| Redis Key | 类型 | 结构/Score 设计 | 用途 |
|-----------|------|----------------|------|
| `task:queue:split` / `asset` / `video` / `export` | ZSet | `score = priority*10^12 + unix_timestamp_ms`（例：VIP7 优先级=7 → score=70001760000000000） | 按优先级+FIFO 弹出。VIP 用户 priority 自动提权 6~7，免费用户 0~3 |
| `task:running` | Set | member = task_id | 正在执行的任务 ID 集合；用于并发计数、调度器轮询不重复取 |
| `task:lock:{task_id}` | String（SETNX） | value = gocron-node-id:{pid}:{goroutine-id}; EX=30s | 单任务执行幂等锁；守护协程每 10s 续约（EX 重置 30s），panic 未续约自动释放 |
| `task:concurrency:global` / `space:{id}` / `user:{id}` | String（INCR/DECR） | value = 当前运行任务数 | 三级并发计数器。提交任务先 CAS 检查不超上限，成功才 INCR。Worker 完成后 DECR |
| `task:progress:{task_id}` | Hash | 字段 pct / msg / elapsed_ms / node_id | 进度缓存，WS 推送读这里，不读 DB 降低 IO |
| `task:throttle:{task_id}` | String（SETNX+EX） | EX=250ms | 同任务 ID 进度消息节流 250ms，只让一条通过，其余丢弃 |

### D.3 队列弹出 Lua 脚本（ZSet 原子 POP，防并发重取）

```redis
-- internal/engine/task/pop_queue.lua
-- KEYS[1] = ZSet queue key（例 task:queue:video）
-- KEYS[2] = Running Set（task:running）
-- ARGV[1] = 最大 score 截止时间戳（一般=now_ms，取不超过当前时间的任务）
-- 返回值：json 数组 [{task_id, priority}] 或空数组 []

local result = {}
-- 取最高优先级的最多 5 条（批量弹出减少 RTT）
local members = redis.call('ZRANGEBYSCORE', KEYS[1], '-inf', ARGV[1], 'WITHSCORES', 'LIMIT', 0, 5)

for i = 1, #members, 2 do
    local task_id = members[i]
    local score = members[i+1]

    -- 先尝试加 Running Set（SADD 返回 1 表示成功，0 表示已在集合中=别人已取）
    local added = redis.call('SADD', KEYS[2], task_id)
    if added == 1 then
        -- 加锁成功后才从 ZSet 移除（原子二步）
        redis.call('ZREM', KEYS[1], task_id)
        table.insert(result, cjson.encode({task_id = task_id, score = tonumber(score)}))
    end
end

return cjson.encode(result)
```

### D.4 状态机定义（queued → running → succeeded/failed/cancelled/expired）

```go
// internal/model/task.go
type TaskStatus string

const (
	StatusPending     TaskStatus = "PENDING"      // 预创建（未入队）
	StatusQueued      TaskStatus = "QUEUED"       // 已入 Redis ZSet（成功提交）
	StatusRunning     TaskStatus = "RUNNING"      // Worker 取到
	StatusSuccess     TaskStatus = "SUCCESS"      // 成功（扣积分）
	StatusFailedRetry TaskStatus = "FAILED_RETRYING" // 失败，下次自动重试（retry_count<3）
	StatusFailedDead  TaskStatus = "FAILED_DEAD"  // 死信（重试≥3 次）
	StatusCancelUser  TaskStatus = "CANCELED_USER"   // 用户手动取消
	StatusCancelTO    TaskStatus = "CANCELED_TIMEOUT" // 超时回收
	StatusSkipped     TaskStatus = "SKIPPED"      // 跨集复用跳过（M0 不用）
	StatusPaused      TaskStatus = "PAUSED_USER"  // 用户暂停（M1 加）
)

// 状态机合法转移矩阵（map[from][]to）
var validTransitions = map[TaskStatus][]TaskStatus{
	StatusPending:     {StatusQueued, StatusCancelUser},
	StatusQueued:      {StatusRunning, StatusCancelUser, StatusCancelTO},
	StatusRunning:     {StatusSuccess, StatusFailedRetry, StatusFailedDead,
	                   StatusCancelUser, StatusCancelTO},
	StatusFailedRetry: {StatusQueued, StatusFailedDead},
	StatusCancelTO:    {}, // 终态
}

// CanTransition 是否允许从 from 转到 to
func CanTransition(from, to TaskStatus) bool {
	tos, ok := validTransitions[from]
	if !ok { return false }
	for _, allowed := range tos {
		if allowed == to { return true }
	}
	return false
}
```

### D.5 失败重试策略（指数退避 max 3 次）

| 第几次重试 | backoff_seconds | 触发条件 |
|----------|----------------|---------|
| 第 1 次（retry_count=0→1） | 15s | 网络 5xx / 模型超时 MODEL_TIMEOUT / VRAM 溢出 |
| 第 2 次（1→2） | 60s | 同上 + 第一次重试仍失败 |
| 第 3 次（2→3） | 180s | 同上 |
| ≥3 次 | — | 转 FAILED_DEAD，写死信表，发告警，积分全额退回 |

入队时 score = priority*10^12 + (now_ms + backoff_seconds*1000)，这样 ZRANGEBYSCORE 时间没到不会取出，天然支持延迟重试。

### D.6 三级并发控制（全局/空间/用户）— 提交任务前校验

```go
// internal/engine/task/concurrency.go
package taskengine

type ConcurrencyConfig struct {
	GlobalMax int // 默认 100（单机 4 类 Worker 总和）
	SpaceMax  int // 默认 20
	UserMax   int // 默认 3（M0 免费用户限并发≤3）
	VIPBoost  map[int]int // VIP 等级 1~4：5/8/15/20
}

// TryAcquire 并发额度 CAS 申请
// 返回值：releaseFunc() 释放函数；acquired=是否成功；err=系统异常
func (c *ConcurrencyMgr) TryAcquire(ctx context.Context,
	userID int64, spaceID int64, vipLevel int,
) (releaseFunc func(), acquired bool, err error) {
	userLimit := c.UserMax
	if boost, ok := c.VIPBoost[vipLevel]; ok {
		userLimit = boost
	}

	// 顺序：用户→空间→全局。任一超限立即回滚已加的。
	userKey := fmt.Sprintf("task:concurrency:user:%d", userID)
	spaceKey := fmt.Sprintf("task:concurrency:space:%d", spaceID)
	globalKey := "task:concurrency:global"

	// 1. 用户级 CAS（WATCH+MULTI 原子性）
	txf := func(tx *redis.Tx) error {
		cur, err := tx.Get(ctx, userKey).Int()
		if err != nil && err != redis.Nil { return err }
		if cur >= userLimit { return ErrUserConcurrency }
		_, err = tx.TxPipelined(ctx, func(p redis.Pipeliner) error {
			p.Incr(ctx, userKey)
			p.Expire(ctx, userKey, 24*time.Hour)
			return nil
		})
		return err
	}
	if err := c.rdb.Watch(ctx, txf, userKey); err != nil {
		return nil, false, err
	}
	// 空间/全局 同理省略（代码按用户级同结构写）

	releaseFunc = func() {
		// 成功后 DECR 三个 key
		c.rdb.Decr(ctx, userKey)
		// ... space/global decr
	}
	return releaseFunc, true, nil
}
```

### E.3 Key 加密存储（AES-256-GCM）+ 脱敏展示 + 轮换

```go
// internal/pkg/aesgcm/aes.go
package aesgcm

import (
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"encoding/base64"
	"errors"
	"io"
)

// 32 字节主密钥（从环境变量 AES_MASTER_KEY 读取 viper）
type Crypter struct{ gcm cipher.AEAD }

func NewCrypter(masterKey32Byte []byte) (*Crypter, error) {
	if len(masterKey32Byte) != 32 {
		return nil, errors.New("aes key must be 32 bytes (AES-256)")
	}
	block, err := aes.NewCipher(masterKey32Byte)
	if err != nil { return nil, err }
	gcm, err := cipher.NewGCM(block)
	if err != nil { return nil, err }
	return &Crypter{gcm: gcm}, nil
}

func (c *Crypter) Encrypt(plaintext string) (cipherB64 string, err error) {
	nonce := make([]byte, c.gcm.NonceSize())
	if _, err := io.ReadFull(rand.Reader, nonce); err != nil { return "", err }
	ct := c.gcm.Seal(nonce, nonce, []byte(plaintext), nil)
	return base64.StdEncoding.EncodeToString(ct), nil
}

func (c *Crypter) Decrypt(cipherB64 string) (plaintext string, err error) {
	ct, err := base64.StdEncoding.DecodeString(cipherB64)
	if err != nil { return "", err }
	ns := c.gcm.NonceSize()
	if len(ct) < ns { return "", errors.New("ciphertext too short") }
	nonce, raw := ct[:ns], ct[ns:]
	pt, err := c.gcm.Open(nil, nonce, raw, nil)
	if err != nil { return "", err }
	return string(pt), nil
}

// 脱敏展示：取前 6 + **** + 后 4
func MaskKey(raw string) string {
	if len(raw) <= 10 { return "****" }
	return raw[:6] + "****" + raw[len(raw)-4:]
}
```

### H.2 支付宝当面付回调 7 步验签流程（Go 伪代码）

对应 10 号文档 TAG 8.6 说明：

```go
// internal/domain/billing/alipay_service.go

// AlipayWebhook 支付宝异步回调处理（POST /payments/webhook/alipay）
// 安全检查严格按 1→7 顺序，任何一步失败返回字符串 "fail"
func (s *AlipayService) HandleWebhook(ctx context.Context,
	form map[string]string, clientIP string,
) (respBody string, err error) {
	// ===== Step 1: 验签（支付宝 RSA2 公钥校验 sign 字段） =====
	ok, err := s.alipaySDK.VerifySign(form)
	if !ok || err != nil {
		s.auditLogRepo.Write(ctx, &model.AuditLog{
			Action:   "ALIPAY_VERIFY_FAILED",
			ClientIP: clientIP,
			Extra:    fmt.Sprintf("form=%v", form),
		})
		return "fail", nil // 返回 fail，支付宝会重试
	}

	// ===== Step 2: 校验 7 个核心字段 =====
	// 2a: 时间戳 timestamp（如开启）≤ 当前时间 + 5 分钟 防重放
	// 2b: nonce 24 小时内 Redis SETNX（防止同一笔回调 24h 内重复处理）
	nonceKey := "alipay:nonce:" + form["nonce"] + ":" + form["trade_no"]
	set, err := s.rdb.SetNX(ctx, nonceKey, "1", 24*time.Hour).Result()
	if err == nil && !set {
		// 24h 内已处理过 → 直接返回 success（幂等）
		return "success", nil
	}
	// 2c: sign_type == "RSA2"（Step1 已经验过）
	// 2d: app_id == 我们的支付宝应用 ID（防止串商户）
	if form["app_id"] != s.cfg.AppID {
		return "fail", nil
	}
	// 2e: out_trade_no == 我们 order_no
	outTradeNo := form["out_trade_no"]
	// 2f: total_amount == orders.paid_amount_yuan（字符串转 decimal 精确比对到分）
	totalAmountStr := form["total_amount"]

	// ===== Step 3: 幂等（已 PAID 的订单不再处理，直接返回 success） =====
	order, err := s.orderRepo.FindByOrderNo(ctx, outTradeNo)
	if err != nil {
		return "fail", nil
	}
	if order.PayStatus == model.PayPaid {
		return "success", nil
	}
	if order.PayStatus != model.PayPending {
		return "fail", nil
	}

	// 金额精确比对：避免 50.0 vs "50.00" 的浮点误差
	paidYuanCent := int64(order.PaidAmountYuan * 100)
	formCent := s.parseAlipayAmountToCents(totalAmountStr)
	if paidYuanCent != formCent {
		return "fail", nil
	}

	// ===== Step 4~6: DB 事务（更新订单+扣积分+写流水） =====
	err = s.repo.RunInTx(ctx, func(tx pgx.Tx) error {
		// Step 4: UPDATE orders SET pay_status=PAID, paid_at=NOW(), trade_no=?
		if err := s.orderRepo.UpdatePaidTx(ctx, tx, order.ID, form["trade_no"]); err != nil {
			return err
		}

		// Step 5: 积分扣减/增加（事务内 SELECT FOR UPDATE 防并发）
		// user_points.current_balance += order.PointsGrantedTotal
		newBalance, err := s.pointRepo.AddBalanceTx(ctx, tx, order.UserID, order.PointsGrantedTotal)
		if err != nil {
			return err
		}

		// Step 6: 写 point_transactions（CREDIT + PURCHASE_POINTS_PACKAGE）
		if err := s.pointRepo.WriteTransactionTx(ctx, tx, &model.PointTransaction{
			AccountID:             order.UserID, // M0 user_id=account_id 一对一
			TxnUUID:               uuid.New().String(),
			TxnType:               constants.TxnPurchasePointsPkg,
			Direction:             constants.DirectionCredit,
			Amount:                order.PointsGrantedTotal,
			BalanceAfter:          newBalance,
			RelatedOrderID:        order.ID,
			Description:           fmt.Sprintf("充值积分包 %s +%d", order.PackageCode, order.PointsGrantedTotal),
		}); err != nil {
			return err
		}
		return nil
	})
	if err != nil {
		return "fail", nil // 事务失败，让支付宝重试
	}

	// ===== Step 7: 若用户 WS 在线，主动推余额更新 =====
	s.notifyHub.BroadcastToUser(order.UserID, &wsmsg.PointsBalanceChanged{
		NewBalance:   newBalance,
		DeltaAmount:  order.PointsGrantedTotal,
		Direction:    "CREDIT",
		ReasonLabel:  fmt.Sprintf("充值成功 +%d", order.PointsGrantedTotal),
	})

	return "success", nil // 必须返回纯字符串 success，否则支付宝 24h 内反复回调
}
```

### H.3 生成任务积分扣减事务（SELECT FOR UPDATE）

```go
// internal/engine/billing/point_tx.go

// DeductPointsOnTaskSuccess 任务成功后扣积分事务
// 【铁律】扣积分必须在同一 DB 事务内，顺序固定：
//   SELECT FOR UPDATE 查余额 → 写 billing_records → 写 point_transactions → UPDATE point_accounts
func (b *BillingEngine) DeductPointsOnTaskSuccess(ctx context.Context,
	taskID, userID, spaceID int64,
	costPoints int, costBreakdown map[string]int,
) (newBalance int, err error) {
	err = b.repo.RunInTx(ctx, func(tx pgx.Tx) error {
		// 1. SELECT FOR UPDATE 行锁（禁止幻读/并发双扣）
		acct, err := b.pointRepo.LockForUpdateTx(ctx, tx, userID)
		if err != nil { return err }
		if acct.FrozenBalance < costPoints {
			return errors.NewBizError(4000, fmt.Sprintf("冻结积分不足：冻结%d 需扣%d", acct.FrozenBalance, costPoints))
		}

		// 2. UPDATE frozen_balance -= costPoints（冻结→扣减，余额不变；冻结的钱本来就从余额划出来了）
		newFrozen := acct.FrozenBalance - costPoints
		newLifetimeSpent := acct.LifetimeSpentTotal + costPoints
		if err := b.pointRepo.UpdateFrozenAndSpentTx(ctx, tx, userID, newFrozen, newLifetimeSpent); err != nil {
			return err
		}

		// 3. 写 billing_records（任务计费流水）
		if err := b.billingRepo.CreateTx(ctx, tx, &model.BillingRecord{
			TaskID:         taskID,
			SpaceID:        spaceID,
			UserID:         userID,
			CostPoints:     costPoints,
			CostBreakdown:  costBreakdown,
			Status:         "DEDUCTED",
		}); err != nil {
			return err
		}

		// 4. 写 point_transactions（FROZEN → DEBIT 扣减）
		if err := b.pointRepo.WriteTransactionTx(ctx, tx, &model.PointTransaction{
			AccountID:              userID,
			TxnUUID:                uuid.New().String(),
			TxnType:                constants.TxnGenVideo, // 按 task_type 映射
			Direction:              constants.DirectionDebit,
			Amount:                 costPoints,
			BalanceAfter:           acct.CurrentBalance, // 扣冻结后余额未变
			FrozenAfter:            newFrozen,
			RelatedGenerationTaskID: taskID,
			Description:            fmt.Sprintf("生成任务 #%d 扣减 %d 积分", taskID, costPoints),
		}); err != nil {
			return err
		}

		newBalance = acct.CurrentBalance
		return nil
	})
	return newBalance, err
}

// UnfreezeOnTaskFail 任务失败解冻积分策略：
//   - CANCELED_USER（用户主动取消）→ 不退！（占了算力排队时间）
//   - CONTENT_VIOLATION / NSFW_BLOCKED（违规）→ 不退！
//   - 其他（超时/模型失败/网络）→ 全额退还 frozen → current_balance
func (b *BillingEngine) UnfreezeOnTaskFail(ctx context.Context,
	taskID, userID int64, errorCode string,
) error {
	refund := true
	switch errorCode {
	case "USER_CANCEL", "CONTENT_VIOLATION", "NSFW_BLOCKED":
		refund = false
	}
	// 如果不退款：把冻结的钱清零（算收入），写流水 FROZEN → DEBIT
	// 如果退款：frozen → balance，写流水 FROZEN → UNFREEZE
	// （同 DeductPoints 事务模式，省略完整代码）
	return nil
}
```

```go
	policy.SetContentLengthRange(sizeBytes*9/10, sizeBytes*11/10)

	formData, uploadURL, err := a.minioClient.PresignedPostPolicy(ctx, &policy)
	if err != nil {
		return nil, err
	}
	// asset_token = JWT(key, userID, sizeBytes, expireAt) 防篡改 Complete
	token := a.signAssetToken(key, userID, sizeBytes, policy.Expires)
	return &PresignPostResp{
		UploadURL:  uploadURL.String(),
		FormData:   formData,
		AssetToken: token,
		ExpiresAt:  policy.Expires,
	}, nil
}

// CompleteUpload 上传完成回执：校验 token → 统计对象大小 → 关联业务对象（asset/variant）
func (a *AssetEngine) CompleteUpload(ctx context.Context,
	token string, businessRef dto.BusinessRef,

	key, userID, _, exp := a.verifyAssetToken(token)
	if time.Now().After(exp) {
		return "", errors.NewBizError(9500, "上传回执已过期")
	}
	// HeadObject 验证真实存在，返回最终 CDN URL

	}

}
```

### L.2 FFmpeg 滤镜流水线（concat / overlay / amerge）

```go
// internal/engine/video/ffmpeg_pipeline.go

// BuildFFmpegCommands 根据 TimelineProject 构建多段 ffmpeg 命令
// Step1: 视频/图片片段转码为统一编码 ts 文件（demuxer concat 要求）
// Step2: 使用 concat demuxer 拼接同轨道所有片段 → track_v1.mp4
// Step3: overlay 滤镜叠加多层（图片/画中画）：[v0][v1]overlay=x:y[outv]
// Step4: amerge 滤镜合并多音轨：[a0][a1]amerge=inputs=2[aout]
// Step5: 最终输出完整 mp4 + 烧录字幕（可选）

func (vp *VideoPipeline) Compose(ctx context.Context,
	timeline *TimelineProject, outputPath string,
) (finalMP4 string, err error) {
	// 1. 准备工作目录（用于存中间 ts / 日志）
	workDir := filepath.Join(os.TempDir(), "ffmpeg", uuid.New().String())
	if err := os.MkdirAll(workDir, 0755); err != nil {
		return "", err
	}
	defer func() { // 7 天生命周期清理兜底
		go func() {
			time.Sleep(7 * 24 * time.Hour)
			os.RemoveAll(workDir)
		}()
	}()

	// 2. 每条轨道各自 concat（先把所有 clip 转成同编码 ts，再 demuxer concat）
	var trackFiles []string
	for _, track := range timeline.Tracks {
		if track.TrackType == "audio" { continue } // 音轨后面单独处理
		concatFile, err := vp.concatTrackClips(ctx, workDir, track)
		if err != nil { return "", err }
		trackFiles = append(trackFiles, concatFile)
	}

	// 3. 多层 overlay（假设最多 3 层视频轨 + 1 层图片）
	filterComplex := "[0:v]" // 基础视频轨
	for i := 1; i < len(trackFiles); i++ {
		// 简化：按轨道 z_index 排序后依次 overlay=x:y
		// 真实实现需要从 track.clips 取每张图的 x/y/duration
		filterComplex = fmt.Sprintf("%s[%d:v]overlay=%d:%d[v%d]",
			filterComplex, i, 0, 0, i)
	}
	// （省略：amerge 多音轨合并 / 字幕烧录 drawtext / 缩放 scale）

	// 4. 组装最终 ffmpeg 命令，实时解析进度（stderr 解析 time=xx:xx:xx.xx）
	args := []string{"-y"}
	for _, f := range trackFiles { args = append(args, "-i", f) }
	if filterComplex != "[0:v]" {
		args = append(args, "-filter_complex", filterComplex)
		// -map "[v3]" -map "[aout]" 省略
	}
	args = append(args, "-c:v", "libx264", "-preset", "veryfast",
		"-crf", "23", "-c:a", "aac", "-b:a", "192k", outputPath)
	cmd := exec.CommandContext(ctx, "ffmpeg", args...)

	// stderr 捕获 FFmpeg 日志 → 落盘 ffmpeg-{task_id}.log + 解析进度回调
	progressPipe, _ := cmd.StderrPipe()
	go vp.parseFFmpegProgress(ctx, progressPipe, vp.taskID, vp.onProgress)

	if err := cmd.Run(); err != nil {
		vp.logFFmpegError(vp.taskID, outputPath, err)
		return "", err
	}
	return outputPath, nil
}
```

```go
// internal/engine/notify/hub.go
package notifyhub

import (
	"sync"
	"duanju-backend/internal/dto"
)

type SubscriptionTopic string

const (
	TopicTask     SubscriptionTopic = "task"     // task:{task_id}
	TopicPoints   SubscriptionTopic = "points"   // points:{user_id}
	TopicNotify   SubscriptionTopic = "notify"   // notify:{user_id}
	TopicSysBC    SubscriptionTopic = "sys"      // sys:broadcast 全站广播
)

// WebSocket 连接实例
type Client struct {
	ConnID     string
	UserUUID   string
	UserID     int64
	Send       chan []byte            // 下行发送缓冲
	Subscribed map[string]struct{}    // 已订阅的 topic key（例 "task:1234"）
	mu         sync.Mutex
}

type Hub struct {
	clients    map[*Client]struct{}        // 所有在线连接
	broadcast  chan []byte                  // sys:broadcast
	register   chan *Client
	unregister chan *Client

	// topic → clients 索引
	topicIndex map[string]map[*Client]struct{}
	mu         sync.RWMutex
}

func NewHub() *Hub {
	return &Hub{
		clients:    make(map[*Client]struct{}),
		broadcast:  make(chan []byte, 256),
		register:   make(chan *Client, 64),
		unregister: make(chan *Client, 64),
		topicIndex: make(map[string]map[*Client]struct{}),
	}
}

// Run 主事件循环（单 goroutine，无锁设计）
func (h *Hub) Run() {
	for {
		select {
		case c := <-h.register:
			h.clients[c] = struct{}{}
		case c := <-h.unregister:
			if _, ok := h.clients[c]; ok {
				delete(h.clients, c)
				close(c.Send)
				// 从所有 topic 反注册
				for t := range c.Subscribed {
					if m, ok := h.topicIndex[t]; ok {
						delete(m, c)
					}
				}
			}
		case msg := <-h.broadcast:
			for c := range h.clients {
				select {
				case c.Send <- msg:
				default: // 缓冲满踢下线，防 goroutine 泄漏
					close(c.Send)
					delete(h.clients, c)
				}
			}
		}
	}
}

// Subscribe 订阅
func (h *Hub) Subscribe(c *Client, topicFullKey string) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if _, ok := h.topicIndex[topicFullKey]; !ok {
		h.topicIndex[topicFullKey] = make(map[*Client]struct{})
	}
	h.topicIndex[topicFullKey][c] = struct{}{}
	c.Subscribed[topicFullKey] = struct{}{}
}

func (h *Hub) PublishToTopic(topicKey string, msg []byte) {
	h.mu.RLock()
	defer h.mu.RUnlock()

	if !ok { return }
	for c := range m {
		select {
		case c.Send <- msg:
		default:
			// 同上踢下线
		}
	}
}
```

```go
type progressThrottle struct {
	mu       sync.Mutex
	pending  map[string]*MsgTaskProgressPayload // key=task_id
	timer    *time.Timer
	interval time.Duration // 250ms
	hub      *Hub
}

func (pt *progressThrottle) Emit(p *MsgTaskProgressPayload) {
	pt.mu.Lock()
	pt.pending[p.TaskUUID] = p
	if pt.timer == nil {
		pt.timer = time.AfterFunc(pt.interval, pt.flush)
	}
	pt.mu.Unlock()
}

func (pt *progressThrottle) flush() {
	pt.mu.Lock()
	items := make([]*MsgTaskProgressPayload, 0, len(pt.pending))
	for _, v := range pt.pending { items = append(items, v) }
	pt.pending = make(map[string]*MsgTaskProgressPayload)
	pt.timer = nil
	pt.mu.Unlock()
	// 批量 Publish
	for _, p := range items {
		buf, _ := json.Marshal(p)
		pt.hub.PublishToTopic("task:"+p.TaskUUID, buf)
	}
}
```

```go
// internal/pkg/redislock/lock.go
type RedisLock struct{
	rdb         *redis.Client
	key         string
	value       string // 唯一标识：node_id:pid:gid:start_ts
	ttl         time.Duration
	stopRenew   chan struct{}
	locked      bool
}

// Lock 加锁（SET NX EX 原子），成功后启动续约协程（每 ttl/3 续一次）
func (l *RedisLock) Lock(ctx context.Context) (bool, error) {
	if l.ttl == 0 { l.ttl = 30 * time.Second }
	l.value = fmt.Sprintf("%s:%d:%d:%d",
		hostname, os.Getpid(), getGID(), time.Now().UnixMilli())
	ok, err := l.rdb.SetNX(ctx, l.key, l.value, l.ttl).Result()
	if err != nil || !ok { return ok, err }
	l.locked = true
	l.stopRenew = make(chan struct{})
	// 续约守护协程
	go func() {
		tick := time.NewTicker(l.ttl / 3)
		defer tick.Stop()
		for {
			select {
			case <-tick.C:
				// 仅当 value 还是我自己时才 EXPIRE 续约（防止续了别人的锁）
				l.rdb.Eval(ctx, `
					if redis.call("GET", KEYS[1]) == ARGV[1] then
						return redis.call("EXPIRE", KEYS[1], ARGV[2])
					else return 0 end
				`, []string{l.key}, l.value, int(l.ttl.Seconds()))
			case <-l.stopRenew:
				return
			}
		}()
	return true, nil
}

// Unlock 释放：Lua 脚本判断 value=自己才 DEL，避免误删别人的锁
func (l *RedisLock) Unlock(ctx context.Context) {
	close(l.stopRenew)
	l.rdb.Eval(ctx, `
		if redis.call("GET", KEYS[1]) == ARGV[1] then
			return redis.call("DEL", KEYS[1])
		else return 0 end
	`, []string{l.key}, l.value)
}
```

- 429 自动切换：Router.SelectKey 遇到 429 → 临时从候选池移除，5 分钟后恢复

### P.5 风险 5：Agent 流式输出与异步任务回填的一致性

**场景**：用户看到 SSE XML 已输出 `<character id=23 name=沈青禾>`，但 DB 里 characters 表 23 号还没插入→前端点生成时报 404。

**解决方案**：J.5 节 `consistency.go` 机制：

```go
// internal/engine/agent/consistency.go

type ConsistencyMgr struct{
	// task_id → 累积的 XML delta 字符串
	pendingDeltas  map[int64]strings.Builder
	// task_id → 已完成的 SQL 写入 list（逐条回放）
	pendingWrites  map[int64][]any
}

// 流程：
// 1. SSE 每 flush 一段 → AppendDelta(task_id, chunk)
// 2. LLM 返回完整结果 → 后台 goroutine 异步解析 XML → 写 characters/scenes/shots 表
// 3. 全部写完前 generation_tasks.status = RUNNING
// 4. 写全成功 → SUCCESS + WS TASK_SUCCESS 才发 result
// 5. 中途任一 SQL 失败 → 整个 task 置 FAILED_RETRYING，积分不扣，重跑整个 Agent
// （最终一致性保障：DB 事务写 characters + beats + shots 要么全成要么全回滚）
```

### P.6 风险 6：衍生资产追溯（批量生成失败的那几条不知道 parent_id 是谁、无法单独重试）

**场景**：一次 batch 20 条衍生，17 条成 3 条失败，用户要单独重跑失败的 3 条，但 UI 不知道对应 ref_asset_ids 是哪几张。

**解决方案**：K.1 节 generated_images 表 + 任务自关联 parent_task_id：

```sql

-- generated_images.ref_asset_ids int[]：多张参考图数组，按权重排序
-- generated_images.parent_variant_id：顶层源头（追溯链 parent_id→parent_id→...→NULL）

-- 失败重试 SQL：找出这个 batch 下失败的
-- SELECT gt.id, gt.task_type, gt.error_code, gi.parent_variant_id, gi.ref_asset_ids
--   FROM generation_tasks gt
```

#### C.3 限流 429 + 熔断降级策略：
- **单 Key 命中 429 后自动切换下一可用 Key**（按 model_keys.priority 降序）：
  ```go
  // internal/engine/model/router.go SelectKey() 遇到 429：
  // 1. 把当前 Key 临时加入 Redis 缓存 "circuit:key:{id}" = "429" EX 300s（5 分钟跳过）
  // 2. 取下一个 priority 次高的 Key，重新走 RPM 令牌桶检查
  // 3. 如果所有 Key 都在 429 临时熔断中 → 抛 code=90003
  ```
- **同一 Key 连续失败 3 次标记不可用 5 分钟熔断**：
  - 失败判定范围：HTTP 5xx / 网络超时（>30s）/ 厂商返回 error_code=SYSTEM_ERROR（非 NSFW/参数错误等用户侧问题）
  - fail_count++（写 DB model_keys.fail_count + last_fail_at），连续 3 次失败 → model_keys.status=0（熔断）+ 写 Redis "circuit:key:{id}" EX 300s
  - 5 分钟后 Redis TTL 到期，Router.SelectKey 下次查询时自动把 status 恢复 1（前提是 DB status 还是 0 且人工没设停用=2）
- **熔断期间路由跳过**：`SELECT * FROM model_keys WHERE model_id=? AND status=1` 直接过滤掉 DB 层面熔断的，Redis 层面临时熔断在内存过滤
- **所有 Key 全熔断 → 抛 code=90003「厂商限流降级，请稍后重试」**（05 接口文档 C 节 9xxx 系统码）+ **写入失败告警 Prometheus Counter**：
  ```
  # Prometheus metrics
  duanju_model_circuit_break_total{provider="seedance", model="SEEDANCE_2_5_VIP"} 3
  duanju_model_request_fail_total{provider="kling", error_code="429_RATE_LIMITED"} 27
  ```
  同时 Sentry 告警发邮件 + 钉钉群机器人通知运维（model_keys 全熔断=P1 级故障，30 分钟内响应）

- **每次生成任务的 prompt 版本号要写入 generation_tasks.params.prompt_version**（JSONB 字段里的 `prompt_version: "v2.3.1"`）方便回溯「为什么这次输出格式不对」：

#### C.5 视频模型异步回调 vs 轮询策略：
- **厂商支持 webhook → 优先 webhook**（`/api/v1/internal/model-callback/{provider}` 鉴权用 provider 的 secret HMAC 签名校验）：
  - 校验流程：从 URL path 取 provider_code → 查 model_providers 取 webhook_secret → 取请求头 `X-Signature: sha256=xxx` → 用 webhook_secret + raw body 计算 HMAC-SHA256 → 和 X-Signature 比对 → 不匹配直接 401 丢弃
  - 白名单 IP：回调接口最好再加一层 Nginx IP 白名单（Seedance/Kling 官方回调 IP 段从厂商文档获取），双保险防伪造回调
- **厂商不支持 → 轮询间隔 15s**（防止 429），超时上限 30 分钟：
  ```go
  // internal/engine/model/provider_xxx.go 轮询循环（goroutine 异步跑，不阻塞 Worker）
  func (p *XXXProvider) pollProgressLoop(ctx context.Context, handle *TaskHandle, req *GenRequest) {
      ticker := time.NewTicker(15 * time.Second)   // 固定 15s，不要 5s
      defer ticker.Stop()
      timeout := time.After(30 * time.Minute)      // 超时上限 30 分钟
      for {
          select {
          case <-ctx.Done(): return
          case <-timeout:
              // 超时 → 回调 onProgress(0, "超时 30 分钟未完成", true, ErrTimeout)
              return
          case <-ticker.C:
              pct, msg, done, err := p.Progress(ctx, handle)
              if err != nil { /* 错误处理，连续 3 次 err 才放弃 */ }
              req.OnProgress(pct, msg)
              if done { return }
          }
      }
  }
  ```
- **无论 webhook 还是轮询，收到结果都要过幂等检查**：`generation_tasks.status` 已经 `SUCCEEDED` 绝不重复写 OSS/重复扣费：
  ```go
  // 收到厂商完成回调 / 轮询 done 后第一行必调：
  curStatus, err := taskRepo.GetStatus(ctx, taskID)
  if err != nil { return err }
  if curStatus == StatusSuccess || curStatus == StatusFailedDead {
      // 已经处理过了（可能同一任务 webhook + 轮询同时到达），直接返回不做任何操作
      log.Warn("task already final, skip duplicate callback", zap.Int64("task_id", taskID))
      return nil
  }
  // 通过幂等检查后才：写 OSS → 扣积分 → 更新 DB status → WS 通知
  ```
  同时 `generation_task_retry_logs` 表记录每次回调的 provider_task_id + raw payload JSONB，方便事后审计重复回调问题。

- **LLM 拆分输出 XML 格式不正确 → 自动重试 1 次**（附加错误位置提示）：

#### C.7 成本监控（每模型积分定价 vs 实际厂商调用成本）：
- **每小时汇总一次「generation_tasks 各 model_key 调用次数 × 厂商单调用实际价格」和「billing_records 总收入积分 × 积分汇率」比值**，如果 >1.2（成本超过定价 120%）→ 发送告警给管理员，可临时调低并发阈值或暂停该模型：
  ```sql
  -- internal/engine/billing/cost_monitor.go gocron 每小时执行：
  SELECT
      m.model_code,
      COUNT(*)                                            AS calls_hour,
      SUM(br.cost_points)                                 AS total_points_charged,
      SUM(mk.actual_cost_yuan_per_call * 1.0)             AS total_vendor_cost_yuan,
      (SUM(mk.actual_cost_yuan_per_call) / NULLIF(SUM(br.cost_points) * $exchange_rate, 0)) AS cost_revenue_ratio
  FROM generation_tasks gt
  JOIN billing_records br ON br.task_id = gt.id
  JOIN model_keys mk     ON mk.id = gt.model_key_id
  JOIN models m          ON m.id = mk.model_id
  WHERE gt.created_at >= NOW() - INTERVAL '1 hour'
    AND gt.status = 'SUCCESS'
  GROUP BY m.model_code;
  ```
  - `$exchange_rate` = 积分汇率（1 积分 = 多少元，从 configs/point_exchange_rate.yaml 读，默认 0.01 元/积分 = 1 元=100 积分）
  - `model_keys.actual_cost_yuan_per_call` 字段：每个 Key 对应的厂商单调用实际成本（按厂商官方价目表填，例 Seedance 2.5 VIP 720p = 0.25 元/次），管理后台可编辑
  - 告警规则：`cost_revenue_ratio > 1.2` → P2 级告警（企业微信 + 邮件），运营需要 24 小时内处理（要么上调 models.point_cost 积分定价，要么联系厂商谈折扣把 actual_cost_yuan_per_call 调低）
  - `cost_revenue_ratio > 1.5` → P1 级严重告警（电话 + 钉钉@所有人），自动触发引擎保护：`model_keys.status=0` 临时熔断该模型所有 Key（避免继续亏钱），对外用户端显示 code=90002「该模型临时维护中，请稍后重试或切换其他模型」，管理员在管理后台手动解除（点「恢复模型」按钮）
