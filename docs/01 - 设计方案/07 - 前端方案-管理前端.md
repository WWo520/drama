### 1.1 管理端特有数据真源规则（强制执行，违反算 Bug）

① **分页(page/page_size) / 筛选(keyword/status) / 排序** → 放 URL SearchParams（不是 Zustand），保证刷新 / 分享 / 后退都还原
② **用户列表 / 订单列表 / 作品列表 / 审计日志等远程数据** → TanStack Query Cache（不是 Zustand），严禁双源复制不一致
③ **交互状态 / 临时勾选 / 弹窗开关** → 最后才用 Zustand 或 useState
④ **ProTable 列设置（显示哪些列 / 列顺序 / 列宽）** → 持久化 localStorage，key=`admin:table-cols:用户列表`

本方案专注于**管理端 Web 应用** `apps/web-admin`，面向运营 / 平台管理员 / 内容审核员 / 财务人员提供后台管理工作台。

| 维度 | 管理端 Web 说明 |
|------|---------------|
| 包名 | `apps/web-admin` |
| 目标用户 | 运营 / 管理员 / 审核员 / 财务 / 超管 |
| UI 体系 | Ant Design 5 + Pro Components（ProLayout / ProTable / ProForm） |
| 设计目标 | 高效清晰、表格优先、RBAC 权限细粒度控制、审核工作台二开快捷键 |

### 2.3 web-admin 目录结构（根结构与共享包见 06 四章）

> 根目录结构（apps/packages/共享包）与共享层规范统一见 [06 - 前端方案-用户前端.md](./06%20-%20前端方案-用户前端.md) 四章，本文只列 **web-admin 包内**结构。

#### 2.3.1 web-admin 包 src 目录分层职责

| 目录 | 职责 | 行数限制 |

#### 2.3.2 路由前缀与 Nginx 反代说明

管理端路由统一 `/admin/**` 前缀，Nginx 两条规则：
- `/admin/` → SPA history 模式 fallback（所有未命中静态文件回退到 `/admin/index.html`）
- `/api/v1/admin/` → 反向代理到后端管理端接口服务

用户端走 `/` 前缀，API 走 `/api/v1/`（不含 admin），两者完全隔离，Cookie 域 `domain=.duanju.com` 共享。

## 四、🔴 管理端路由树（/admin/** 全部分页）

### 4.1 路由分类与权限层级

| 路由类别 | 前缀 | 最少角色要求 | loader 守卫规则 |
|---------|------|------------|----------------|
| **T1 登录页** | `/admin/login` | 无（公开） | publicLoader：已登录且有 admin 角色 → `/admin/overview` |
| **T2 受保护基础路由** | `/admin/overview` / `/admin/users/**` / `/admin/platform/**` | `ADMIN` / `SUPER_ADMIN` | adminRbacLoader：①鉴权（登录态）②角色校验（不是 admin 403）③菜单权限预加载 |
| **T3 审核 / 内容类** | `/admin/audit/**` / `/admin/works/**` | `AUDITOR` / `ADMIN` / `SUPER_ADMIN` | 基础 T2 + 额外审核权限（`works.review`）校验 |
| **T4 财务 / 计费类** | `/admin/billing/**` / `/admin/orders/**` | `FINANCE` / `SUPER_ADMIN` | 基础 T2 + 财务权限（`billing.manage`）校验 |

## 五、🔴 鉴权守卫：adminRbacLoader + 菜单权限过滤

### 5.1 RBAC 权限模型（与 02 - 数据库设计.md B1.5 `roles.permissions` JSONB 对齐）

#### 5.1.1 6 大角色层级

| 角色 code | 说明 | 典型可访问菜单 |
|----------|------|--------------|
| `SUPER_ADMIN` | 超管（创始人/技术主管） | **全部** + 超管专属：角色权限矩阵 / 模型厂商Key / 平台配置 |
| `ADMIN` | 普通管理员 | Overview / 用户列表 / 作品管理 / 审核工作台 / 日志 / 算力监控 / 运营 Banner |
| `FINANCE` | 财务 | Billing 全部 3 子页 + Overview（不含用户/审核/算力） |
| `AUDITOR` | 审核员 | 审核工作台 3 子页 + Overview（不含用户/财务/算力） |
| `USER` | 普通用户（前端 C 端） | 禁止进入管理端（403） |
| `GUEST` | 游客 | 禁止进入管理端（403） |

#### 5.1.2 permissions JSONB 字段结构（唯一真源 = 02 - 数据库设计.md B1.5）

键命名两类规则：
- **菜单级**：`menu:<菜单key>`，值 true/false，控制 ProLayout 菜单项显示；菜单 key 与 4.3.1 对照表严格一致（如 `menu:overview` / `menu:users-list` / `menu:billing-orders` / `menu:platform-config` 共 20 项）
- **按钮级**：`<模块>:<动作>`，控制 ProTable 操作列按钮渲染与 mutation 调用，典型键：

| 权限键 | 含义 | 备注 |
|--------|------|------|
| `users:ban` | 封禁用户 | ADMIN+ |
| `users:adjust-points` | 调整积分 | ADMIN+ |
| `audit:works-pass` / `audit:works-reject` | 作品审核通过 / 驳回 | AUDITOR+ |
| `audit:works-batch-pass` | 批量通过 | AUDITOR+ |
| `billing:manual-refund` | 人工退款 | 财务专属 |
| `tasks:rerun-dead-letter` | 死信重跑 | ADMIN+ |
| `platform:edit-config` | 平台配置修改 | 超管专属 |
| `export:excel` | 导出 Excel 通用 | 按模块另控 |

角色差异示例：普通 ADMIN 的 `menu:users-roles` / `menu:billing-*` / `menu:tasks-model-vendor` / `menu:platform-config` 均为 false；SUPER_ADMIN 直接赋 `*` 通配。

### 5.2 三级守卫行为契约（loaders.ts）

| 守卫 | 适用范围 | 行为契约 |
|------|---------|---------|
| `publicLoader` | `/admin/login` | 已登录且角色属 admin 系列（SUPER_ADMIN/ADMIN/FINANCE/AUDITOR）→ 重定向 `/admin/overview`；否则停留登录页 |
| `adminRbacLoader` | `/admin` 根路由（全局） | ① 未登录 → `/admin/login?redirect=原路径`；② 角色非 admin 系列 → Toast 提示 + 403；③ 通过则预拉 permissions（`GET:/admin/auth/permissions`，staleTime 10 分钟，真源 = roles 表 JSONB），返回 `{user, permissions}` 供页面与 ProLayout 使用；接口报 bizCode 10004 → 403 |
| `financeRbacLoader` | billing 3 子页 | 先跑 adminRbacLoader；再校验角色 ∈ {FINANCE, SUPER_ADMIN} 且 `menu:billing-packages` 为 true，否则 403 |
| `superAdminLoader` | 角色权限页 / 模型厂商页 / 平台配置页 | 先跑 adminRbacLoader；再严格校验角色 === SUPER_ADMIN，否则 Toast + 403 |

公共要求：登录态初始化统一走 authStore 的 `ensureInitialized()`；所有跳转用路由 redirect，禁止 window.location。

### 5.3 ProLayoutWrapper 菜单按权限过滤

#### 5.3.1 按钮级权限组件 `<HasPerm>` 规范

| 项 | 规范 |
|----|------|
| 输入 | `code`（按钮级权限点，如 `audit:works-pass`）+ `children` + 可选 `fallback`（默认 null） |
| 数据来源 | 读取 `/admin` 路由 loaderData 中的 permissions，`permissions[code] === true` 才渲染 children，否则渲染 fallback |
| 用法示例 | `<HasPerm code="billing:manual-refund"><Button>人工退款</Button></HasPerm>` |
| 禁用写法 | ❌ `if (role === 'FINANCE') <Button>…</Button>`（角色硬编码改不了权限） |

**强制规则**：所有按钮级权限都用 HasPerm 包，禁止写死角色条件分支。

#### 5.3.2 路由级 + 按钮级权限「双保险」设计

即使前端绕过菜单过滤（有人懂 F12 改路由），也逃不过两层守卫：
1. **loader 层（路由级）**：进入页面前 adminRbacLoader 校验角色 → 不是对应角色 403（这层是服务端 loader，改前端代码没用）
2. **Mutation 层（后端层）**：每个写操作接口后端再校验一次 permissions，前端只是 UX 上隐藏按钮防误点。后端才是真权限，前端只是 UI 友好。

#### 5.3.3 权限变更实时生效方案

管理员在「角色权限矩阵」页改了某角色权限，其他已登录该角色管理员实时生效，不用退出重登：
- 保存权限 → WS 广播 `permissions_updated` 消息
- 收到消息 → TanStack Query `invalidateQueries(['GET:/admin/auth/permissions'])` → ProLayout 菜单 300ms 内重新渲染（新增菜单出现/已关菜单消失）

**ProLayoutWrapper 行为契约**（components/layout/ProLayoutWrapper.tsx）：

| 项 | 规范 |
|----|------|
| 布局形态 | ProLayout theme=dark / layout=side / siderWidth 240 / fixSiderbar + fixedHeader |
| 主题 | 白顶栏 + slate-900 深色侧边菜单（token 对齐 3.2 节） |
| 菜单过滤（核心） | `menuDataRender` 递归过滤：`permissions['menu:' + item.key] === false` 的菜单及其子项一律剔除；菜单配置来自 router/menu.ts，key 必须与 permissions 同名 |
| 右上角 | avatarProps：头像 + 昵称下拉（个人信息 / 修改密码 / 退出登录） |
| 底部 | menuFooterRender 固定版权行 |
| 内容区 | 渲染路由 `<Outlet />` |

## 七、性能优化：管理端 AntD 专属建议

### 7.1 AntD 按需加载（W1 必做，否则首屏 > 1MB）

vite.config.ts 两块配置：
- **按需插件**：@ant-design/vite-plugin-import 分别对 `antd` 与 `@ant-design/pro-components` 启用 es 目录组件级按需加载（AntD 5 CSS-in-JS 本身 Tree Shaking 已好，plugin 再加强 ProComponents）
- **手动分包**（manualChunks 4 个 vendor，长期缓存）：

| chunk | 包含 |
|-------|------|
| react-vendor | react / react-dom / react-router-dom |
| antd-vendor | antd / @ant-design/icons / pro-components / pro-layout |
| echarts-vendor | echarts / echarts-for-react |
| tanstack-vendor | @tanstack/react-query / react-virtual |

**验收标准**：`vite build` 后首屏核心包 `index-xxx.js` gzip < 300KB（AntD 比用户端重，放宽到 300KB）；antd-vendor chunk 单独 ~400KB gzip 长期缓存。

### 7.2 ProTable 大数据性能（审计日志 10 万行）

| 场景 | 优化方式 |
|------|---------|
| **10 万行列表滚动** | ProTable `scroll={{ y: 600, x: 2400 }}` + AntD 5 Table 内置 `virtual` 虚拟滚动（`options={{ virtual: true }}`）|
| **ProTable columns 复杂渲染** | 列 render 包 `React.memo`；自定义复杂单元格抽组件 `memo(())`；避免 render 里新生成 object/array 引用导致重渲染 |
| **筛选区条件多（10+ 筛选项）** | `defaultCollapsed` 默认折叠 3 行以上筛选项；按钮「更多筛选」展开；筛选条件变更 debounce 300ms |
| **Excel 导出 1 万行** | 后端生成 OSS 预签名 URL 返回给前端点链接，**不允许前端用 xlsx 库浏览器内导出**（吃内存卡死） |
| **ProTable 列设置持久化** | 见 9.3 节 `useProTablePersist` Hook：localStorage 存显示列 / 列顺序 / 列宽 |

### 7.3 ECharts Dashboard 性能

- **懒加载图表**：`<EchartReact />` 包 `IntersectionObserver`，不在可视区不初始化；每个图表独立 chunk
- **WS 实时曲线（GPU 使用率）**：WS 推送每 3s 一条数据，setOption 只改 series.data 增量，不重画整个图；最多保留 60 个数据点（3 分钟），超出 shift 旧数据
- **7 日趋势图数据量 < 100 条**：直接渲染无压力；月报 30 条 / 年报 365 条也 OK
- **Dispose**：Tab 切换关闭 Dashboard 时 `echartsInstance.dispose()` 释放 WebGL 上下文（不释放 6 个图占 ~500MB 内存）

### 7.4 其他管理端通用优化

#### 7.4.1 AntD Icons 按需加载（减小 ~50KB）

AntD Icons 默认全量引入包含 700+ 图标，管理端只用 80+ 个。做法：vite resolve.alias 将 `@ant-design/icons` 指向显式导入入口（ExplicitImports.js），实际用到的 80 个图标写在一个统一文件里显式导出。

#### 7.4.2 ProForm 复杂表单性能优化

角色权限矩阵 6 角色 × 40+ 权限点 = 240 个 Checkbox，默认渲染卡顿：
- `preserve={false}`：收起的分组不保留 DOM
- Checkbox onChange debounce 100ms（240 个 setState 合并一次）
- 分组折叠时 `unmountOnExit`，展开才渲染内部 CheckboxGroup

#### 7.4.3 Drawer / Modal DOM 销毁规范

- `destroyOnClose` = true：所有包含表单（审核备注、用户调整积分 Dialog、导出条件 Dialog）都开启，避免上次输入残留这次打开还在
- 体积大的「作品预览 Drawer」（含视频播放器）关闭后 `instance.dispose()` ECharts / 视频元素，避免 WebGL 上下文和 video 元素泄漏

| 场景 | 优化方式 |
|------|---------|
| **图片懒加载（用户头像/作品封面）** | `<Image preview={false} lazy />`（AntD Image 内置懒加载）|
| **Drawer / Modal 销毁方式** | `destroyOnClose` 对复杂表单/预览页开启，避免旧状态残留 |
| **Form 表单项 > 20 个** | 用 ProForm 分组 + `defaultCollapsed` 折叠高级项；字段 `preserve={false}` |
| **批量操作请求（>100 条批量通过）** | 切分 20 条一批串行调接口 + 进度条 Toast 显示；避免一次 100 条 30s 超时 |

### 8.3 审核操作三要素：按钮 + 快捷键 + 批量操作

#### 8.3.1 单条审核按钮规范

| 按钮 | 变体 | 位置 | 行为 | 必填项 |
|-----|------|-----|------|-------|
| **🟢 通过** | `type="primary" ghost`（绿色 Primary 色）| ProTable 操作列 / Drawer 底部 A 位置 | 点击 → `mutation POST /admin/works/{id}/audit`，请求体 `{action:"APPROVE"}` → Toast「已通过」→ 该行从 PENDING Tab 移除 → 自动加载下一条待审核 | 无（备注选填） |
| **🔴 驳回** | `type="primary" danger` | ProTable 操作列 / Drawer 底部 R 位置 | 点击 → 打开**驳回备注 Dialog**（必须填至少 10 字才能点确定）→ `mutation POST /admin/works/{id}/audit`，请求体 `{action:"REJECT",note}` → Toast「已驳回，作者端可见」 | **备注必填，至少 10 字** |
| **👁️ 预览** | `type="link"` | ProTable 操作列左侧 | Drawer 打开 60% 宽详情 + 视频预览 | 无 |

#### 8.3.2 ⌨️ 全局快捷键规范（审核员效率核心）

> Drawer 打开时（全局 `document.addEventListener('keydown')`，useEffect 绑定，Drawer 关闭时移除）

| 快捷键 | 功能 | 触发上下文 | 实现要点 |
|-------|-----|---------|---------|
| **`A`（单字母，无修饰键）** | 通过当前作品 | Drawer 打开时（焦点不在 input 内） | 弹出确认 Toast 1.5s「将通过《xxx》」→ 1.5s 内再按 A 确认（防误触）；或直接 mutation（可配置开关） |
| **`R`（单字母）** | 驳回当前作品 → 光标聚焦驳回备注框 | Drawer 打开时 | 打开驳回备注 Dialog，光标直接聚焦 Textarea，Textarea value = 上次模板（记忆） |
| **`Esc`** | 关闭 Drawer | Drawer 打开时 | AntD Drawer 默认支持，但要确认无未保存备注 → 二次确认 |
| **`←`（左方向键）** | 上一个作品 | Drawer 打开时 | 如果在第 1 条 → Toast「已是第一条」 |
| **`→`（右方向键）** | 下一个作品 | Drawer 打开时 | 如果在最后一条 → Toast「全部审核完啦 🎉」 |
| **`Shift + A`** | **批量通过**选中项（ProTable 勾选） | 全局（任何时候） | 选中项 >0 时 → Dialog「确定批量通过 N={checked.length} 条作品？」→ 确定 → 串行每条调 mutation + 进度条 |
| **`Shift + R`** | **批量驳回**选中项 | 全局 | Dialog「批量驳回原因：[Textarea 统一备注]」→ 备注必填 → 串行每条带上统一备注 |
| **`Ctrl/Cmd + S`** | 保存当前审核备注草稿 | Drawer 驳回备注编辑中 | localStorage 暂存（刷新不丢） |

**快捷键冲突防护**：
- 焦点在 `input` / `textarea` / `select` 内时，A / R 单字母快捷键禁用（否则打字触发审核）
- `e.preventDefault()` 前检查 `document.activeElement.tagName !== 'INPUT' && 'TEXTAREA'`

#### 8.3.3 批量操作规范（选中 > 0 项显示工具栏）

| 批量操作 | 实现要点 |
|---------|---------|
| **批量通过** | mutation 串行切分 20 条一批（避免 100 条一次超时）；顶部进度条「批量通过中 40/120」+ 成功计数 Toast；失败的单独在列表行标红「批量失败：原因xxx」 |
| **批量驳回** | 打开 Dialog 备注统一填，每条驳回 mutation 带上同一个 remark；支持「附件上传审核意见截图」可选 |
| **批量导出** | 调后端导出接口（不要前端拼 Excel）→ 返回 OSS 预签名 Excel URL → Toast「导出成功，点击下载」 |
| **批量标记重点关注** | 给作品打 `review:high_priority` 标签，后面审核优先排队 |

## 九、🔴 ProTable 统一规范（筛选/分页/导出/列设置持久化）

> 管理端 **90% 的页面 = ProTable**，所有表格必须按此统一规范。用户/作品/订单/日志等所有 ProTable，看起来、操作起来完全一样。

### 9.1 BaseProTable 标准封装（每一个表格必须基于它）

所有页面基于 `BaseProTable.tsx` 通用封装，不重复写配置。入参与统一行为：

| 项 | 规范 |
|----|------|
| 入参 | `tableKey`（必传，列设置持久化 key = `admin:cols:${tableKey}`）/ columns / request / rowKey / batchActions（批量工具栏，见第八章）/ showExport（默认 true） |
| 分页 | 默认 20 条/页；可选 10/20/50/100；显示总条数 + 快速跳转 |
| Toolbar 右侧 | 选中 >0 显示批量操作；导出按钮；列设置按钮（持久化）；密度切换（紧凑/默认/宽松，持久化）；全屏（快捷键 F） |
| 搜索区 | labelWidth auto；默认折叠，展开文案「展开更多筛选/收起」（细则见 9.5.1） |
| options | density / fullScreen / reload 开启；setting 关闭（用自己的持久化列设置，不用 AntD 默认） |
| 滚动 | `scroll.x = max-content`；URL 同步见 9.4 |
| 列定义 | 经 useProTablePersist 合并持久化配置后传给 ProTable |

### 9.2 标准列定义（12 个常用列通用约定）

| 列类型 | dataIndex | 宽度 | 对齐 | 渲染规范 |
|-------|-----------|-----|-----|---------|
| 行号/多选 | rowSelection | 48px | 中 | `rowSelection={{ preserveSelectedRowKeys: true, selectedRowKeys: ... }}` |
| 缩略图 | cover_url / avatar_url | 80px | 中 | `<Image width={48} height={48} preview={false} lazy />` |
| ID / UUID | user_id / order_id | 200px | 左 | 等宽字体 font-mono；hover 显示完整 ID + 复制按钮 |
| 名称 / 标题 | name / title | 220px | 左 | 主文字 14px bold + 副标题（12px slate-400，如邮箱/手机号）；超长度 ... + Tooltip |
| 时间列 | created_at / submitted_at | 170px | 左 | `YYYY-MM-DD HH:mm:ss`；hover 显示相对时间「2 小时前」 |
| 状态列 | status / review_status | 100px | 中 | `<Tag color={colorMap[status]}>{textMap[status]}</Tag>` |
| 数值列 | amount / points_cost / count | 110px | 右 | 数字 `font-mono text-right`；积分金橙色 / 消耗红色；千分位 `1,234` |
| 合规检测列 | compliance_flags | 160px | 中 | 多个 Badge 组合（✓绿/✗红/⚠️黄），超过 5 个折叠成「+N」 |

| IP 地址 | operator_ip | 140px | 左 | font-mono；hover 显示归属地「北京市 电信」 |
| 操作列 | — | 200px 固定 | 中（右侧） | 操作按钮组：`<a>预览</a><Divider type="vertical" /><a>通过</a>...`；超过 3 个用 Dropdown 收起 |

### 9.3 useProTablePersist：列设置持久化 Hook（核心）

hooks/useProTablePersist.ts 行为契约：

| 项 | 规范 |
|----|------|
| 存储 | localStorage key = `admin:table-cols:${tableKey}`，存 4 项：显示列 visibleKeys / 列顺序 order / 列宽 widths / 密度 density |
| 恢复 | 页面加载从 localStorage 恢复；无存储时默认全列显示、默认顺序、密度 middle |
| 自动持久化 | 任何变更即时写入 localStorage，刷新/后退完整还原 |
| 列合并规则 | 按 order 排序；开发新加的列不在 order 里时追加到末尾；不在 visibleKeys 的列 hideInTable；列宽优先取 widths |
| 工具栏 UI | 「列设置」按钮（Modal 720 宽，可调显示/顺序/宽度）+「恢复默认」按钮（重置后 Toast 提示） |
| 返回 | persistedColumns（最终列）/ setColumnsStore / columnSettingRender / density |

### 9.4 URL 同步：筛选 / 分页 / 排序 放 SearchParams

每个 ProTable 配合 useSearchParams，刷新/分享链接都还原：
- **从 URL 恢复**：page（默认 1）/ page_size（默认 20）/ keyword / status / sort
- **写回 URL**：分页或筛选变更时 setSearchParams 更新对应键，保持其余参数不动

### 9.5 统一导出：后端生成 OSS 预签名（前端不拼 Excel）

#### 9.5.1 ProTable 搜索区统一规范

搜索区筛选项严格按以下规范：
- **默认显示 1 行**：keyword 搜索框 + status 下拉 + 时间范围（created_at），超过 3 项的「高级筛选」默认折叠
- **筛选项标签**：左 label 右 Input，labelWidth = 80px（紧凑）；中文字段 label 不超过 6 字
- **重置按钮行为**：重置所有筛选项为 undefined，page 重置到 1，不要保留 keyword
- **搜索 Enter 触发**：搜索框 keydown Enter 立即触发查询，不用点按钮
- **时间范围 quick select**：常用快捷按钮「今天 / 昨日 / 近7天 / 近30天 / 本月」一键选中

#### 9.5.2 ProTable 行展开详情规范

需要查看一条记录的完整详情（不打开 Drawer）用 ProTable `expandable`：
- **展开图标位置**：第一列（多选框后 / ID 前）
- **展开内容高度 ≤ 400px**：超过用滚动条；包含创建人信息 / 操作历史时间线 / 备注全文
- **展开同时加载完整详情**：expandedRowRender 内部 `useQuery` 调 GET /admin/users/{id} 完整接口（列表只返回 20 列，完整信息展开时才拉）
- **支持嵌套展开？** 禁止（层级太多乱），多层信息一律 Drawer

#### 9.5.3 AntD 5 Table 虚拟滚动实测参数

ProTable 开启虚拟滚动（审计日志 ≥ 50,000 行）：`options.virtual = true`；`scroll = { x: 2400（超屏宽横滚）, y: 600（可视区约 15 行）}`；`rowHeight = 40`（与 Token 行高一致）。
验收标准：10 万行渲染 FPS ≥ 55；首屏 500ms 内出数据；上下滚无白边无抖动。

**ExportExcelButton 行为契约**（pro-table-ex/ExportExcelButton.tsx）：点击 → loading → 调后端导出接口（POST /admin/export/{module}，带当前筛选项 table_key + filters）→ 后端生成 Excel 存 OSS 返回 download_url + filename → Toast 成功 → 触发浏览器下载；失败 Toast 报错，finally 关 loading。

**禁止项**：
- ❌ 禁止用 `xlsx` 库前端拼 JSON→Excel（1000 行 20 列 = 2 万单元格浏览器卡死 10s）
- ❌ 禁止导出超过 10 万行（前端弹窗提示「请缩小日期范围」，后端分页截断）
