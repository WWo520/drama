# 短剧平台分期路标（6 周 3 阶段 · AI 辅助开发 · 排期唯一真源）

> 🔒 **排期唯一真源声明**：本文档是全项目排期/路标/里程碑/晋级门槛的**唯一真源**。
> 01~07 各文档中不再包含任何排期内容，仅保留指向本文的引用行。
> 所有排期争议以本文为准；修改排期必须且只能修改本文。

> **开发模式**：AI 辅助单兵开发（1 人 + AI Agent 批量生成代码），非传统 4 人团队。
> 优势：脚手架/CRUD/业务逻辑/测试可批量产出，无沟通等待/无文档 review 扯皮。
> **节奏**：每阶段末 E2E 全链路走查 + 验收签字。

## 二、M0 阶段（第 1~2 周）🔴 MVP 最小闭环

### 2.1 M0 成功指标（缺一不准进入 M1）

| 编号 | 指标 | M0 门槛 |
|------|------|---------|
| 1 | 技术成功率 | ≥75% |
| 2 | 付费转化率 | ≥5% |
| 3 | 首片时长中位数 | ≤25分钟 |

> 指标口径固定：技术成功率 = 观察窗内完成 Step1 的真实用户项目中，最终成功下载 MP4 的去重项目数 ÷ 完成 Step1 的去重项目数；付费转化率 = 初始赠送积分已耗尽的去重用户中，累计成功支付金额 ≥ ¥10 的去重用户数 ÷ 该类用户数；首片时长中位数 = 去重项目从首次进入 `SCRIPT_SPLITTING` 到首次成功下载成片的分钟数中位数。M0 观察窗为内测开放起至 M0 评审冻结时；排除员工、自动化测试和被标记为测试的数据；项目状态与下载事件从业务库及埋点事件交叉核验。公式与样本量门槛以 03 G.1 为准，指标事件字段以 03 D8 为准。

### 2.3 M0 阶段结束 Checkpoint

- [ ] Step1~4 全流程走通不阻塞，10 内测用户无阻塞 Bug
- [ ] 积分扣费链路闭环（充值→批量生成→冻结→扣减→余额正确）
- [ ] WS 断网重连，消息不丢不重复
- [ ] 首片时长中位数 ≤ 25 分钟
- [ ] 生成任务故障闭环：重复投递、重复/乱序模型回调、Worker 宕机、Redis 重启、超过最大重试均可恢复或进入 `FAILED_DEAD`，积分只结算一次
- [ ] 支付回调：验签、金额/商户校验、重复回调幂等和订单—积分流水原子性均通过沙箱验证
- [ ] OpenAPI 契约冻结并通过生成校验；枚举由 02 - 数据库设计.md A 章生成，禁止手写
- [ ] 部署脚本 1 条命令，删库 100% 恢复
- [ ] TypeScript strict：全仓库 `any` ≤ 10 处

### 2.5 弹性约定（总周期不延，风险前置）

> 6 周总周期**不因单点风险延后**；通过内部检查点提前暴露风险、用相邻排期吸收：
> - **W1 D5 收口检查**：脚手架 + M0 核心表迁移 + AI Adapter 全通 → 通过则 W2 正常推进；不通过 → W2 前 2 天集中补（吞 W2 排期，不延总周数）
> - **W2 D4 检查**：E2E-01~04 全过 → 按计划收尾；不过 → W2 D5 让位修 Bug，支付宝沙箱联调顺延至 W3 前 2 天
> - **视频质量风险前置**：E2E-06（生成视频全链路）必须在 W2 D3 前首次跑通，不等到 W2 末才发现；模型降级链（主模型 429/失败自动切备选）随 Adapter 一并实现

## 五、里程碑晋级门槛铁律

**M0→M1 晋级（第 2 周周末开评审会），以下条件全部 AND 满足**：

1. G1 技术成功率 ≥ 75%，按 2.1 的观察窗和项目去重口径计算
2. G2 付费转化率 ≥ 5%，且样本中的成功付费用户 ≥ 3 人
3. G3 首片时长**中位数** ≤ 25 分钟
4. E2E 核心用例 100% 全通过，且包含支付重复回调、模型回调重复/乱序、Worker 宕机恢复、Redis 重启恢复四类故障用例
5. DDL 迁移可在空库与从 M0 基线库重复执行；OpenAPI 契约与由 02 - 数据库设计.md A 章生成的枚举校验通过
6. 代码 Bug：P0 级 0 个未修 / P1 级 ≤ 5 个未修
7. 计费账本抽样核对：每个成功任务恰有一次扣费、每个不可交付终态恰有一次全额解冻；支付订单、积分账户和积分流水无差异

处理规则：全部满足 → 下周启动 M1；任一项不满足 → 冻结 M1 新功能集中修；连续不通过 → 复盘降级方案（缩功能或延周期）。

**M1→M2 晋级（第 4 周周末开评审会），以下条件全部 AND 满足**：

1. M1 团队版付费率 ≥ 10%，且 50 个团队用户中至少 5 个已成功升级付费套餐；自由画布周活使用率 ≥ 20%。
2. M1 纳入评审的质量指标达成率 ≥ 80%；计算公式继续使用 03 G.1，指标范围、观察窗、样本清洗及事件来源沿用 2.1 的固定口径。
3. M1 新增和受影响的 E2E 用例 100% 执行，整体通过率 ≥ 95%；至少包含协作邀请与越权拦截、团队账户并发冻结、团队余额不足不入队且不扣个人、成功/失败及重复乱序回调单次结算、OWNER/ADMIN 成员报表与退出成员历史对账、版本回滚、跨集复用免扣、月卡首购与到期、画布保存恢复及多轨导出。
4. M1 新增迁移可在空库与 M0 基线库重复执行；实际扩表范围与外键拓扑顺序已先更新到 02 - 数据库设计.md D.2，且 OpenAPI 契约及该文档 A 章枚举生成校验通过。
5. 协作、画布和会员相关 P0 缺陷为 0，所有 P1 缺陷均有明确修复计划且未阻断对应 E2E；计费账本抽样核对无差异。
6. 画布保存、任务重试和月卡续期的故障恢复用例通过；执行中的任务不因前端断连或页面刷新被写为失败。

处理规则：全部满足 → 下周启动 M2；任一项不满足 → 冻结 M2 新功能集中修复；连续不通过 → 复盘并裁剪 M2 范围或调整上线窗口。

> 指标量化口径（一次通过率/付费转化率/首片时长中位数的精确定义）见 03 功能文档 G 章。
