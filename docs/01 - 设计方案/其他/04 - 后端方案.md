> 基于《系统架构》《数据模型》《接口文档》
> 技术栈：Go ｜ PostgreSQL + Redis + S3 ｜ 平台内置任务调度

```
server/
├── cmd/
│   └── server/main.go            # 入口：装配、启动
├── internal/
│   ├── config/                   # 配置加载
│   ├── middleware/               # 鉴权、日志、限流、恢复、CORS
│   ├── router/                   # 路由注册（user / admin 分组）
│   ├── domain/                   # 领域定义与核心逻辑（服务层）
│   │   ├── auth/                 # 认证/用户
│   │   ├── space/                # 空间/成员/权限
│   │   ├── creation/             # 创作（项目/单元/资产/分镜/视频）
│   │   ├── work/                 # 作品/发布
│   │   ├── taskorder/            # 任务与接单
│   │   ├── content/              # 发现/互动
│   │   ├── notify/               # 消息
│   │   ├── billing/              # 商业化/计费
│   │   ├── admin/                # 管理端
│   │   └── help/                 # 教学/帮助
│   ├── engine/                   # 核心引擎
│   │   ├── task/                 # 任务调度引擎
│   │   ├── model/                # 模型接入与调度治理层
│   │   ├── asset/                # 资源/资产服务（S3）
│   │   ├── audit/                # 审核服务
│   │   ├── billing/              # 计费计量服务
│   │   └── notify/               # 消息服务
│   ├── repository/               # 数据访问（PG / Redis）
│   ├── model/                    # 领域模型/表结构
│   ├── dto/                      # 请求/响应对象
│   └── pkg/                      # 通用工具（errors、response、id、jwt、s3）

```

> 分层原则：router（HTTP 层）→ domain（业务服务）→ repository（数据访问）。核心引擎作为共享服务被各 domain 调用。

## 三、关键设计

### 3.1 认证与鉴权
- JWT 无状态认证，payload 含 `user_id`、`space_id`（当前空间）、平台角色（admin）。
- 三层校验中间件：
  1. 用户认证（必须登录）。
  2. 平台权限（管理端 RBAC）。
  3. 空间权限（操作空间资源时校验成员角色：owner/admin 可写/管理，member 可写，viewer 只读）。
- 密码 bcrypt 哈希；密钥加密存储（KMS/环境变量）。

### 3.2 任务调度引擎（重点）
统一异步任务模型，覆盖分镜/图/视频等所有生成类任务。

**核心组件**
| 组件 | 职责 |
|------|------|
| 提交器 | 校验参数/额度 → 落库（queued）→ 写 Redis 队列 → 返回 task_id |
| 调度器（worker） | 从队列取任务 → 加分布式锁 → 分配并发额度 → 执行 |
| 模型适配层 | 按 `model_key` 路由到对应厂商实现，统一接口（Submit/Cancel/Progress） |
| 状态机 | queued → running → succeeded / failed / cancelled / expired |
| 结果回写 | 成功后结果写 S3，回填 `result`，更新状态 |
| 重试/超时 | 失败/超时/断连按策略重试（配置最大次数），超限 failed；超时 expired 并回收 |

**并发与额度**
- 每用户/每空间/全局三级并发上限，基于 Redis 计数（`running:tasks` ZSet）+ 分布式锁控制。
- 任务队列用 Redis **ZSet**（score = 优先级 + 时间戳），可**按优先级弹出**；超过并发则留在队列，按 `priority` 调度。

**进度上报**
- 执行过程中周期回写 `progress`（0-100），前端轮询 `GET /tasks/{id}` 查看。

**计费联动**
- 提交时校验并冻结/扣费额度，写 `billing_records`；失败按策略退还。

### 3.3 模型接入与调度治理层（轻量消费侧）
平台侧为**消费侧模型治理**，与"模型路由中心"（用户自建服务器、对外提供标准接口的服务）本质不同：本层只负责平台自身如何接入并调用模型，可直连厂商，也可把"模型路由中心"作为其中一路接入源（其标准接口作为 provider 之一）。

- **统一接口**：`type ModelProvider interface { Generate(ctx, req) (*TaskHandle, error); Cancel(ctx, handle); }`，覆盖四类能力 `llm / t2i / i2i / t2v / i2v / audio`。
- **厂商 → 模型 → Key 三级管理**：由 `model_providers` / `models` / `model_keys` 表驱动；厂商区分用名称（name），对外引用统一 `model_key` = 模型 `name`。
- **每 Key 并发限制**：每个 API Key 配置独立速率/并发限制（RPM / QPS），记录可用并发。
- **路由与负载均衡**：按「模型能力 + 当前可用 Key 并发 + 优先级」选择调用哪个 Key；多 Key 分摊额度与并发。
- **429 / 失败处理**：命中限流自动切换其他可用 Key 或退避重试；连续失败标记该 Key 不可用并告警。
- **接口限流限速**：后端每个接口按用户 / IP 配置限流（Redis 计数），防止滥用（独立于模型 Key 的厂商限流）。
- **Key 安全**：Key 加密存储、脱敏展示、支持轮换与停用。

### 3.4 空间权限
- 空间是资源归属与权限边界；几乎所有创作资源（项目/资产/任务/作品）带 `space_id`。
- 成员角色：owner（全部）/ admin（管理）/ member（可编辑生成）/ viewer（只读）。
- 访问资源前统一权限校验服务，避免遗漏。

### 3.5 审核服务
- 作品发布提交 → 状态 `pending` → 管理端审核 approve/reject → 驱动状态流转，写 `publish_records`。
- 驳回后用户可修改重新提交。

### 3.6 计费与订单
- 下单带幂等键，防重复购买/发放。
- 支付回调验签、幂等处理。
- 套餐订阅 / 积分包支付成功后，事务内发放积分并写 `point_transactions`，保证不重复发放。
- 生成任务计费：模型/分辨率/时长映射**积分成本**，成功后计量扣减积分（事务内校验积分 ≥ 扣减额 + 写流水）。
- 商业化无钱包/余额概念，统一走积分。

### 3.7 文件与存储（S3）
- 前端通过预签名 URL 直传/直读，后端下发签名、回执关联业务对象。
- 中间文件按生命周期策略清理。

### 3.8 智能体引擎（Agent）
创作智能化由**智能体引擎**承载，覆盖剧本 → 分镜 → 分镜图 → 视频 → 配音的完整链路。
- **双层结构**：决策层（agent）负责拆解任务、调用子 Agent；子 Agent 专注单一能力（OutlineScript / Storyboard / TTS 等）。
- **技能体系**：技能以 Markdown 文件（含 frontmatter：name/description）定义，提供 `activate_skill` / `read_skill_file` 工具，决策层按需激活技能；含预设**画面风格库**与**导演叙事技能库**。
- **记忆系统**：会话级 + 摘要级记忆，可检索（RAG/向量化）当前项目上下文，支持前端一键清除。
- **思考等级**：决策层推理深度可配置（关闭 / 轻 / 深 / 极限），影响质量与耗时。
- **流式结构化输出**：AI 输出以 XML 标签包裹结构化内容（剧本 / 导演计划 / 分镜表 / 分镜项），流式返回并实时回填画布。
- **异步一致性**：图片/视频/配音等生成统一走任务调度引擎，前端轮询回填，避免阻塞对话。

### 3.9 衍生资产与图片编辑引擎
- **衍生资产生成**：基于顶层资产（`parent_id` 自关联）+ 参考资产图，支持单条与**批量**生成（换装 / 多形态 / 虚背 / 多角度），统一走任务调度引擎与 `generated_images` 状态回填。
- **图片编辑**：基于原图 + 参考资产图（图生图 / 多图参考）编辑分镜图，结果回写 `generated_images`。

### 3.10 视频合成引擎
- **多轨时间线**：视频 / 图片 / 音频三轨合成，画布尺寸随项目比例自适应（16:9 / 1:1 / 9:16），保存 / 读取时间线、导出工程文件。
- **TTS 配音**：复用角色声音资产，调用音频生成模型为台词生成配音音轨并合入时间线。

### 3.11 审计日志
- 关键操作（登录、支付、审核、权限变更、空间治理、积分调整）写 `audit_logs`。

## 五、部署与运行

- 单体服务 + 无状态水平扩展；调度器可独立进程/实例运行。
- 环境：本地开发、测试、生产三套配置（env 驱动）。
- 启动：配置加载 → 连接 DB/Redis → 执行迁移 → 注册路由 → 启动调度器 worker → 监听端口。

## 六、开发计划建议（阶段）

1. **基建**：工程骨架、配置、JWT、统一响应、数据库迁移、日志。
2. **用户与空间**：注册登录、默认空间、成员邀请、角色权限、RBAC。
3. **创作域（核心）**：项目/单元、资产管理（含衍生资产）、分镜（含批量/图片编辑）、视频制作（含多轨合成）、任务调度引擎、模型适配层。
4. **智能体引擎**：双层 Agent、技能体系（画风库/导演叙事技能库）、记忆系统、思考等级、流式结构化输出、TTS 配音。
5. **作品与发布**：作品管理、回收站、发布审核流。
6. **商业化**：套餐（多版本、月付/年付）、积分包、订阅、订单、支付回调、积分计费计量。
7. **内容与互动**：信息流、评论、点赞、收藏、关注、举报。
8. **任务与接单**：任务发布、意向登记。
9. **消息/帮助/教学**。
10. **管理端各模块**：概览、用户、内容、计费、算力任务、智能体模型、配置、运营。
11. **收尾**：审计、监控、性能、上线。

## 七、风险与注意事项

- **任务调度稳定性**：队列消费的幂等、断连重试、并发额度控制是重点，需充分测试。
- **计费准确性**：积分扣减与任务计费的一致性，需事务与对账保证。
- **空间权限覆盖**：所有资源操作都要过权限校验，防止越权。
- **模型厂商适配**：多厂商 API 差异大，需统一抽象并做好错误/超时处理。
- **智能体一致性**：生成类结果异步回填，需保证与对话流式输出的状态一致性；记忆/技能需做版本与权限管理。
- **衍生资产与图片编辑**：批量生成、参考图多图合成结果需可追溯（`generated_images.ref_asset_ids`），失败可重试。
