## 一、适用范围与原则

1.1 适用范围：短剧 Agent 4 步流水线所有生成类任务 + 空间配额扩容 + 套餐订阅 + 积分包购买
1.2 无钱包无充值余额铁律：商业化只围绕「积分」 + 「套餐订阅权益」；用户无法把现金提现（合规要求，避免被判定为支付平台/二清风险）
1.3 积分有效期：⏳ M0 上线前 1~2 周运营/财务/安全/DevOps 确认后再填（财务确认：建议 1 年有效期，到期前 30/7/3 天三次站内信通知）
1.4 积分来源优先级：套餐赠送积分先消耗 → 首购加赠积分 → 付费积分包（减少过期浪费）
1.5 跨集复用不重复扣费铁律（对齐 03 附录 A.3）：asset_usage_logs 唯一索引豁免 = 透明化，前端预览弹窗必须返回「本次应扣 X / 豁免 Y / 实际扣 X-Y」三个数字
1.6 积分过期清零策略：⏳ M0 上线前 1~2 周运营/财务/安全/DevOps 确认后再填（过期前提醒机制、过期后是否可申诉恢复、清零批次处理时间窗口）
1.7 积分转账/赠送规则：⏳ M0 上线前 1~2 周运营/财务/安全/DevOps 确认后再填（是否允许用户间积分互转、是否收取手续费、最小/最大转账额度、反洗钱监控阈值）

### 3.3 跨集复用豁免计算

```
实际扣费 = max(0, (基础分×模型倍率×分辨率×时长×风格) - 已豁免数×单份对应积分)
已豁免数 = COUNT(asset_usage_logs WHERE asset_id=? AND project_id=? AND episode_id<?) -- 此项目之前的剧集已经用过的次数
```

3.3.1 豁免范围边界：⏳ M0 上线前 1~2 周运营/财务/安全/DevOps 确认后再填（同一 asset 跨项目是否豁免？不，仅限同 project_id 内。同一集内多次使用是否豁免？第一次扣，第二次及以后免？）
3.3.2 豁免凭证展示：用户侧「扣费明细」页面可点击展开查看每条 asset 的豁免历史（哪一集用过、对应豁免积分），做到完全透明可审计
3.3.3 豁免滥用防护：⏳ M0 上线前 1~2 周运营/财务/安全/DevOps 确认后再填（检测同一 asset 在 N 个项目出现、疑似批量复制刷豁免？反作弊规则触发人工审核）

### 3.4 Preview API 一致性

所有生成类按钮提交前必须先调 `POST /points/preview` 返回以上计算结果+豁免明细，前端弹窗透明展示用户点「确认扣费」才提交。绝不允许点击就直接扣了不知道扣多少。

3.4.1 Preview 与 Actual 一致性校验：实际扣费与 Preview 预估差值 > ⏳ M0 上线前 1~2 周运营/财务/安全/DevOps 确认后再填 时触发告警（防止配置更新不同步导致用户投诉），差值 > ⏳ 待填 时自动回滚扣费并补偿积分
3.4.2 Preview 缓存策略：⏳ M0 上线前 1~2 周运营/财务/安全/DevOps 确认后再填（相同参数 Preview 结果缓存 N 秒？缓存失效条件：系数配置变更、用户积分余额变化、豁免历史变化）
3.4.3 积分不足拦截：Preview 阶段检测到当前可用积分 < 预计扣费时，前端直接拦截并跳转充值页，不允许提交任务导致失败

## 四、支付宝当面付（扫码付）接入（伪代码见 04 后端方案 H 章，本处只列检查点）

### 4.1 商户号配置

平台支付宝商户号（⏳ M0 上线前 1~2 周运营/财务/安全/DevOps 确认后再填：运维配置环境变量，严禁硬编码或写入代码仓库）

4.1.1 多环境商户号隔离：开发/测试/预发/生产各用一套独立的支付宝沙箱或正式商户号，禁止测试环境调用生产商户号
4.1.2 密钥轮换机制：⏳ M0 上线前 1~2 周运营/财务/安全/DevOps 确认后再填（RSA 私钥有效期、轮换周期、轮换期间双公钥并行验签过渡期、旧密钥彻底作废流程）
4.1.3 权限最小化：应用公钥证书授权范围仅开通「当面付.trade.precreate」「trade.query」「trade.refund」「bill.downloadurl.query」4 个接口，多余权限全部关闭

### 4.2 扫码下单流程

创建订单（幂等键防重复）→ 调用 alipay.trade.precreate → 返回二维码 URL → 前端显示 QRCode + 倒计时 15 分钟过期

4.2.1 幂等键生成规则：user_id + sku_id + client_uuid（前端生成 UUID）+ 时间窗口（5 分钟粒度），三重哈希后存入 Redis SETNX，5 分钟内重复请求直接返回上次未支付订单
4.2.2 二维码过期处理：⏳ M0 上线前 1~2 周运营/财务/安全/DevOps 确认后再填（过期后订单自动关闭并释放幂等键、用户刷新页面自动生成新订单、未支付订单保留 N 天后归档）
4.2.3 前端轮询 + WebSocket 双通道：支付状态查询前端每 3 秒轮询 `GET /orders/{id}/status`，同时后端收到回调后 WS 推送 PAYMENT_SUCCESS，任一通道收到成功即跳转
4.2.4 异常订单清理定时任务：⏳ M0 上线前 1~2 周运营/财务/安全/DevOps 确认后再填（每 10 分钟扫描创建超过 30 分钟仍 pending 的订单，主动调 alipay.trade.query 确认真实状态，防回调丢失导致漏发积分）

### 4.3 支付回调 7 步验签铁律

必须 100% 按 04 后端方案 H.4 步序做：
① RSA2 公钥验签 → ② 校验 app_id = 平台商户号 → ③ 校验 out_trade_no 存在 + 金额 total_amount=订单金额（防钓鱼改金额）→ ④ nonce 24 小时去重防重放 → ⑤ 幂等：订单状态 pending 才转 paid，重复回调直接返回 success 不重复发积分 → ⑥ DB 事务：订单状态=paid + 积分发放（首购加赠）+ 写 point_transactions → ⑦ WS 推送 POINTS_CHANGED + 跳转成功页 → ⑧ RETURN "success" 字符串（必须小写无空格，否则支付宝会一直重试导致积分重复发放问题）

4.3.1 回调通知 URL 安全：⏳ M0 上线前 1~2 周运营/财务/安全/DevOps 确认后再填（仅支付宝官方 IP 段可访问回调接口、WAF 白名单、回调接口 HTTPS 强制、禁止 GET 方法只允许 POST）
4.3.2 回调异常兜底：⏳ M0 上线前 1~2 周运营/财务/安全/DevOps 确认后再填（事务第⑥步任何失败写 dead_letter_queue，运维后台可手动重试/补偿；每小时对账脚本扫描「支付宝成功但平台 pending」订单，自动补发积分并告警）
4.3.3 积分发放原子性：订单状态 + point_transactions + 用户积分余额必须在同一个数据库事务里提交，任何一步失败全部回滚，严禁分步骤非事务写入
4.3.4 回调日志留存：⏳ M0 上线前 1~2 周运营/财务/安全/DevOps 确认后再填（回调原始请求体、验签结果、各步骤执行耗时、事务结果全部写入 audit_payment_callback_log，保留 ≥ 10 年，税务查账必备）

### 4.4 退款流程（⏳ 财务确认规则）

## 八、异常场景与应急方案（⏳ 上线前运维+财务确认）

### 8.2 积分批量错发/少发

8.2.1 检测触发：⏳ M0 上线前 1~2 周运营/财务/安全/DevOps 确认后再填（point_transactions 同比昨日增幅 > 300% / 用户投诉密集反馈积分不对 / 对账脚本差额 > 1%）
8.2.2 应急隔离：⏳ M0 上线前 1~2 周运营/财务/安全/DevOps 确认后再填（立即关闭充值入口开关 / 暂停 point_transactions 写入 / 新订单进入待确认队列 / 同时紧急排查根因）
8.2.3 修正与补偿：⏳ M0 上线前 1~2 周运营/财务/安全/DevOps 确认后再填（多发积分：用户剩余积分够扣直接扣回，不够扣记录负数分期待后续充值抵扣，CEO 审批后可豁免；少发积分：批量补发 + 每人额外补偿 ⏳ 待填 积分歉意奖励；所有修正记录写入 point_adjustments 并附审批单号）

### 8.3 数据库扣费事务大规模失败

8.3.1 场景：⏳ M0 上线前 1~2 周运营/财务/安全/DevOps 确认后再填（DB 主从延迟 > 10s / 唯一键冲突激增 / 死锁检测告警 > 5次/min / 磁盘满导致事务无法提交）
8.3.2 降级预案：⏳ M0 上线前 1~2 周运营/财务/安全/DevOps 确认后再填（生成任务入口暂时关闭、Preview API 返回「系统繁忙」、已有任务冻结状态不变不扣费、DB failover 切换到从库）
8.3.3 事后一致性修复：⏳ M0 上线前 1~2 周运营/财务/安全/DevOps 确认后再填（DB 恢复后跑一致性脚本：asset_usage_logs 扣费记录 vs point_transactions vs 任务表状态，三方不一致生成差异报告 → 财务审批 → 批量修复脚本执行 → 二次校验全绿）

## 附录 C：财务 KPI 看板指标定义（待接入 BI）

### C.1 日维度指标

- 当日充值金额（元）/ 当日充值笔数 / 客单价
- 当日消耗积分（按任务类型分布）/ 当日消耗积分折算金额
- 当日退款笔数 / 退款率 / 退款金额
- 当日开票申请数 / 已开票数 / 待开票积压数
- Gross Margin（毛利率）= （消耗积分折算金额 - 模型供应商成本 - 云资源成本）/ 消耗积分折算金额

### C.2 周/月维度指标

- MRR（月度经常性收入）= 当月套餐订阅收入 + 积分包月均收入（滚动 3 月平均）
- NRR（净收入留存率）= 上月付费用户本月付费总额 / 上月付费总额
- CAC（获客成本）/ LTV（用户生命周期价值）/ LTV:CAC 健康度 ≥ 3:1
- 积分消耗 ARPU（每付费用户平均扣积分）/ 积分充值 ARPU
- 过期未使用积分占比 = 当月清零过期积分 / 当月总发放积分
- 对账差异率 = 月度对账差额绝对值 / 月度交易总额 × 100%（目标 < 0.05%）
