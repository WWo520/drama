### E.2 短剧Agent 4步流水线详细状态机图 + 叙事单元头部5件套 + 重新规划双Tab

#### E.2.1 四步总状态机（Episode级）

|---|---|---|---|

### E.3 任务调度引擎：三级并发+优先级队列+失败重试+计费联动+WebSocket推送+轮询兜底

#### E.3.1 三级并发控制（Redis 计数 + Lua 原子增减）

| 层级 | 默认上限 | 规则 |
|---|---|---|
| 全局并发 | 100 | 达上限则新任务返回 202 排队 |
| 空间级并发 | Basic=5 / Pro=20 / Enterprise=50 | 按空间套餐配置查询 |
| 用户级并发 | 2（套餐可提高到4~8） | 三级同时满足才弹出执行 |

任务完成回调时三个计数同时 DECR（Lua 脚本保证原子性）。调度器实现细节（ZSET 优先级队列/锁续租/指数退避/死信）见 01 B.3.1 与 04 后端方案 D 章。

#### E.3.2 优先级队列（自写调度器，ZSET score＝优先级×1e9＋时间戳）

| 优先级档 | 包含任务类型 | 消费能力建议 |
|--------|-------------|---------|
| 高 | VIDEO_SEGMENT_GEN（视频生成用户等最久） | Worker×4 并发 |
| 中 | IMAGE_GEN（资产生成分镜图）/ FINAL_VIDEO_COMPOSE | Worker×2 并发 |
| 低 | SCRIPT_SPLIT / STORYBOARD_PLAN / VIDEO_GROUP_CONCAT | Worker×1 并发 |

全局并发不足时优先消费高优先级队列（饿死保护：每 10 个高优先级轮 1 个低优先级）。

#### E.3.3 失败重试（指数退避+死信DEAD）

最多重试 3 次，间隔 1s/2s/4s 指数退避；可重试错误＝500/502/503/429/网络超时/模型服务不可用；不重试＝400 参数错/401 鉴权/积分不足。第 3 次仍失败：generation_tasks.status=DEAD，retry_logs 写入失败原因；扣费类任务自动 UNFREEZE 冻结积分回 current_balance；前端通知「生成失败（已自动重试3次），点击手动重试/联系客服」；管理端死信队列可手动重试/标记成功/放弃。

#### E.3.4 计费联动（强事务保证＝冻结→单条扣/解冻）

批量生成提交四步：

1. **预览**：POST /points/preview 计算 total_cost＝Σ单条单价、exempt_count＝跨集复用豁免数、actual_cost＝两者之差，校验余额后返回预览弹窗数据；
2. **冻结入队**：用户确认后 POST /assets/batch-generate {asset_ids, idempotency_key}，同一事务内：幂等 key 去重（重复提交直接返回旧结果）→行锁更新双余额（current−=actual、frozen+=actual）→写 FROZEN 流水（带 balance_after）→为每条 asset 建 generation_task（PENDING）→按优先级入队→返 task_uuids[]；
3. **单条回调**：成功→frozen−=cost、写 SPENT 流水、更新 asset.image_url；失败且无更多重试→frozen−=cost、current+=cost、写 UNFREEZE 流水；
4. **兑底**：定时任务每 5min 扫描 RUNNING 且 updated_at 超阈值的任务→自动标 FAIL→触发重试或 DEAD→退积分（防 Worker 崩溃无回调）。

事务实现细节见 04 后端方案 H 章；字段真源见 02 generation_tasks 三字段（request_id/frozen_points/thawed_points）。

#### E.3.5 WebSocket推送+轮询兜底

前端连接 `/ws/tasks?token={jwt}`。推送消息字段：type=TASK_PROGRESS、task_uuid、task_type、status（QUEUED/RUNNING/PROGRESS/SUCCESS/FAILED/DEAD）、progress_pct（0~100，部分任务支持）、message、result、points_cost、balance_after、timestamp。

兑底策略：WS onclose→自动降级 GET /tasks/{uuid} 轮询，间隔 2s（0~1min）→5s（1~5min）→10s（>5min）；超时 15min 任务自动标失败；WS 恢复后自动补拉离线未读消息（Redis List 缓存 1h）。消息协议完整定义见 05 接口文档 WS 章节。

### E.5 作品发布审核流：未发布→待审核→已发布/驳回+驳回意见+复审

状态机（works.status 枚举）：

| 状态 | 转移条件 |
|---|---|
| UNPUBLISHED（默认，仅空间内可见） | 用户点【发布作品】填表单（标题/简介/分类/标签）→ PENDING_REVIEW |
| PENDING_REVIEW（待审核，进管理端审核队列） | 审核员通过→PUBLISHED；驳回→REJECTED |
| PUBLISHED（已发布，发现流可播放） | 强制下架可回 UNPUBLISHED |
| REJECTED（存 reject_reason/reject_by/reject_at） | 用户按驳回意见修改后重新提审→PENDING_REVIEW（复审＝新审核记录，保留历史审核链） |

| id | work_id | reviewer_id | action(PASS/REJECT) | reason（驳回必填≥10字，通过可选） | snapshots(JSON存审核时作品的标题/简介/视频Hash) | reviewed_at |
|----|---------|-------------|---------------------|----------------------------------|----------------------------------------------|-------------|

前端显示：
- 作品卡片右上角状态徽章：🔵待审核 / ✅已发布 / ❌已驳回

- 审核历史Tab（作品详情）：按时间倒序展示所有审核记录（审核员匿名显示"平台审核员"不展示真实身份）

**自动合规前置（用户提交时先自动跑）**：提交发布后异步调第三方内容安全：①视频抽帧（每 10 秒 1 帧+关键帧）涉黄/涉暴/涉政评分；②标题+简介+标签文本敏感词检测；③封面图检测。任一项≥高危 80 分→自动驳回（原因：「系统自动检测到违规内容，请修改后重试」）；中危 40~79→标 PENDING_REVIEW 并标记高风险优先分配审核员；低危<40→正常排队。

### E.7 任务与接单：纯信息登记 + 客服线下撮合

**模块定位铁律（M2上线前团队必须全员签字）**：平台做的是"短剧创作工具"不是"短剧外包众包平台"，任务与接单模块**仅限信息发布与意向登记**，**坚决不碰以下红线**：
- ❌ 不做用户间在线IM聊天功能
- ❌ 不做电子合同在线签署/存证
- ❌ 不做资金托管/担保交易/在线付款给接单方
- ❌ 不做平台抽佣/分成/中介费
- ❌ 不为双方履约结果做担保/背书

**完整流程（7步纯信息）**：

1. 需求方填发布表单：标题/描述（富文本+附件）/所需能力 Tag 多选（剧本/分镜/剪辑/配音/后期）/参考作品链接（可链本平台作品）/期望周期/预算范围（可选区间）/联系方式/截止日期；
2. 提交→状态＝草稿→发布者点【确认发布】→发布中→任务广场公开可见；
3. 承接方浏览广场：分类 Tab/能力筛选/预算区间/截止排序→搜索→进任务详情；
4. 承接方点【我要接单】填意向登记表：自我介绍≤500字/擅长领域多选/3 条作品集外链/本人联系方式→提交→意向已登记；
5. 发布方个人中心「我发布的任务」→查看收到的意向列表（含承接方昵称/简介/联系方式/登记时间）→**自行电话/微信联系承接方（平台不介入）**；
6. 承接方个人中心「我登记的意向」→每条意向+任务标题+状态（已查看/未查看）；联系方式在登记意向后双方才互相可见（保护隐私）；
7. 客服线下撮合（可选增值）：发布金额≥5000 元可申请【客服撮合】→客服人工匹配认证接单方→线下建群协助沟通→**不参与合同/资金/担保**→撮合完成退群；M2 先免费体验，V2 可考虑撮合服务费。

**违规处理**：用户举报/平台巡检发现→任务内容违法违规→立即下架+警告/封号；若产生纠纷双方自行协商/走法律途径→平台仅在双方授权+公检法调查配合时提供登记信息（免责条款必须点同意才允许使用本模块）。

### H.2 违规升级流程（scope争议4级裁定机制）

四级裁定机制：

1. **1级（当场）**：先查 H.1 对应 T1~T10 铁律，能套进去直接驳回，不用讨论；
2. **2级（当天）**：套不进去→按 09 号 A2 节 ROI 打分（用户价值1~5 × 实现成本反向1~5，乘积满分25）：≥15分→进当前 Sprint 尾插队；9~14分→下个 Sprint；<9分→打回 Backlog Icebox（永不做除非有新证据）；
3. **3级（2天内）**：双方对打分有争议→产品负责人+技术负责人双签评审会，两人各打一次分取平均，≥12 分做，否则进 Icebox；
4. **4级（每周五下午 Scope 仲裁会·最高）**：双签还不服（罕见）→全团队匿名投票，≥2/3 支持→破例加进当前里程碑（必须同时从当前 Sprint 砍掉相等工时的低 ROI 功能，工时守恒不延期）；<2/3→永久打回 Icebox，3 个月内不得再提同一需求。

**工时守恒铁律**：任何破例通过的新需求，必须从当前 Sprint Backlog 砍掉总工时≥新需求工时的其他已规划功能（产品选砍什么），Sprint 总工时不增、交付日期不变，避免「加个需求就延1周」的无限膨胀死循环。

#### A.6 重新规划双 Tab 弹窗交互详细规格（对齐 M1 需求）
