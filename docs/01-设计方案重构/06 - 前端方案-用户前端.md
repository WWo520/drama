## 〇、一眼看懂：技术栈与整体架构

| 层 | 选型 | 一句话说明 |
|----|------|-----------|
| 应用形态 | Vite 5 SPA（`apps/web-user`） | 纯静态部署 CDN，不上 SSR |
| 框架/语言 | React 18.3 + TypeScript 5.5 strict | 函数组件 + Hooks，禁 Class |
| 路由 | React Router v6.26（createBrowserRouter） | loader 守卫做鉴权/进度拦截/数据预取 |
| 远程数据 | TanStack Query v5（唯一真源） | QueryKey 严格对齐 05 接口路径 |
| 本地状态 | Zustand 4.5（6 Store，总字段 ≤ 60） | 只存交互态，禁存远程数据 |
| HTTP | Axios + 拦截器 | 401 自动 refresh 重放 1 次 |
| UI 体系 | 自建组件库（Radix UI 底座 + Tailwind Tokens） | 影视感深色优先，30+ 组件 |
| 画布 | @xyflow/react 12（React Flow） | 自由画布（M1 核心） |
| 工程 | pnpm Monorepo（web-user + web-admin + 5 个共享包） | api-client 由 OpenAPI 自动生成 |

**整体架构一句话**：Monorepo 里的用户端 SPA——路由层 loader 守门 → 页面只调 Hooks → Hooks 用 TanStack Query 拿数据（WS 实时推送优先、轮询降级）→ Zustand 只存交互态 → UI 全部出自自建组件库。

## 二、总体策略：用户端 Vite React + 自建UI组件库/Radix底座

### 2.1 用户前端应用定位

本方案专注于**用户端 Web 应用** `apps/web-user`，面向短剧创作者（C端/B端小团队）提供全流程短剧AI创作工作台。

| 维度 | 用户端 Web 说明 |
|------|---------------|
| 包名 | `apps/web-user` |
| 目标用户 | 短剧创作者（C端/B端小团队） |
| UI 体系 | 自建组件库（Radix UI 底座 + Tailwind CSS Tokens 封装） |
| 设计目标 | 美观大方、影视感、突出创作体验、动效克制高质 |
| 核心场景 | 登录注册 → 项目管理 → 四步工作台（剧本拆分/资产管理/分镜视频/成片导出）→ 支付充值 → 自由画布 |

### 2.2 与管理端的关系

- 用户端与管理端 `apps/web-admin` 同属 Monorepo pnpm workspace
- 共享工程规范（TS/ESLint/Prettier/Commitlint）、共享包（`@duanju/api-client` / `@duanju/utils` / `@duanju/ui-shared`）
- 登录态 Cookie 域共享，同一套 axios 拦截器配置
- **UI体系完全独立**：用户端自建Radix+Tailwind组件库，管理端使用Ant Design Pro

### 2.3 Monorepo 工程体系（用户端适用部分）

- **包管理器**：pnpm workspace（比 npm/yarn workspace 更快、更省磁盘、幽灵依赖防护）
- **工程规范四件套统一**：所有共享包全部引用根目录配置，禁止各自为政：
  - `tsconfig.base.json`：strict=true、noImplicitAny=强制、paths alias 统一
  - `.eslintrc.cjs`（根）+ `eslint-plugin-react-hooks` + `eslint-plugin-import` 顺序强约束
  - `.prettierrc`（根）：统一 2 空格 / 单引号 / 无分号 / 行宽 100
  - `commitlint + husky`：Conventional Commits，feat/fix/docs/chore 前缀强制，`git commit` 卡点
- **TypeScript 严格模式零容忍**：`any` 必须写 eslint-disable 注释 + 理由，`// @ts-ignore` 禁止出现在非第三方库代码里

### 2.4 为什么选 SPA（Vite）而不是 Next.js SSR

| 维度 | Vite + React SPA（本次选择） | Next.js SSR |
|------|----------------------------|-------------|
| **团队学习成本** | ✅ 团队已有 React + 路由 + 状态管理基础，无需学习 RSC/Server Actions | ❌ 要学 App Router 约定、RSC 和 Client 组件边界、Server Actions |
| **首屏 SEO 重要性** | ✅ 短剧创作平台首屏是用户登录后的工作台，搜索引擎爬虫不登录抓不到，SSR 收益为 0 | ❌ 多花 SSR 服务器运维成本，无实际 SEO 收益 |
| **部署复杂度** | ✅ 纯静态文件，丢 CDN（阿里云 OSS / 七牛 / Cloudflare）就完事，无 Node 服务器 | ❌ 需要常驻 Node 进程，运维要处理内存泄漏、PM2 进程守护、冷启动 |
| **开发体验** | ✅ Vite HMR 100ms 级热更新，修改立即生效 | ⚠️ Next.js App Router HMR 常触发整页刷新，RSC 调试慢 |
| **与后端 API 对接** | ✅ 直接 axios 调后端，BFF 层可后期加 nginx 反向代理实现 | ❌ 多一层 Route Handlers，多一次网络跳转增加延迟 |
| **未来可扩展性** | ✅ 如果哪天要做首页营销页 SEO，单独再加一个 Next.js 官网站即可 | — |

> **结论**：短剧创作平台是「登录后使用的生产力工具」，非「公开内容站点」，Vite SPA 是性价比最优解。

## 三、技术栈表：每库版本 + 选择理由

### 3.1 用户端核心技术栈

| 层 | 选型 & 版本 | 为什么选它 | 禁止替换为 |
|----|-----------|-----------|-----------|
| **核心框架** | React 18.3+（函数组件 + Hooks 强制，禁止 Class） | 生态最全、Hooks 封装业务逻辑最顺手 | Vue / Angular / Solid |
| **语言** | TypeScript 5.5+（strict=true） | 10 号 OpenAPI 文档生成 TS 类型，编译期防接口字段错用 | JavaScript / 宽松 TS |
| **构建工具** | Vite 5.4+ | 冷启动 < 500ms，HMR 毫秒级，构建用 Rollup 稳定 | Webpack / Turbopack |
| **路由** | React Router v6.26+（createBrowserRouter，禁止 BrowserRouter+Routes 手写嵌套） | 官方推荐的声明式路由配置，loader/action 守卫天然适合鉴权与数据预加载 | Next.js Router / React Router v5 |
| **远程数据 / 缓存** | TanStack Query v5.51+（原 React Query，NOT SWR） | QueryClient 缓存 + 失效策略 + 乐观更新 + DevTools 比 SWR 更强大；Query Key 数组命名对齐 SWR 字符串模式，平移零成本 | SWR / RTK Query / 裸 axios |
| **本地状态** | Zustand 4.5+（persist + devtools 中间件） | 比 Redux Toolkit 轻 5 倍代码量；AI 产品状态读写频繁响应要快；**禁止引入 Redux/MobX/Jotai** | Redux Toolkit / MobX / Recoil |
| **HTTP 客户端** | Axios 1.7+ | 请求/响应拦截器、超时、取消请求、错误处理比 fetch 现成好用 | 原生 fetch / ky |
| **UI 组件库（核心）** | 自建组件 + Tailwind CSS 3.4 + Radix UI 无样式底座 | 完全掌控设计风格，打造短剧产品独特影视感品牌识别，不被组件库"模板味"限制；Radix 提供无障碍底座 | shadcn/ui / Material UI |
| **表单** | react-hook-form 7.52+ + Zod 3.23+（zod schema 共享给前后端） | 受控/非受控表单性能双优；Zod 校验逻辑后端可复用，避免前后端校验规则不一致 | Formik / AntD Form（用户端） |
| **图标** | lucide-react 0.441+ | 统一图标风格，轻量，按需 Tree Shaking | react-icons / heroicons / 混搭多套图标库 |
| **自由画布（核心）** | @xyflow/react 12.3+（React Flow 新包名） | 行业标准无限画布库，支持自定义节点、事件系统完善、性能经过万人验证 | reactflow v11 旧包名 / 自研 Canvas |
| **虚拟滚动** | @tanstack/react-virtual 3.10+ | Step3 100+ 镜头卡片渲染性能保障 | react-window / react-virtualized |
| **Toast / 通知** | sonner 1.5+ | 轻量美观、支持 Promise Loading Toast 绑定 | react-hot-toast / AntD message（用户端） |

## 五、🔴 状态分层黄金公式（重点）

> **黄金公式**：`① 能放 React Router useSearchParams 的，不放 Zustand；② 能放 TanStack Query Cache 的，不放 Zustand；③ 剩下（操作频繁 UI 态/跨组件共享）才放 Zustand。`
>
> **铁律**：Zustand 单个 Store ≤ 10 字段，全部 Store 总字段 ≤ 60。超过了就要自查"这个能不能放回 URL / TanStack Query"。

### 5.1 四层状态分层详解

| 分层 | 存储位置 | 典型内容 | 示例 |
|------|---------|---------|------|
| **L1 持久 URL（最推荐）** | React Router `useSearchParams()` → `?xxx=yyy` | 分页(page/page_size)、排序(sort/order)、筛选(status/keyword)、当前Step、当前集、当前选中的资产id/镜头id、弹窗是否打开（分享链接可复用） | `/workspace/project/p-xxx?episodeId=e-xxx&step=2&selected_asset_ids=cv-aaa,cv-bbb` |
| **L2 TanStack Query Cache（次推荐）** | `queryClient.getQueryData(['GET:/api/v1/projects', {page:1}])` | 所有 GET 请求返回值（项目列表/资产详情/任务状态）→ TanStack Query 统一管 dedupe + 缓存 + 重验证 + 垃圾回收 | `useQuery({ queryKey: ['GET:/api/v1/projects', {page:1}], queryFn })` |
| **L3 页面内本地 state（第三推荐）** | React `useState`（组件内） | 临时 UI：输入框值、是否 hover、单个卡片展开/折叠、input focus | `const [scriptText, setScriptText] = useState('')` |
| **L4 Zustand 全局（最后选择！别什么都塞）** | Zustand store + persist (localStorage 仅存必要) | ①用户登录态（access_token + user info）②工作台四步共享：资产勾选集合/临时草稿③WebSocket连接状态④跨页面临时操作态（批量任务已选id跳转Step3还能看到）⑤充值弹窗/侧边栏折叠等纯UI态 | `useAuthStore(s => s.accessToken)` → 存 localStorage |

### 5.2 L1 为什么优先放 URL（useSearchParams 是真源）

✅ **好的做法（URL 是真源）**：访问 `/workspace/project/p-123?episodeId=e-456&step=2` —— 分享链接可直接进 Step2 看资产（需登录+权限）；浏览器后退回到 Step1；刷新页面 step 不变；误关标签恢复后状态全还原。

❌ **错误做法（存 Zustand `currentStep=2`）**：刷新重置回 Step1；分享链接朋友从 Step1 开始；后退退到 /projects；误关标签全丢。

> **扩展原则**：所有「希望分享链接能复现」的东西，一律塞 Search Params。Step、选中资产ID、镜头ID、打开的弹窗、筛选排序——全放 URL。参数多没关系，React Router 性能没问题。

### 5.3 SearchParams 命名约定（全项目统一，避免混用）

| 约定键名 | 类型 | 示例 | 用途 |
|---------|------|------|------|
| `step` | enum `1\|2\|3\|4` | `?step=2` | 当前工作台 Step |
| `projectId` | uuid | `?projectId=p-uuid4` | 兜底（路径里也有，但参数里写一份方便组件直接取） |
| `episode` | number | `?episode=1` | 当前集序号（M0单集写死=1，M1多集有用） |
| `narrativeUnitId` | uuid | `?narrativeUnitId=b-uuid4` | 当前高亮/展开的叙事单元 |
| `nodeId` | uuid | `/canvas/p-xxx?nodeId=nd-uuid4` | 自由画布当前选中节点 |
| `selected_asset_ids` | `逗号分隔uuid列表` | `?selected_asset_ids=cv-aaa,cv-bbb,sc-ccc` | Step2已勾选的资产id列表（用户勾选后，切页回来还在）≤20项同步URL |
| `modal` | string enum | `?modal=batch_assets_preview` / `?modal=alipay_qr&order_no=xxx` | 当前打开的弹窗名（分享/回退时可恢复） |
| `page` / `page_size` / `keyword` / `status` | — | 同 05 号接口 | 列表页用 |
| `redirect` | encodeURIComponent | `/login?redirect=%2Fworkspace%2Fproject%2Fp-xxx` | 登录成功后跳回原页 |

### 5.4 哪些东西严禁放 Zustand（放 L1/L2）

| 常被塞错的内容 | 应该放哪里 | 为什么 |
|--------------|-----------|-------|
| 项目列表 `/projects` 返回值 | TanStack Query: `useQuery(['GET:/api/v1/projects', {page:1}])` | 有分页/筛选，TanStack Query 自动 dedupe/cache/revalidate |
| 资产列表 Step2 角色/场景/道具 | TanStack Query: `useQuery(['GET:/api/v1/episodes/e-xxx/characters'])` | 重新生成后 `invalidateQueries` 自动刷新，不需要手动更新 Store |
| 积分余额 | `['GET:/api/v1/points/account']` 或 `['GET:/api/v1/auth/me'].data.points_account` | 余额变动会推 WS → 自动 setQueryData，双源不同步会出现"顶栏余额500但批量生成说不够"致命Bug |
| 任务状态 `/tasks/t-uuid` | `useQuery(['GET:/api/v1/tasks/t-uuid'])` + WS 到达时 setQueryData | 轮询降级 + 实时推送双通道 |
| 风格库列表 | `useQuery(['GET:/api/v1/styles/library'])` | 基本不变，staleTime=1h 完美 |
| 当前 step / 当前集 / 当前叙事单元 | URL SearchParams `useSearchParams()` | 分享/刷新/后退都还原，唯一真源 |

### 7.1 useAuthStore（auth.store.ts · 唯一 persist localStorage）

**职责**：所有页面先依赖它；persist 只存 accessToken + user（refreshToken 是后端 HttpOnly Cookie，前端不存）；清除条件：401 code=10003 / 登出成功 / 手动退出。

| 字段（State，8 个 ≤10） | 说明 |
|------------------------|------|
| accessToken / user | 登录后一次填入；持久化到 localStorage（key=`duanju-auth-store-v1`，结构不兼容升 v2） |
| isInitialized | 页面刚打开是否已尝试过 validate token |
| loginLoading / registerLoading | 按钮 Loading 态 |
| refreshTokenLock | 防并发 refresh 死循环 |

| Action | 行为 |
|--------|------|
| onLoginSuccess(res) | 登录后一次填 store（accessToken + user + isInitialized） |
| setAccessToken / setUser | refresh 成功只换 token；充值后余额变化更新 user |
| logout(reason) | 清 store + 跳 `/login?redirect=<当前页>`；token_expired 额外带 reason=expired |
| ensureInitialized() | 每个 loader 开头 await：已初始化直接返回；有 token 调 GET /auth/me 验有效；无效直接 logout 踢登录 |

### 7.2 useWorkspaceStore（workspace.store.ts · 不持久化，刷新从 URL 重建）

**职责**：只存「用户选择/编辑态」，不存远程数据；刷新清空，从 URL searchParams 重建；切项目调 resetForProject 清空。

| 字段（State） | 说明 |
|---------------|------|
| step2CheckedAssetIds | 三个子数组：characterVariantIds / sceneIds / propIds（勾选的资产 UUID） |
| step3BatchSelectedShotIds / step3BatchSelectedGroupIds | Step3 批量生成视频时选中的镜头/镜头块 |
| currentProjectSidebarCollapsed | 侧边栏折叠（纯 UI） |
| canvasNodeDrafts | 自由画布节点未保存草稿（拖拽位置/临时属性，按 nodeId 索引） |
| unsavedEntityDrafts | Step2 编辑未保存的角色名/prompt 草稿（按 entityKey 如 `characters.c-xxx` 索引） |

**Actions**：toggleStep2Asset / batchSetStep2Assets / clearStep2Selection（勾选三件套，去重合并）· toggleSidebar · saveCanvasNodeDraft · saveEntityDraft · resetForProject（切项目全清）。均为纯函数小操作，禁止在 Action 里写远程调用。

---

### 7.3 useWebSocketStore（websocket.store.ts · 单例连接管理）

**铁律**：全局只维护 1 个物理 WS 连接（不是每开一个 project 新开），靠订阅 SUBSCRIBE 消息逻辑隔离（task_uuid / room_id）；UI 组件不直接操作 WebSocket，只调 store actions。

**State（4 字段）**：connStatus（DISCONNECTED/CONNECTING/ONLINE/RECONNECTING/DEAD）· lastPingLatencyMs（>500ms 提示网络慢）· disconnectCount（断线次数告警）· topics（当前订阅主题集合）。

**Actions**：ensureConnected（登录成功后立刻调）· subscribe/unsubscribe（按 topic 订阅）· hardDisconnect（登出/断网时调）。

**WsClient 单例（lib/ws-client.ts）行为契约**：
- 连接 URL 带 accessToken；指数退避重连 1s→2s→4s→8s→最大 60s，重试 ≥20 次置 DEAD
- 重连成功：重订阅所有 topics + 启动心跳（30s PING 测 PONG 延迟）
- 消息分发：同 topic 连续消息 throttle 250ms 合并；**不把消息数据塞 Zustand**（消息量太大），直接调 handler → handler 内部 setQueryData

### 7.4 useUiStore（ui.store.ts · 小而全的全局 UI）

业务无关纯展示态，单文件 ≤ 50 行。State：theme（light/dark/system，唯一持久化字段）· rechargeModalOpen + rechargeHighlightPackageId（顶栏点充值、余额不足都弹同一个）· replanModalTab（Step3 双 Tab：SHOT_STYLE / NARRATIVE_ADJUST）· toastQueue（备用，sonner 足够时可不启用）。Actions：setTheme / openRechargeModal / closeRechargeModal / setReplanModalTab / pushToast / removeToast。

### 7.5 useTasksBatchStore（tasks-batch.store.ts · 跨页面批量汇总）

**场景**：Step2 批量生成 20 个资产 → 每个完成推 WS BATCH_SUMMARY → 这里更新数字 → 顶栏「批量进度」条显示；按 batchGroupId 划分，多个批量任务互不影响。

**State**：`batches: Record<batchGroupId, BatchSnapshot>`，快照字段：requestedTotal / succeeded / failed / progress(0~100) / startedAt / pointCostSoFar / lastUpdated。

**Actions**：createBatch（提交批量时初始化快照）· onBatchProgress（WS 消息增量更新，缺字段保留旧值，累计积分消耗）· clearBatch · getActiveBatchCount（progress<100 的数量，供 beforeunload 防误关用）。

## 八、🔴 TanStack Query 数据获取策略

### 8.1 QueryKey 命名约定（统一数组带参数 · 和 05 接口文档路径对齐）

> 原则：`['METHOD:/api/v1/xxx', { 参数对象 }]` 嵌套数组，DevTools 一眼看懂，搜索直接定位。
> 所有 Query Key 命名必须严格**对齐 05 - 接口文档.md 中的接口路径**，绝不自定义路径。

全项目唯一 Query Key 命名文件 `hooks/query-keys.ts` 导出 QK 对象，所有 Hook 一律从 QK 取，禁止在 useQuery 里直接写死字符串（后期改路径搜不到）：

| QK 键 | QueryKey |
|-------|----------|
| auth_me | `['GET:/api/v1/auth/me']` |
| projects_list(params) | `['GET:/api/v1/projects', params]` |
| projects_detail(id) / episodes_detail(id) | `['GET:/api/v1/projects', id]` / `['GET:/api/v1/episodes', id]` |
| assets_chars / scenes / props(episodeId) | `['GET:/api/v1/episodes', episodeId, 'characters' \| 'scenes' \| 'props']` |
| assets_summary(episodeId) | `['GET:/api/v1/assets/episodes', episodeId, 'summary']` |
| tasks_detail(taskId) | `['GET:/api/v1/tasks', taskId]` |
| styles_lib / points_account / recharge_options | `['GET:/api/v1/styles/library']` / `['GET:/api/v1/points/account']` / `['GET:/api/v1/payments/recharge-options']` |
| points_txn(params) | `['GET:/api/v1/points/transactions', params]` |

### 8.2 全局 queryFn 封装（统一解包 ApiResponse + BizError 抛出）

`lib/query-fn.ts` 提供全局 defaultQueryFn，行为契约：
1. 从 QueryKey 解出 `['METHOD:/api/v1/xxx', params?]`，拆 method 与 path
2. axios 发请求（GET 走 params，非 GET 走 body）
3. 解包 05 号约定的 ApiResponse `{code, message, data, request_id}`；code≠0 → throw `BizError(code, message, request_id)`，TanStack Query 走 isError 分支 + 全局错误 Toast
4. code=0 → 返回 data 字段（业务层拿到的永远是解包后的 data）

### 8.3 QueryClient 全局默认配置

| 配置项 | 值 | 理由 |
|--------|-----|------|
| staleTime | 30s | 30s 内认为数据新鲜不发请求 |
| gcTime | 5min | 未使用数据 5 分钟后回收 |
| retry | 网络错误重试 2 次（指数退避）；BizError 不重试 | 业务错误重试无意义 |
| refetchOnWindowFocus | false | 避免切回窗口所有接口同时刷爆服务器 |
| refetchOnReconnect | true | 断网恢复自动重拉 |
| queryFn | defaultQueryFn（8.2） | 全局统一解包 |
| mutations.onError | BizError → toast(message)；其他 → 「网络错误」 | 写操作失败默认 Toast |
| mutations.retry | false | 写操作不重试（避免重复扣费） |
| 全局错误订阅 | QueryCache error 事件：code=40003（积分不足）→ 自动弹充值引导弹窗 | 余额不足全局统一入口 |

### 8.4 失效（invalidateQueries + setQueryData）策略

> **核心原则**：写操作（POST/PATCH/DELETE）成功后，改了什么数据，就 invalidate 父级列表 + setQueryData 自己详情（乐观更新）。

| 写操作（接口） | 成功后执行的 TanStack Query 操作 |
|---------------|-------------------------------|
| POST `/projects` 创建项目 | ✅ `invalidateQueries({ queryKey: QK.projects_list })`（列表加新的）<br>✅ `setQueryData(QK.auth_me, prev => ({...prev, stats: ...}))`（创建数+1） |
| DELETE `/projects/p-xxx` | ✅ `invalidateQueries({ queryKey: QK.projects_list })` |
| PATCH `/characters/c-xxx` 修改角色 | ✅ `invalidateQueries({ queryKey: QK.assets_chars(eid) })`（刷新角色列表） |
| POST `/assets/batch-generate` 批量生成资产 | ❌ **不用 invalidate！** 任务异步，等 WS 推每个子任务 SUCCESS 时单独 invalidate 该资产卡片 key（不要等全批量完才刷新，体验差） |
| POST `/beats/{beat_id}/generate-videos` 批量生成视频（【全部生成视频】）/ `POST /shot-groups/{id}/generate-video` 单块重试 | ✅ WS TASK_COMPLETED 到达时<br>`setQueryData(QK.tasks_detail(id), taskData)`<br>+ `invalidateQueries({ queryKey: QK.assets_summary(eid) })` |
| POST `/orders` 创建订单（支付宝当面付）支付成功 | ✅ WS POINTS_BALANCE_CHANGED 到达时<br>`setQueryData(QK.points_account, newBalance)`<br>+ `invalidateQueries({ queryKey: QK.points_txn })`<br>+ `invalidateQueries({ queryKey: QK.auth_me })` |

### 8.5 乐观更新（Optimistic UI · 批量生成积分扣减防 UI 疑惑）

> 场景：点击批量生成后，后端返回 202 Accepted，但积分要等 WS 或轮询才扣。为避免“点完按钮余额没变”疑惑，乐观先扣 UI 显示。

`useBatchGenerateAssets` mutation 三阶段行为契约：
1. **onMutate（提交前先改 UI）**：cancelQueries 冻结 points_account → 快照旧值 → setQueryData：current_balance 减 netToFreeze、frozen_balance 加 netToFreeze；返回 rollback 函数
2. **onError（失败回滚）**：调 rollback 还原快照 + Toast「提交失败，积分已返还」
3. **onSuccess（成功拉真源）**：invalidateQueries points_account，从后端拉最新真源覆盖

## 十、🔴 鉴权守卫：React Router loader + Axios 拦截器双保险

### 10.1 Axios 请求/响应拦截器行为契约（关键）

实例配置：baseURL=VITE_API_BASE_URL（/api/v1 + nginx 反代）· timeout=30s · Content-Type=json。

**请求拦截**：
- 从 authStore.getState() 取 accessToken 注入 `Authorization: Bearer`（getState 不进 React 渲染循环）
- 注入 `X-Request-Id: req-<uuid>` 链路追踪，出问题给用户复制粘贴

**响应拦截（2xx）**：code=0 直接返回；code≠0 → DEV 环境 console.warn → 非 3001 错误 toast(message) → reject `BizError(code, message, request_id)`（3001 积分不足不 Toast，由全局订阅弹充值引导）。

**响应拦截（非 2xx）**：

| HTTP 状态 | 处理 |
|----------|------|
| 401 | token 过期：若 refreshTokenLock 已有 refresh 在进行 → 轮询等锁完成后用新 token 重放；否则置锁 → POST /auth/refresh（withCredentials 带 HttpOnly Cookie）→ 成功换新 token 重放原请求（最多 1 次，__retry 标记防死循环）→ refresh 也 401 → logout('token_expired')；finally 解锁 |
| 403 | Toast「无权限执行此操作（code=10004）」→ reject BizError(10004) |
| 429 | Toast「操作过于频繁」→ reject BizError(90001) |
| 5xx | Toast「服务器错误已通知技术团队」→ reject BizError(99999) |
| 无状态（超时/断网） | Toast「网络连接失败」 |

### 10.2 React Router v6 loader 守卫（重复 E3 节强调）

- **T2 所有受保护路由 loader** 必须调 `await authStore.ensureInitialized()` 校验 token，未登录 `redirect('/login?redirect=xxx')`
- **T3 workspace/canvas loader** 在此基础上追加 **owner 校验**（项目存在且 owner_id=当前 user_id，否则 `/projects` + Toast）
- **进度守卫**：用户手动改 URL `step=4` 但 step3 未完成 → 自动 redirect 到已完成的最大 step 并 Toast 警告
- **预取优化**：loader 内 `queryClient.fetchQuery(...)` 预拉数据，页面组件 useQuery 直接命中缓存 0 等待

## 十二、🔴 性能优化

### 12.1 路由级懒加载（首屏分包 < 200KB gzip）

分包策略：所有页面组件一律 `lazy()` 动态导入 + `Suspense` 骨架兑底；首屏只加载登录页 + 项目列表，Step3/Step4/自由画布（体积最大的 3 个）各自独立 chunk 首屏不加载；WorkspaceProjectPage 内部 Step 组件再二级 lazy。

**分包验收**：Vite build 后首屏核心包 < 200KB gzip；Step3 / Step4 / Canvas 分别独立 chunk 按需加载。

### 12.2 虚拟滚动（Step3 100+ 镜头卡片）

用 @tanstack/react-virtual 只渲染可视区：estimateSize 每张卡片预估 220px、overscan=5（上下缓冲 5 张防滚动白屏）；容器固定高度 overflow-auto，总高度用 virtualizer.getTotalSize() 撑开，可视项用 translateY 定位。验收：150 个镜头滚动 ≥55fps（Chrome Performance 录制）。

### 12.3 长任务防误关页面

WorkspaceLayout 全局挂载 beforeunload 监听：tasksBatchStore.getActiveBatchCount() > 0 时拦截关闭并提示「当前有进行中的批量生成任务，离开后任务后台继续但进度无法实时查看」；无活跃任务不拦截。

| 场景 | 优化方式 | 负责人 / 验收时机 |

## 附录A：UI设计体系与组件库规范（Radix UI + Tailwind Tokens 封装）

### A.1 设计原则：影视感深色优先 / 图像优先 / 动效克制

- **影视感深色优先**：默认深色主题（deep-space slate-950），品牌色深蓝紫渐变传达"专业AI创作工具"调性；亮色模式跟随系统但优先深色
- **图像优先**：创作工作台 Step2/3 核心页面以资产图、分镜图、视频缩略图为视觉主体，文字为辅助；卡片大图优先，小标签点缀
- **动效克制（参考 luxreal 整体调性）**：不做炫技大动画；动效只为"反馈"服务——按钮 hover、卡片选中高亮、进度条渐变、弹窗 300ms 渐入；不做全局旋转、夸张弹跳等
- **对比度 ≥ WCAG AA**：所有文字与背景对比度 ≥ 4.5:1（正文）/ 3:1（大标题），深色模式下主色 primary-500 #6366f1 与 slate-950 对比度 ≥ 5.2

### A.2 设计 Tokens 定义（tailwind.config.ts 对应字段）

> 所有颜色/字体/间距/圆角/阴影/动效必须通过 className 使用 Tokens，**禁止硬编码 style={{ color: '#6366f1' }}** 等。

#### A.2.1 颜色体系

定义在 `packages/tailwind-preset/src/colors.ts`，分六组：

| 组 | 定义 | 用途 |
|----|------|------|
| primary（主色深蓝紫） | 11 档色阶 50~950；主色 500=#6366f1，hover/active 用 600=#4f46e5；附 135° 渐变 gradient | 品牌色 |
| accent（辅助金橙） | 7 档色阶 50~700；主色 500=#f59e0b | 积分/徽章/推荐 |
| slate（中性灰阶） | 11 档 50~950；950=#020617 为深色模式默认背景 | 背景/文字/边框 |
| 功能色 | success=#10b981 / warning=#f59e0b / error=#ef4444 / info=#3b82f6，各带 light/dark/bg 变体 | 状态反馈 |
| points（积分金专属） | gold=#fbbf24 + glow 发光阴影（比 accent 更亮） | 余额徽章发光 |

**对比度验证（深色模式 slate-950 背景）**：
- 正文 slate-200 vs slate-950 = 14.3:1 ✅ AAA
- 主色 primary-400 vs slate-950 = 7.1:1 ✅ AAA
- 辅助色 accent-400 vs slate-950 = 9.2:1 ✅ AAA
- 功能色 success-light/warning-light/error-light vs slate-950 全部 ≥ 4.5:1 ✅ AA

#### A.2.2 字体层级

定义在 `packages/tailwind-preset/src/typography.ts`：

| 项 | 定义 |
|----|------|
| 无衬线字体栈 | 中文优先：PingFang SC → Microsoft YaHei → Noto Sans SC → Inter → system-ui |
| 等宽字体栈 | JetBrains Mono → Menlo → Monaco → Consolas（数字：积分/时长/UUID） |
| 标题 H1~H6 | 全部 700 字重；H1=36px / H2=30px / H3=24px / H4=20px / H5=18px / H6=16px；行高 1.2~1.4 |
| 正文 Body1~3 | 400 字重，行高 1.5；Body1=16px / Body2=14px / Body3=12px |
| Caption | 10px 辅助文字 |

**className 映射**：
- H1 = `text-h1 font-bold`，Body1 = `text-body1`，数字 = `font-mono text-body2`

#### A.2.3 间距栅格（4px 基准，所有间距必须用以下值，禁止自定义）

8 档：xs=4px（图标与文字）· sm=8px · md=12px（卡片内 padding）· lg=16px（组件间）· xl=24px（区块间）· 2xl=32px（大区块）· 3xl=48px（页面级）· 4xl=64px（超大页边距）。

**使用规则**：✅ `className="p-lg gap-md m-xl"`；❌ 禁止内联 style 硬编码像素值；❌ 禁止 Tailwind 默认数字间距（p-4/gap-3 等），一律用语义档位。

#### A.2.4 圆角阴影 Tokens

**圆角 6 档**：xs=2px（徽章/标签）· sm=4px（按钮/输入框）· md=8px（卡片/弹窗）· lg=12px（大卡片/图片）· xl=24px（顶栏胶囊/品牌徽章）· full=9999px（头像/圆形按钮）。

**阴影**：3 档常规（sm/md/lg，深色模式从背景升起）+ inner 内阴影（输入框 focus）+ 发光组 glow：primary（Button hover）/ accent / points（余额徽章高亮）。

**使用示例**：标准卡片 `rounded-lg shadow-md`；主按钮发光 `shadow-glow-primary`；积分徽章 `rounded-xl shadow-glow-points`。

#### A.2.5 动效规范（曲线 + 时长 + 交错）

> 动效只准用两条曲线，时长只用 4 个值。禁止随意写 `duration-500`、`ease-in-out` 默认值。

- **两条曲线**：out-cubic = cubic-bezier(0.33,1,0.68,1)（出场/展开，快入慢出）；in-out-cubic = cubic-bezier(0.65,0,0.35,1)（过场动画，慢-快-慢）
- **4 档时长**：fast=100ms（checkbox/按钮 press）· normal=150ms（hover/开关）· slow=200ms（卡片选中/Tab 切换）· xslow=300ms（Modal/Drawer/页面切换）
- **列表交错**：stagger=50ms（每一项依次晚 50ms）

通过 tailwind.config.ts 扩展 transitionTimingFunction / transitionDuration 落地。**使用示例**：✅ `transition-all duration-normal ease-out-cubic hover:scale-[1.02]`；❌ `duration-300 ease-in-out`。

#### A.2.6 响应式断点（桌面优先 · <md 禁用创作工作台）

桌面优先（用 max- 语义，注意 Tailwind 默认是移动优先）：2xl=<1535px · xl=<1279px · lg=<1023px · md=<767px（用户端断点核心）。

**强制规则**：
- `md:` 断点以下（<768px，平板/手机）访问 `/workspace/**` 或 `/canvas/**` → 全屏显示 Banner「请使用桌面浏览器（≥1024px）以获得最佳创作体验」，不渲染实际工作台
- 其他页面（项目列表/支付/设置）md 断点下自适应两栏变单栏

#### A.2.7 暗黑/亮色模式（CSS 变量切换）

实现机制：不用 Tailwind 的 dark:class 两套 className，而是把 Tokens 映射成 CSS 变量，`<html>` 的 data-theme 属性切换（:root=亮色，[data-theme="dark"]=深色，如 --color-bg / --color-fg / --color-primary）。

- ✅ 只用一套 className：`bg-bg text-fg border-border`，内部自动切 CSS 变量
- ❌ 禁止两套 className：`bg-white dark:bg-slate-950 text-slate-900 dark:text-slate-100`

**切换流程**：
1. Zustand `useUiStore.setTheme('dark' | 'light' | 'system')` → persist localStorage
2. App 根组件初始化：读 system prefers-color-scheme，`document.documentElement.setAttribute('data-theme', xxx)`
3. `window.matchMedia('(prefers-color-scheme: dark)')` listener 跟随系统

### A.4 强制使用规则（违反算 Bug 打回）

#### 规则 ① 组件源强制

- **禁止**直接 `import * as RadixDialog from '@radix-ui/react-dialog'` 或写原生 `<button>` / `<input>` / `<select>`
- **必须**从 `@duanju/ui` 包导入：`import { Button, Input, Modal } from '@duanju/ui'`
- 如果 `@duanju/ui` 缺少需要的变体 → 提 PR 给 UI 包扩展变体，**不允许**在用户端应用内直接 import Radix 绕开封装

#### 规则 ② Tokens 强制禁止硬编码

- **禁止** `style={{ color: '#6366f1', padding: '16px', borderRadius: '8px' }}`
- **禁止** `<div className="p-4 gap-3">`（Tailwind 默认数字间距）
- **必须**用 className 映射 Tokens：`className="text-primary-500 p-lg gap-md rounded-md shadow-md"`

#### 规则 ③ 动效强制

- **禁止** `className="transition-all duration-500"` 或随便写 duration/ease
- **必须**用 A.2.5 定义 4 档时长 2 条曲线：`className="transition-all duration-normal ease-out-cubic"`

### A.5 Monorepo packages/ui 目录 + Storybook 文档站

#### A.5.1 目录结构

见 4.3 节（packages/ui 五层结构：tokens / components 五类 / stories / utils）；包配置补充：`@duanju/ui` peerDependencies 为 react@^18 + tailwindcss@^3，构建用 Vite library mode 产出 dist/esm + dist/cjs 双格式；内部 utils 提供 cn()（clsx + tailwind-merge）合并 className。

#### A.5.2 Storybook 每个组件验收清单（设计 QA 逐个过视觉）

每个组件的 stories 文件必须覆盖全部变体×尺寸组合（以 Button 为例：5 变体×3 尺寸逐个 Story + Disabled + WithLoading 状态 Story），Meta 配 autodocs + variant/size 控件，设计 QA 逐个 Story 视觉验收。

**Storybook 配置**：
- 深色主题默认显示（和产品一致），顶部切换亮色预览
- 每个 Story 附带 Tokens 面板：显示当前组件用了哪些颜色/间距/圆角变量
- 加 `@storybook/addon-a11y` 无障碍插件：每个组件自动跑 axe 扫描，对比度不达标、缺失 aria-label 全部红波浪提示
- Chromatic（或自建快照）视觉回归测试：每次 PR 自动比对所有 Story 截图，像素差超过阈值阻断合并
