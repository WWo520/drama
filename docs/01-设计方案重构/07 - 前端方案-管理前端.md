### 1.2 数据真源铁律（强制执行，违反算 Bug）

① **枚举值** → 唯一真源 = 02 数据模型 B 章 Postgres CREATE TYPE
② **接口路径 / 请求 / 响应字段** → 唯一真源 = 05 接口文档 D/E 章 OpenAPI Schemas（用 openapi-generator 生成 TS 类型禁止手写字段）
③ **错误码 → Toast 文案映射** → 唯一真源 = 05 接口文档 C 章（axios 拦截器统一映射，禁止硬编码）
④ **菜单权限 + 按钮级权限** → 唯一真源 = 02 数据模型 `roles.permissions` JSONB 字段（前端 `adminRbacLoader` 校验，ProLayout `menuItemRender` 按权限过滤，无权限路由直接 403）
⑤ **分页(page/page_size) / 筛选(keyword/status) / 排序** → 放 URL SearchParams（不是 Zustand），保证刷新 / 分享 / 后退都还原
⑥ **用户列表 / 订单列表 / 作品列表 / 审计日志等远程数据** → TanStack Query Cache（不是 Zustand），严禁双源复制不一致
⑦ **交互状态 / 临时勾选 / 弹窗开关** → 最后才用 Zustand 或 useState
⑧ **ProTable 列设置（显示哪些列 / 列顺序 / 列宽）** → 持久化 localStorage，key=`admin:table-cols:用户列表`

### 2.3.2 路由前缀与 Nginx 反代说明

管理端路由统一 `/admin/**` 前缀，Nginx 配置：
```
location /admin/ {
  try_files $uri /admin/index.html;  # SPA history 模式 fallback

location /api/v1/admin/ {
  proxy_pass http://backend-service/admin-api/;  # /admin/** API 走后端管理端接口
}
```

用户端走 `/` 前缀，API 走 `/api/v1/`（不含 admin），两者完全隔离，Cookie 域 `domain=.duanju.com` 共享。

### 3.2 Ant Design 5 主题定制（品牌色对齐用户端）

### 3.2.1 暗色/亮色模式切换机制

管理端默认亮色模式（表格更清晰），但也支持暗色。切换入口：顶栏头像 →「主题切换」，使用 AntD ConfigProvider 的 `theme.algorithm` 动态切换：
- `theme.defaultAlgorithm` = 亮色
- `theme.darkAlgorithm` = 暗色
用户偏好写入 localStorage，key = `admin:theme-preference`。

## 四、🔴 管理端路由树（/admin/** 全部分页）

### 4.1 路由分类与权限层级

| 路由类别 | 前缀 | 最少角色要求 | loader 守卫规则 |
|---------|------|------------|----------------|
| **T1 登录页** | `/admin/login` | 无（公开） | publicLoader：已登录且有 admin 角色 → `/admin/overview` |

### 5.2 adminRbacLoader 守卫伪代码（核心 3 函数）

```ts
// apps/web-admin/src/router/loaders.ts
import { redirect } from 'react-router-dom'
import { useAuthStore } from '@/stores/auth.store'
import { queryClient } from '@/lib/query-client'
import { toast } from 'antd'

/**
 * T1 公开路由：/admin/login 已登录 admin → /admin/overview
 */
export async function publicLoader({ request }) {
  const { isInitialized, user, ensureInitialized } = useAuthStore.getState()
  if (!isInitialized) await ensureInitialized()
  // 有 admin 系列角色
  if (user && ['SUPER_ADMIN', 'ADMIN', 'FINANCE', 'AUDITOR'].includes(user.role)) {
    return redirect('/admin/overview')
  }
  return null
}

/**
 * ✅ T2 全局守卫 adminRbacLoader（所有 /admin/** 子路由先跑这个）
 * 步骤：①登录态 ②角色必须是 admin 系列 ③拉 permissions JSONB ④返回 {user, permissions}
 * 菜单过滤：ProLayoutWrapper 用 permissions 过滤 menuDataRender
 */
export async function adminRbacLoader({ request }) {
  const { isInitialized, user, ensureInitialized } = useAuthStore.getState()
  if (!isInitialized) await ensureInitialized()

  // 1. 未登录 → admin 登录页
  if (!user) {
    const path = new URL(request.url).pathname + new URL(request.url).search
    return redirect(`/admin/login?redirect=${encodeURIComponent(path)}`)
  }

  // 2. 角色校验：USER/GUEST 403
  if (!['SUPER_ADMIN', 'ADMIN', 'FINANCE', 'AUDITOR'].includes(user.role)) {
    toast.error('您没有管理后台权限，请联系超管开通')
    return redirect('/admin/403')
  }

  // 3. ✅ 预拉当前角色 permissions（TanStack Query 缓存，ProLayout 直接用）
  //    注意：permissions 真源 = roles 表 JSONB，从 GET /admin/auth/permissions 取
  try {
    const permissions = await queryClient.fetchQuery({
      queryKey: ['GET:/admin/auth/permissions', { role_code: user.role }],
      staleTime: 10 * 60_000, // 10 分钟内缓存，权限变更不频繁
    })
    return { user, permissions }
  } catch (err) {
    if (err.bizCode === 2003) {
      return redirect('/admin/403')
    }
    throw err
  }
}

/**
 * T4 财务专属页 loader（billing 3 子页）
 */
export async function financeRbacLoader({ request }) {
  const base = await adminRbacLoader({ request })
  if (base instanceof Response) return base
  const { user, permissions } = base
  if (user.role !== 'SUPER_ADMIN' && user.role !== 'FINANCE') {
    toast.error('该模块仅限财务或超管访问')
    return redirect('/admin/403')
  }
  // 按钮级再确认
  if (!permissions['menu:billing-packages']) {
    return redirect('/admin/403')
  }
  return { user, permissions }
}

/**
 * T5 超管专属 loader（角色权限页 / 模型厂商页 / 平台配置页）
 */
export async function superAdminLoader({ request }) {
  const base = await adminRbacLoader({ request })
  if (base instanceof Response) return base
  if (base.user.role !== 'SUPER_ADMIN') {
    toast.error('该页面仅限超级管理员访问')
    return redirect('/admin/403')
  }
  return base
}
```

### 5.3 ProLayoutWrapper 菜单按权限过滤

### 5.3.1 按钮级权限 HOC `<HasPerm>` 实现规范

```tsx
// apps/web-admin/src/components/rbac/HasPerm.tsx
import { useRouteLoaderData } from 'react-router-dom'

interface Props {
  code: string          // 按钮级权限点 code，如 'audit:works-pass'
  children: React.ReactNode
  fallback?: React.ReactNode   // 无权限时显示（默认 null = 直接不渲染）
}
/**
 * ✅ 用法：<HasPerm code="billing:manual-refund"><Button>人工退款</Button></HasPerm>
 * ❌ 禁用：if (role === 'FINANCE') <Button>...</Button>（角色硬编码改不了权限）
 */
export default function HasPerm({ code, children, fallback = null }: Props) {
  const loaderData = useRouteLoaderData('/admin') as { permissions?: Record<string, boolean> } | undefined
  const has = loaderData?.permissions?.[code] === true
  return has ? <>{children}</> : <>{fallback}</>
}
```
**强制规则**：所有按钮级权限都用 HasPerm 包，禁止写死角色条件分支。

### 5.3.2 路由级 + 按钮级权限「双保险」设计

即使前端绕过菜单过滤（有人懂 F12 改路由），也逃不过两层守卫：
1. **loader 层（路由级）**：进入页面前 adminRbacLoader 校验角色 → 不是对应角色 403（这层是服务端 loader，改前端代码没用）
2. **Mutation 层（后端层）**：每个写操作接口后端再校验一次 permissions，前端只是 UX 上隐藏按钮防误点。后端才是真权限，前端只是 UI 友好。

### 5.3.3 权限变更实时生效方案

管理员在「角色权限矩阵」页改了某角色权限，其他已登录该角色管理员实时生效，不用退出重登：
- 保存权限 → WS 广播 `permissions_updated` 消息
- 收到消息 → TanStack Query `invalidateQueries(['GET:/admin/auth/permissions'])` → ProLayout 菜单 300ms 内重新渲染（新增菜单出现/已关菜单消失）

```tsx
// apps/web-admin/src/components/layout/ProLayoutWrapper.tsx

import { menuConfig } from '@/router/menu'
import { antdThemeConfig } from '@/lib/ant-d-theme'

export default function ProLayoutWrapper() {
  const loaderData = useRouteLoaderData('/admin') as { permissions: Record<string, boolean> } | undefined
  const permissions = loaderData?.permissions ?? {}

  // ✅ 核心：menuItemRender 按 permissions 过滤（key = menu:xxx 格式）
  const menuDataRender = (menuList: any[]) => {
    return menuList
      .filter(item => permissions[`menu:${item.key}`] !== false) // 没权限 = 过滤掉
      .map(item => ({
        ...item,
        children: item.children
          ? item.children.filter(child => permissions[`menu:${child.key}`] !== false)
          : undefined,
      }))
  }

  return (
    <ProLayout
      theme="dark"
      layout="side"
      siderWidth={240}
      fixSiderbar
      fixedHeader
      // ✅ AntD 品牌色 配置

        header: { colorBgHeader: '#ffffff' },
```

### 7.2 ProTable 大数据性能（审计日志 10 万行）

| 场景 | 优化方式 |
|------|---------|
| **10 万行列表滚动** | ProTable `scroll={{ y: 600, x: 2400 }}` + AntD 5 Table 内置 `virtual` 虚拟滚动（`options={{ virtual: true }}`）|
| **ProTable columns 复杂渲染** | 列 render 包 `React.memo`；自定义复杂单元格抽组件 `memo(())`；避免 render 里新生成 object/array 引用导致重渲染 |
| **筛选区条件多（10+ 筛选项）** | `defaultCollapsed` 默认折叠 3 行以上筛选项；按钮「更多筛选」展开；筛选条件变更 debounce 300ms |
| **Excel 导出 1 万行** | 后端生成 OSS 预签名 URL 返回给前端点链接，**不允许前端用 xlsx 库浏览器内导出**（吃内存卡死） |
| **ProTable 列设置持久化** | 见第十一章 `useProTablePersist` Hook：localStorage 存显示列 / 列顺序 / 列宽 |

### 7.3 ECharts Dashboard 性能

- **懒加载图表**：`<EchartReact />` 包 `IntersectionObserver`，不在可视区不初始化；每个图表独立 chunk
- **WS 实时曲线（GPU 使用率）**：WS 推送每 3s 一条数据，setOption 只改 series.data 增量，不重画整个图；最多保留 60 个数据点（3 分钟），超出 shift 旧数据
- **7 日趋势图数据量 < 100 条**：直接渲染无压力；月报 30 条 / 年报 365 条也 OK
- **Dispose**：Tab 切换关闭 Dashboard 时 `echartsInstance.dispose()` 释放 WebGL 上下文（不释放 6 个图占 ~500MB 内存）

角色权限矩阵 6 角色 × 40+ 权限点 = 240 个 Checkbox，默认渲染卡顿：
- `preserve={false}`：收起的分组不保留 DOM

### 7.4.3 Drawer / Modal DOM 销毁规范

- `destroyOnClose` = true：所有包含表单（审核备注、用户调整积分 Dialog、导出条件 Dialog）都开启，避免上次输入残留这次打开还在

| **批量操作请求（>100 条批量通过）** | 切分 20 条一批串行调接口 + 进度条 Toast 显示；避免一次 100 条 30s 超时 |

### 9.1 ProTable 标准配置（每一个 ProTable 必须包含）

```tsx
// 抽象一个 BaseProTable.tsx，所有页面基于它，不用重复写这些配置
import { ProTable, type ProColumns } from '@ant-design/pro-components'
import { useProTablePersist } from '@/hooks/useProTablePersist'

interface BaseProTableProps<T> {
  tableKey: string                    // ✅ 必须：每个表格唯一 key，用于列设置持久化 localStorage key = `admin:cols:${tableKey}`
  columns: ProColumns<T>[]            // 列定义
  request: (params: any, sort: any, filter: any) => Promise<{ data: T[]; success: boolean; total?: number }>
  rowKey: string
  batchActions?: React.ReactNode      // 批量操作工具栏（见第十章）
  showExport?: boolean                // 是否显示导出按钮（默认 true）
}

export default function BaseProTable<T extends Record<string, any>>(props: BaseProTableProps<T>) {
  const { tableKey, columns, request, rowKey, batchActions, showExport = true } = props

  // ✅ 第十一章核心：列设置持久化 Hook
```

### 9.3 useProTablePersist：列设置持久化 Hook（核心）

```ts
// apps/web-admin/src/hooks/useProTablePersist.ts
import { useState, useEffect, useMemo } from 'react'
import type { ProColumns } from '@ant-design/pro-components'
import { Button, Modal, Space, message } from 'antd'
import { SettingOutlined, UndoOutlined } from '@ant-design/icons'

interface Options<T> {
  tableKey: string                              // 唯一 key
  defaultColumns: ProColumns<T>[]               // 默认列（开发时写的）
}

interface ColumnsStore {
  visibleKeys: string[]                         // 显示的列 dataIndex
  order: string[]                               // 列顺序（dataIndex 数组）
  widths: Record<string, number>                // 列宽
  density: 'default' | 'middle' | 'small'       // 密度
}

const STORAGE_PREFIX = 'admin:table-cols'

/**
 * ✅ 列设置持久化 Hook：localStorage 存 4 项
 * 列显示 / 列顺序 / 列宽 / 密度 —— 全部刷新还原，审核员按自己习惯配置不用每次调
 */
export function useProTablePersist<T extends Record<string, any>>(opts: Options<T>) {
  const { tableKey, defaultColumns } = opts
  const storageKey = `${STORAGE_PREFIX}:${tableKey}`

  // === 从 localStorage 恢复 ===
  const [store, setStore] = useState<ColumnsStore>(() => {
    try {
      const raw = localStorage.getItem(storageKey)
      if (raw) return JSON.parse(raw)
    } catch {}
    // 默认：所有列显示，顺序=默认列顺序
    return {
      visibleKeys: defaultColumns.map(c => c.dataIndex as string).filter(Boolean),
      order: defaultColumns.map(c => c.dataIndex as string).filter(Boolean),
      widths: {},
      density: 'middle' as const,
    }
  })

  // === 变更自动持久化 ===
  useEffect(() => {
    localStorage.setItem(storageKey, JSON.stringify(store))
  }, [store, storageKey])

  // === 合并 persisted + default 生成最终 columns ===
  const persistedColumns = useMemo<ProColumns<T>[]>(() => {
    // 1. 按 store.order 排序
    const ordered = [...store.order]
      .map(key => defaultColumns.find(c => c.dataIndex === key))
      .filter(Boolean) as ProColumns<T>[]
    // 2. 不在 order 里的新列（开发新加的列）追加到最后
    defaultColumns.forEach(c => {
      if (!ordered.find(x => x.dataIndex === c.dataIndex)) {
        ordered.push(c)
      }
    })
    // 3. 隐藏列 hideInTable
    return ordered.map(col => ({
      ...col,
      width: store.widths[col.dataIndex as string] ?? col.width,
      hideInTable: !store.visibleKeys.includes(col.dataIndex as string),
    }))
  }, [store, defaultColumns])

  // === 重置 ===
  const reset = () => {
    setStore({
      visibleKeys: defaultColumns.map(c => c.dataIndex as string).filter(Boolean),
      order: defaultColumns.map(c => c.dataIndex as string).filter(Boolean),
      widths: {},
      density: 'middle',
    })
    message.success('列设置已恢复默认')
  }

  // === 列设置按钮（Toolbar 渲染） ===
  const columnSettingRender = (
    <Space key="col-setting">
      <Button
        icon={<SettingOutlined />}
        onClick={() => {
          Modal.confirm({
            title: '列设置（显示 / 顺序 / 宽度）',
            icon: <SettingOutlined />,
            width: 720,
            content: <ColumnSettingModalContent
              defaultColumns={defaultColumns}
              store={store}
              setStore={setStore}
            />,
            okText: '保存',
            cancelText: '取消',
          })
        }}
      >
        列设置
      </Button>
      <Button icon={<UndoOutlined />} onClick={reset}>恢复默认</Button>
    </Space>
  )

  return { persistedColumns, setColumnsStore: setStore, columnSettingRender, density: store.density }
}
```
