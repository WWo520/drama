> 审查日期：2026-08-10
> 审查范围：`docs/01 - 设计方案/` 下 01~07 全部 7 份设计文档（合计约 17,200 行）

- P0 阻断级矛盾 7 类（照做必然开发出错）
- P1 重大缺失与文档结构问题 9 条

## 一、P0 阻断级矛盾

### 1. "真源铁律"本身自相矛盾

| 问题 | 冲突方 | 说明 |
|------|--------|------|
| 是否使用 PG ENUM | 04 A.1 明确"不使用 PostgreSQL ENUM，应用层 validator oneof 校验" vs 02/03/05/06/07 声明"枚举唯一真源 = 02 B 章 CREATE TYPE" | 04 同章又要求"从 CREATE TYPE 生成 Go const"，同一文档内部自相矛盾 |
| 密码哈希算法 | 01 = Argon2id；03 B1.1 = "bcrypt + 前端先 MD5"；04 A.2 = bcrypt cost=12 | **MD5 前置哈希是反安全实践，必须删除** |
| Refresh Token 存储 | 01 = AES-256-GCM 加密存 Redis（服务端状态化）；03/04/05 = HttpOnly Cookie 无状态 JWT | 两派均用 Redis 黑名单做撤销，差异在 token 值本身是否服务端存储（影响强制下线/串号检测能力），必须二选一 |

### 4. 错误码体系断裂

- 05 声称 5 位制（积分不足 = 40003、幂等冲突 = 80001），但 **05 内部就四位五位混用**：auth 域用 10002（access 过期）/ 10005（refresh 过期），billing 域才用 5 位；且 05 自己的 `ApiError.code` 定义 `minimum: 1001`（4 位）。
- 03/04/06/07 全部用 **4 位制**：
  - 06：401 清登录态 = 1003、权限 = 2001/2003、项目不存在 = 4004、积分不足 = [3001, 3002]、4290/5000
  - 07：err.bizCode === 2003
- 前后端若各自按本文档实现，错误处理全线失效。

## 二、P1 重大缺失与文档结构问题

1. **storyboards 与 shots 双轨冗余**：02 C3.7 定义了 `storyboards` 表（标注"兼容旧结构"），05 的 3.3.2~3.3.6 端点 + StoryboardCardDTO 等 Schema 有表支撑。但 `storyboards`（shot_no / content / shot_size / camera_movement）与 C2.6 `shots` 表职责重叠、字段几乎一致，两套分镜结构并存，与 C3.1 资产的"统一顶层表"思路相悖，属于表设计冗余而非幽灵资源。（修正：此条原判为"02 无 storyboards 表"有误，特此更正）
2. **主题/语言包无表支撑**：05 定义 11.65~11.72（`/admin/themes`、`/admin/languages`）共 8 个端点，02 无对应表。
3. **实名认证审核无数据基础**：07 UserVerifyPage（身份证 OCR + 人脸比对）——02 users 表无 real_name / id_card 等任何实名字段，05 无实名审核端点，整个功能悬空。
4. **资产合规审核无端点**：07 AssetCompliancePage（违规图库 top-3 对比等）在 05 无对应接口。
5. **安全瑕疵**：05 `/uploads/presign` 设置 `security: []` 免鉴权——任何人可无限获取预签名上传凭证（刷存储成本攻击面）。
6. **05 内部结构错误**：
   - `/projects/{project_id}` 同路径同时定义 POST 和 DELETE（更新应 PUT）
   - pay-callback 声称支持"支付宝/微信"双渠道，但其他文档只设计了支付宝当面付
   - 关联图使用本地绝对路径 `file:///c:/Users/.../Desktop/...`（他人无法打开）
7. **02 内部表数与分期清单自相矛盾**：
   - 表数：C 章实际定义 **58 张**（C9 有 13 张：C9.1~C9.13），附录 F 却写"55 张"且 C9 计 10 张
   - 01 同样表数混乱：阅读指引写"55 张表"，A.2 写"30 张核心业务表"，ADR-05 写"M0 建 16 张"——同一文档三套数字；03 又有"M0 建 16 张"说法（表数体系共 4 套：55/58/30/16）
   - 附录 D（M1 扩表）与 C 章重复：D.1 packages/user_memberships、D.2 canvas 5 张、D.4 agent_skills/directive_skills/agent_memories 在 C 章已全部定义（C8.3/C8.5/C5.1~C5.5/C9.6~C9.8），附录却声称"M1 再细化字段"；且 D.2 列的 canvas_node_results / canvas_conversation_logs 在 C 章不存在（C 章是 canvas_templates / canvas_auto_save_snapshots）
   - 附录 E（M2 扩表）重复：comments/likes/favorites/follows/reports/task_orders/task_intents/3D 场景在 C6/C9 已定义；3D 表名不一致（C9.11 `three_d_scenes` vs 附录 E.3 `3d_scenes` 5 张）；E.5 运营表（banners/announcements/courses/activities 等）在 C 章无字段明细，但 05 有 `/admin/banners`、`/admin/courses`、`/admin/activities` 端点
8. **01 系统架构职责越界**：D 章 4 条核心流程图（含 SQL 事务伪代码、7 步验签 ASCII、WS 消息格式）、F 章非功能性设计（安全算法深挖/删库演练 SOP/P0 告警流程）、G 章 24 周逐周交付物表（含每行风险Top3）、附录 B/C 排期路标均非架构层内容，应移入 03/04 或独立排期文档；架构文档保留真源铁律 + A 目标 + B 分层 + C 模块引擎 + E ADR 即可（约 300 行）
9. **方案文档代码量过大（04/06/07）**：06 有 36 个代码块、07 有 21 个、04 有 44 个（Go/SQL 实现级代码最多），含大量完整实现级代码（auth.store.ts 全量、WS Hook 全量、useProTablePersist 完整实现、BaseProTable 完整组件、JWT 签发工具函数等），超出方案文档职责；应保留目录结构 / 状态分层决策 / QK 命名规则 / 关键交互设计 / 接口契约签名，完整实现交给代码仓库（03 亦有 19 个代码块，其中 Python/Celery 伪代码必须删）

## 四、P3 技术栈残留与文本错误

1. **03 大量 Python 残留**：E.3.2 仍写"Celery 多队列"，附录 A.4 伪代码是 Python FastAPI + SQLAlchemy + `@celery.task`（技术栈是 Go + Gin + 自写 Redis 调度）。
2. **06 残留**：12.4 chunkSplitting 注释含 antd/echarts（用户端技术栈明令禁用 AntD）；"10 号 OpenAPI 文档"笔误（应为 05）。
3. **07 代码错误**：`import { toast } from 'antd'`——antd 无 toast 导出（应为 message）。
4. **07 章节编号错乱**：
   - 第八章标题"第十章"、第九章标题"第十一章"
   - 9.5 标题"统一导出"正文被 9.5.1 搜索区规范截断（导出说明只剩代码块）
   - adminStore 声称"6 字段"实际 5 个
   - authStore 声称"8 字段"只列 6 个
5. **04 文本错误**：N.2 audit_logs SQL 用 `//` 注释（SQL 语法错误，应为 `--`）；M.2 标题"9 消息"实际定义 12 种。
6. **03 编号重复**：C.1.3 出现两次。
7. **07 路由/Nginx 疑点**：反代写 `/api/v1/admin/ → backend /admin-api/`，但 05 管理端路径前缀是 `/admin`（无 `/api/v1` 前缀），前缀拼接规则未对齐。
