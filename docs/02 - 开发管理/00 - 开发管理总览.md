## 〇、排期总原则（3 周 · 15 工作日 · 全量范围）

| 项 | 值 |
|----|----|
| 总周期 | **3 周（15 个工作日，周一~周五）** |
| 范围 | 设计方案全量功能（58 表 / 230 接口操作 / 10 模块 + 8 引擎），范围不裁剪 |
| 阶段 | 4 个：阶段 0 工程地基（W1 D1~D2）→ 阶段 1 核心闭环（W1 D3~D5）→ 阶段 2 协作增强（W2）→ 阶段 3 生态治理（W3） |
| 任务批次 | 68 个（后端 38 / 前端 21 / 质量 9），日均 ~4.5 批 |
| 优先级 | **P0 保底主线 / P1 尽力 / P2 可后置**（管理端 财务/运营/模型配置等为 P2） |
| 弹性吸收 | W1 D2、W1 D5、W2 D5 三个收口检查点；P2 批次顺延至下一阶段消化，**总 15 天不延**，P0 绝不让位 |

**执行铁律**：
1. 质量门槛（E2E 故障用例、计费账本、契约冻结）是硬指标，**压缩的是功能排期，不是验收标准**。
2. 每个任务批次在分解文档中标注优先级与依赖；完成即勾选 `[x]`，进度同步 00 五章速览表。
3. 阶段验收只使用设计方案中已定义的硬指标（03 G 章 G1/G2/G3 与 F 章 E2E），不引入派生指标。

## 四、阶段验收卡（只引用设计已定义硬指标，03 G/F 章）

### 阶段 1 核心闭环 → 阶段 2 晋级（W1 周末评审，全部 AND 满足）

- [ ] **G1** 技术成功率 ≥ 75%（口径见 03 G.1，首次成功下载可播放 MP4 / 完成 Step1）
- [ ] **G2** 付费转化率 ≥ 5% 且成功付费用户 ≥ 3 人（样本 ≥ 50 人）
- [ ] **G3** 首片时长中位数 ≤ 25 分钟（进入 SCRIPT_SPLITTING → 首次成功下载）
- [ ] E2E 核心用例 100% 通过（03 F.1 M0 十条，含支付重复回调、模型回调重复/乱序、Worker 宕机恢复、Redis 重启恢复四类故障用例）
- [ ] DDL 迁移可在空库与基线库重复执行；契约与 02 - 数据库设计.md A 章枚举生成校验通过
- [ ] P0 级 Bug 0 未修 / P1 级 ≤ 5 未修
- [ ] 计费账本抽样核对无差异（每成功任务恰一次扣费、每不可交付终态恰一次全额解冻）

### 阶段 2 协作增强 → 阶段 3（W2 周末评审）

- [ ] E2E 整体通过率 ≥ 95%（03 F.2 M1 五条并入）
- [ ] 协作邀请/越权拦截、团队并发冻结、版本回滚、跨集复用免扣、月卡首购到期、画布保存恢复用例通过
- [ ] 协作/画布/会员 P0 缺陷 0；计费账本抽样无差异
- [ ] M1 扩表迁移在空库与基线库重复执行（02 数据库设计 附录 D 清单）

### 阶段 3 上线门槛（W3 周末）

- [ ] 功能通过率 ≥ 98%；P0 漏洞 0 个
- [ ] 财务对账轧差 = 0
- [ ] 灰度 1%→10%→50%→100% 每档具备监控阈值与一键回滚记录
- [ ] 1000 并发压测通过（03 F.2 / 01 F.2 指标口径）
