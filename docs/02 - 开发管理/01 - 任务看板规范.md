# 任务看板规范

> 本文定义执行状态，不替代 [09 - 分期路标](../01%20-%20设计方案/09%20-%20分期路标.md) 的阶段范围或门槛，也不替代设计真源。

## 1. 任务卡片

每个可交付任务使用下列结构。工作包是任务的聚合单元；可独立验收、可独立回滚或可独立阻断的事项必须拆为任务卡片。

| 字段 | 填写规则 |
|---|---|
| ID | `阶段-领域-序号`，例如 `M0-AUTH-01`；创建后不复用 |
| 工作包 / 领域 | 说明业务归属和交付边界 |
| 关联真源 | 至少一个设计文档链接；涉及 API、DDL、E2E 时必须分别引用 |
| 前置依赖 | 依赖任务 ID、外部服务、决策或迁移；无依赖写“无” |
| 交付物 | 可检查的实现、配置、迁移、测试或运行产物 |
| 验收证据 | PR、迁移记录、契约校验、测试报告、E2E 日志/录像、监控截图等路径 |
| 负责人 / 验收人 | 以角色或实际责任人维护；同一人可兼任但必须显式记录 |
| 状态 | 使用第 2 节状态机 |
| 风险 / 阻断 | 关联 `06` 的风险、问题或变更 ID；无则写“无” |

## 2. 状态机

```text
BACKLOG → READY → IN_PROGRESS → IN_REVIEW → VERIFYING → DONE
                    ↓              ↓             ↓
                 BLOCKED ←─────────┴─────────────┘
BACKLOG / READY / IN_PROGRESS / BLOCKED → CANCELLED
```

| 状态 | 含义 | 进入条件 | 退出条件 |
|---|---|---|---|
| BACKLOG | 已识别，尚未具备执行输入 | 有工作包归属 | 真源、依赖和验收方式明确 |
| READY | 可开始 | 依赖已满足，范围可确定 | 负责人开始处理 |
| IN_PROGRESS | 正在实现或配置 | 有负责人和当次目标 | 提交可评审交付物，或发现阻塞 |
| IN_REVIEW | 等待同行或设计评审 | 交付物完整、影响已说明 | 评审通过进入验证，或退回处理 |
| VERIFYING | 验证中 | 评审通过，具备可运行/可检查产物 | 证据满足完成条件，或发现缺陷 |
| DONE | 已完成且可追溯 | 第 3 节全部满足 | 仅因新变更重新打开为 READY |
| BLOCKED | 外部依赖、决策或缺陷阻塞 | 阻塞项已记录并升级 | 阻塞解除，回到原待处理状态 |
| CANCELLED | 明确不再交付 | 有取消原因、影响和真源确认 | 不直接恢复；需要时创建新任务 |

## 3. 完成定义

任务标记 `DONE` 前必须同时满足：

- 交付物已进入可追溯位置，且评审结论明确。
- 受影响的 API、DDL、枚举、状态机或配置已与对应真源一致；需要变更时先完成真源更新。
- 适用的自动化校验通过，失败项有已关闭的例外决策。
- 适用的 E2E、故障注入、迁移或回滚已执行，并保存原始证据。
- 不存在阻断该交付物的 P0/P1 问题；遗留问题有负责人和归属。

## 4. 更新节奏

- 开始、阻塞、评审完成、验收完成当天更新任务卡片。
- 每次阶段评审前，冻结任务清单并将所有 `BLOCKED`、`IN_REVIEW`、`VERIFYING` 项列入门禁清单。
- 状态描述只陈述已观察事实；“待验证”“待定”“无法复现”不得写成已通过或已上线。
