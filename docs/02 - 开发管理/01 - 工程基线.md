## 三、技术决策登记（阶段 0 必须落定的决策）

> 决策原则：只登记**影响面大、改动成本高**的决策；可后置的（如 M1/M2 细化）不在此登记。每项决策记录：结论 + 理由 + 影响。

### D1 数据库迁移工具（01 系统架构「开发启动再定」①）

| 候选 | 与原生 ENUM（ADR-07）兼容 | 可重复执行（空库+基线库） | 建表依赖顺序支持 | 生态/运维面 |
|------|--------------------------|--------------------------|-----------------|------------|
| golang-migrate | ✅ 纯 SQL 文件 | ✅ versioned 迁移 | ✅ 手工编排序号 | Go 生态，单二进制 |
| goose | ✅ 纯 SQL 文件 | ✅ 支持注释标记 | ✅ 同左 | Go 生态 |
| Atlas | ⚠️ 依赖 schema 解析 | ✅ declarative | ✅ | 额外 DSL 学习面 |
| Prisma Migrate | ⚠️ 与 Go/纯 SQL 弱耦合 | ✅ | ⚠️ | 引入 JS 工具链 |

> **倾向结论**：`golang-migrate`（纯 SQL + versioned + Go 单二进制，与 ADR-02/07 一致）。**D1 为待办决策，W1 D1 上午拍板后回填此处**，格式：`✅ 已定：golang-migrate vX —— 理由：…`。

### D2 枚举代码生成机制（02 - 数据库设计.md A 章 → 代码）

- **方案**：以 `CREATE TYPE` 为单一来源，开发一个小生成器（Go 代码生成，纳入 `make gen`）产出三件套：Go 常量集、TS 类型联合、入参校验器。
- **理由**：真源铁律要求"枚举只加不改"，前后端硬编码即违规（00 导航 B 章第一行）。
- **验收**：B02 生成产物通过校验；阶段 1 起任何接口枚举引用生成物。

### D3 AI Adapter / ModelEngine 结构（对齐 01 C.2.2，不新增设计）

- **结论**：Provider 接口 + 配置表 `model_keys`（vendor/model_name/api_key AES 加密/concurrency_limit/priority/monthly_quota）+ 逐 Key 信号量 + 429 自动切换 + 全失败友好报错。
- **影响**：B06 交付的接口即 E2/E7 的依赖；阶段 1 的 Step1~Step3 Worker 全部经此调用模型，**接口冻结后不改**。

### D4 契约冻结起点（对齐 05 接口文档）

- **方案**：05 OpenAPI 3.0 YAML 为契约真源 → B08 导入生成 `api-client`（前端 TS）与路由校验（后端）；阶段 1 起新增端点必须先在 05 登记。
- **验收**：契约校验纳入 CI；任何路径/字段偏离 05 即 CI 失败。
