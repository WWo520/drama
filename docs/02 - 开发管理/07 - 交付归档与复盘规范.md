# 交付归档与复盘规范

> 归档目标是让任何阶段结论都能由原始证据复查，而不是以口头结论代替验证。

## 1. 证据索引结构

每项证据应以任务 ID 为目录或前缀，并保留来源、生成时间、执行环境、输入版本和结论。

```text
交付证据/
  M0-任务ID/
    migration/       # 迁移、空库与基线库执行、回滚日志
    contract/        # OpenAPI、枚举生成与兼容性校验
    test/            # 单元、集成、E2E 原始报告
    fault/           # 故障注入、恢复和死信重放证据
    release/         # 构建、部署、灰度、回滚记录
    review.md        # 评审结论与遗留项索引
```

实际存储路径可由项目配置确定；任务卡片必须链接到实际位置，不使用仅描述性的“已测试”。敏感日志应脱敏并遵守访问控制。

## 2. 必须归档的交付物

| 类型 | 最小归档内容 |
|---|---|
| 数据迁移 | 迁移编号、依赖、空库/基线库执行日志、回滚或不可回滚说明、数据校验 |
| 契约 | OpenAPI 版本、生成物校验、兼容性结论、消费者影响 |
| 计费/支付 | 幂等、原子性、重复与乱序回调、账本对账结果 |
| 异步任务 | 投递、重试、崩溃恢复、Redis 故障、死信和人工重放证据 |
| E2E | 用例版本、环境、测试数据、执行结果、失败单与修复关联 |
| 性能与恢复 | 压测配置/报告、备份恢复、PITR、容量、降级和回滚记录 |
| 上线 | 制品版本、配置版本、审批、灰度观测、回滚演练和最终结论 |

## 3. 阶段复盘

每个阶段结束后建立一份复盘记录，包含：

1. 目标与实际交付：仅引用 `09` 的范围和门禁结论。
2. 事实时间线：任务状态、故障、决策和恢复动作，避免归因猜测。
3. 数据与质量：门禁证据、缺陷分布、账本和迁移验证结果。
4. 偏差与根因：区分已证实根因与待验证假设。
5. 遗留项：必须关联新的任务 ID、负责人、风险级别与门禁影响。
6. 可复用改进：沉淀到相应设计真源、流程规范或自动化验证中。

阶段结论只能为“通过”“不通过”或“有条件通过（附已批准例外）”，并链接 `05 - 阶段门禁与证据清单`。
