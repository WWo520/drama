## 三、宽度调整逻辑详解

> 本节详细记录各页面的内容宽度设置逻辑，便于后续调整时保持一致性。

### 全局宽度体系

```
总视口宽度 = 72px（主导航）+ 220px（剧集侧边栏）+ 主内容区宽度
```

主内容区使用 `flex-1`，占满剩余空间。内容在主内容区内的宽度因页面而异。

### 各页面宽度参数

| 页面 | 内容宽度 | 实现方式 | 设计原因 |
|------|---------|---------|---------|
| 剧本拆分 | ~65% | `max-width: 65%` + `mx-auto` | 叙事单元卡片+剧本原文，信息密度低，窄一些更易读 |
| 资产生成 | 接近全宽 | 未设置 max-width，使用 `px-6` padding | 资产网格需要足够空间展示角色/场景/道具卡片 |
| 视频制作 | ~85% | `max-width: 85%` + `mx-auto` | 镜头卡片网格需要空间，但左右留边更聚焦 |
| 成片预览 | 播放器 max 400px | `max-width: 400px` + `flex justify-center` | 竖屏 9:16 播放器，固定比例居中展示 |

### 调整方法

如果需要调整某个页面的内容宽度：

1. **剧本拆分页**：在 `workbench-script.html` 中搜索 `max-width: 65%`，修改百分比值
2. **视频制作页**：在 `workbench-video.html` 中搜索 `max-width: 85%`，修改百分比值
3. **成片预览页**：搜索 `max-width: 400px`（播放器宽度）和 `68vh`（播放器高度）

### 注意事项

- 百分比是相对于**主内容区**（即减去 72px + 220px 后的区域），不是整个视口
- 所有页面内容区都有 `px-6` 左右 padding，确保内容不会贴边
- 工作台顶部栏不受内容宽度影响，始终占满全宽（左占位 + 居中胶囊 + 右按钮）

## 四、经验教训

### 1. 不要凭想象做设计，先找真实参考

**教训**：第一版工作台凭经验做了三栏布局（左剧集树+中央内容+右属性面板），与真实界面完全不符。LuxReal 实际上**没有右侧属性面板**，内容占满全部宽度，属性编辑是内联在卡片中的。

**做法**：先通过官网、测评文章、教程视频收集真实界面截图，仔细分析布局后再动手。本次通过 aitntnews 的测评文章获取了 12 张真实界面截图，作为第二版重做的依据。

### 2. 侧边栏结构：主导航 + 剧集栏，不是合并在一起的

**教训**：最初把剧集列表放在主侧边栏里，实际上 LuxReal 有两个独立的左侧栏：
- 最左 72px：全局主导航（创作/发现/作品/帮助/通知/头像），纯黑背景
- 第二栏 220px：项目级导航（返回/项目名/剧集/叙事单元/新增剧集），深灰背景

### 3. 工作流步骤是"胶囊"样式，不是全宽顶栏

**教训**：最初设计了横跨整个顶部的步骤条，真实界面中工作流是一个**居中的圆角胶囊（pill）**，悬浮在内容上方，有毛玻璃效果，当前步骤用蓝紫渐变+发光表示。

**实现方式**：使用 `absolute left-1/2 -translate-x-1/2` 绝对定位居中，外层顶部栏使用 `flex justify-between`，左侧放 `w-[200px]` 占位，右侧放页面特有按钮。

### 4. 卡片风格：深灰圆角矩形，非蓝色调

**教训**：早期卡片使用了蓝紫色调和发光边框，真实 LuxReal 界面是**低饱和度深灰卡片**（`#1E1E24`），只有交互元素（激活按钮、当前步骤）才用蓝紫渐变。整体视觉非常克制。

### 5. 内容宽度因页面而异

**教训**：不同工作流页面的内容宽度不同，不能统一用全宽或统一宽度。各页面根据信息密度和内容类型决定宽度：
- 剧本拆分：约 65% 宽度（居中，卡片不占满，阅读舒适）
- 资产生成：接近全宽（资产网格需要空间）
- 视频制作：约 85% 宽度（镜头卡需要空间但不到全宽）
- 成片预览：播放器居中，宽度较小（竖屏视频特性）

### 6. 底部浮动操作栏（Floating Action Bar）

资产生成和视频制作页有一个**居中悬浮在底部的操作栏**（药丸形按钮组），不是放在页面底部正常流中。容易遗漏。

### 7. 右下角浮动按钮组

每页右下角都有两个圆形浮动按钮（团队协作 + 客服/帮助），固定定位，容易被忽略。

### 8. 叙事单元不是树状展开的剧集

**教训**：最初设计了剧集 → 展开 → 叙事单元的树状结构。真实界面中，剧集是一张独立的卡片（蓝色边框高亮），下方是纯文本的叙事单元列表，没有树形展开收起的交互。

### 9. 全站一致性需要持续维护

**教训**：在不同阶段创建的页面（前台三页 vs 工作台四页）容易出现侧边栏样式、标题命名、图标选择等不一致。每次新增页面或修改共用组件时，务必同步更新所有页面。

**做法**：以工作台的 `workbench-script.html` 为基准页，修改共用元素（侧边栏、工作流、浮动按钮）后，逐一检查其他 6 个页面是否同步。

## 七、交接说明

### 如何继续开发

1. 用浏览器打开 `http://localhost:xxxx/pages/workbench-script.html` 查看工作台起始页
2. 通过顶部工作流胶囊在四个工作台页面间切换
3. 所有页面使用 Tailwind CDN + Lucide 图标 CDN，无需构建工具
4. 共用布局部分（侧边栏/工作流/浮动按钮）以 `workbench-script.html` 为基准，修改时注意 7 个页面同步

### 基准页规则

- **侧边栏基准**：以 `workbench-script.html` 的左侧 72px 主导航为准
- **工作台顶部栏基准**：以 `workbench-script.html` 的顶部栏结构为准（单行 + 左占位 + 居中胶囊 + 右按钮）
- **工作流胶囊基准**：以 `workbench-script.html` 为准

修改共用组件时，先改基准页验证效果，再同步到其他页面。

### 后续可做的优化方向

1. 提取工作台共用 CSS 到独立文件，减少重复代码（当前 4 个工作台页各自内联相同样式）
2. 让 `colors_and_type.css` 成为真正的单一令牌来源
3. 添加简单的交互效果（叙事单元切换、标签切换等已有基础JS）
4. 如果需要更精细的对齐，可注册 LuxReal 账号进入真实工作台逐像素比对
5. 考虑建立正式的 Design Library 统一管理令牌和组件
