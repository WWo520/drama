## 一、整体架构与定位

### 1.1 三层资产关系

```
┌─────────────────────┐    迁移/还原     ┌─────────────────────┐    API 调用    ┌─────────────────────┐
│  luxreal-clone      │ ───────────────▶ │  web-user /         │ ─────────────▶ │  duanju-backend     │
│  （设计稿，15页）    │                  │  web-admin          │                │  （Go 后端）         │
│  静态 HTML + CSS    │                  │  React + TS + TW    │                │  /api/v1 + WS       │
│  纯 mock 数据       │                  │  TanStack Query     │                │  JWT + RBAC + 限流  │
└─────────────────────┘                  └─────────────────────┘                └─────────────────────┘
```

**核心定位**：
- **luxreal-clone = 视觉规格说明书**。不是前端代码，是设计资产。每个页面的 DOM 结构、CSS 类名、交互状态都是"视觉真相源"。
- **web-user / web-admin = 正式前端**。按 `06 - 前端方案` 技术栈实现，React 只做「结构拆分 + 数据注入 + 交互托管」。
- **duanju-backend = 数据与业务源**。接口覆盖率 100%，设计稿的每个数据区域都有对应接口。

### 3.1b 计费规则（2026-08-17 接入，对齐 LuxReal 免费/收费分界）

| 环节 | 计费 | 实现 |
|------|------|------|
| 剧本拆分/分镜 | **免费** | 无扣费代码 |
| 资产图生成 | 角色 10 / 场景 8 / 道具 5 点，跨集复用豁免 | `asset_service.go` BatchGenerate → Freeze |
| 视频生成 | **10 点/秒**（时长×单价） | `service.go` GenerateVideos → Freeze |
| 成片导出 | **1 点/秒**（成片时长×单价） | `export_service.go` Trigger → Freeze |

> 计费链路：建任务 → `billing.Freeze`（冻结+流水）→ worker 完成 Settle（成功扣费/失败全额解冻）；余额不足任务标记 FAILED 返回 40003。

| admin-billing 页样式 | admin-billing（Tailwind 类为主） | → web-admin 直接用 Tailwind |

### 6.2 每页融合三步法

```
第 1 步 搬 CSS：HTML 里 <style>...</style> 整块 → pages/{page}/{page}.css（类名一个都不改）
第 2 步 拆 DOM：<body> 内容按区块拆成 React 组件（class="x" → className="x"）
第 3 步 换数据：内嵌 mock → TanStack Query 查询（渲染模板不变，只换数据源）
```

**铁律**：类名、DOM 层级、CSS 值三者原样保留 → 视觉与设计稿逐像素一致。

### 6.3 四条保真纪律

1. **CSS 原样复制**：禁止重写、整理、"优化"、改命名
2. **DOM 结构 1:1**：只做 `class=`→`className=`、`style=""`→`style={{}}`，层级不动
3. **禁止换 Tailwind 类**：设计稿未用 Tailwind，融合后也不得混用
4. **禁止"顺手美化"**：任何视觉调整必须先改设计稿
