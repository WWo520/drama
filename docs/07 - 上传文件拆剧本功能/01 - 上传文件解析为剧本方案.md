### A.3 进入工作台后的剧本解析（本地同构镜像实测）

官网反自动化无法继续交互，通过本地同构项目（页面与官网 1:1 对齐）走通全链路，API 行为与官网一致：

1. **进入工作台**：URL `/projects/{projectId}/step/1`；项目名自动取剧本开头
2. **Step1 剧本拆分页**：
   - 左侧 240px 集数面板（项目名 + 「第1集」列表 + 「新增剧集」按钮）
   - 右侧「**剧本原文卡片**」：显示字数（如「47 字」），DRAFT 状态可编辑，placeholder =「粘贴你的剧本，AI 将拆解为剧集、叙事单元与分镜脚本…」
   - 主按钮「**开始 AI 拆解**」
3. **拆解状态机**（点击后实测约 6 秒完成）：
   - `DRAFT`（草稿）→ 点击 → `SCRIPT_SPLITTING`（**剧本拆解中**，提示「正在拆解剧本《…》，AI 分析剧情结构中，预计 30s…」+「拆分任务已提交，AI 处理中…」）→ `PARTIAL_ASSETS`（**资产生成中**徽标）
4. **拆解产物（AI 输出四层结构的前三层）**：
   - 剧集：AI 自动命名，如「第1集 - 雨夜追击」（多集拆分实测会把第二段剧情并入第1集，多集切分未完善）
   - 叙事单元（beats）：如「叙事单元1 | 陆言深夜布防」（时长预设 12s）、「叙事单元2 | 巷口追捕」（10s），卡片带「解析完成」徽标 + 时长预设下拉 + 删除按钮
   - 镜头块（shot_group）：显示 `{shot_group_count} 个镜头块`，当前拆解不产出具体分镜内容（占位「（无剧本原文）」）
5. **API 链路（实测网络请求）**：`POST /api/v1/projects`（创建）→ `GET /projects/{id}` → `GET /projects/{id}/episodes` → `GET /episodes/{id}/beats` → `POST /projects/{id}/split-script`（提交拆解）→ 轮询 GET 至终态

## B. Luxreal 上传逻辑分析

### B.1 结论：上传 ≠ 解析，文件只是「剧本获取方式」之一

Luxreal 把「获得剧本文本」与「剧本拆解」**解耦为两个阶段**：

```
┌─ 剧本来源（三选一）────────────────────┐
│ ① 粘贴文字（≤5万字，实时可编辑）          │
│ ② 上传文件（doc/docx/pdf/txt，格式互斥） │
│ ③ 示例剧本（快捷填充入口）               │
└────────────────┬──────────────────────┘
                 ▼
        创建项目（自动命名=剧本开头）
                 ▼
        Step1 工作台 · 剧本原文卡片
        （上传文件 → 解析为纯文本后回填此处）
                 ▼
        点击「开始 AI 拆解」
        DRAFT → SCRIPT_SPLITTING → PARTIAL_ASSETS
                 ▼
        AI 输出：剧集 → 叙事单元 → 镜头块
```

### B.2 关键设计点（对齐价值）

| # | 设计点 | 行为 | 本项目对齐意义 |
|---|--------|------|---------------|
| 1 | **格式互斥** | 上传文件后禁止手动输入，提示「如需手动输入内容请先移除文件」；反之同理 | 避免双剧本源歧义 |
| 2 | **格式静默支持** | 界面不写格式清单，信息收进 info tooltip；accept 属性承载 doc/docx/pdf/txt | 界面简洁，格式扩展不改 UI |
| 3 | **解析前置、拆解后置** | 上传后仅完成「文件→纯文本」（入库/回填），「文本→剧集/单元」由用户点「开始 AI 拆解」触发 | 解析是确定性动作，拆解是 AI 动作，分开便于重试与计费 |
| 4 | **文件卡片态** | 上传成功显示文件名 + 绿勾 + 移除入口，替换初始拖拽区 | 状态可见、可回退 |
| 5 | **示例剧本即 DOCX** | 官方示例剧本就是 docx 文件 → 官网已具备 docx 解析能力 | docx 是文件上传的核心格式，必须支持 |
| 6 | **解析失败可降级** | 粘贴输入始终可用，文件解析失败不阻塞创建 | 兜底路径保体验 |

### B.3 上传格式策略推断

- **txt/md**：纯文本，前端 `FileReader` 直读即得内容（本项目已实现，Luxreal 未支持 md 但支持 txt）
- **docx**：本质 zip+xml，前端 `mammoth.js` 或后端解析均可；官网示例剧本即 docx，说明**官网解析发生在服务端或前端库**，解析结果回填为剧本原文
- **doc**（旧格式）：二进制，前端难解析，需后端或第三方服务转换
- **pdf**：文本层可抽取（pdf.js / 服务端 pdftotext），扫描件需 OCR（成本高，可延后）

### C.2 差距清单

| # | 差距 | 影响 |
|---|------|------|
| G1 | doc/docx/pdf **只入库不解析**，文件内容无法成为剧本 | 文件上传形同虚设，用户仍须手动粘贴 |
| G2 | 无「文件卡片态」：上传成功后输入框仍可编辑，无移除文件入口、无互斥提示 | 双剧本源歧义，与官网交互不一致 |

| G5 | 字数限制（5万字）只对粘贴生效，上传解析后的文本未校验 | 超长文本进入 AI 拆解可能超 token 上限 |

## D. 本项目方案

### D.1 总体流程（对齐 Luxreal 两阶段解耦）

```
┌─ 剧本来源 ─────────────────────────────┐
│ ① 粘贴文字（现状）                       │
│ ② 上传文件（本次补齐）                   │
│ ③ 示例剧本（现状，点击填入文本）          │
└────────────────┬──────────────────────┘
                 ▼
    ┌─ 前端本地直读（txt/md）─┐
    │                        │
    │  ┌─ 后端解析（doc/docx/pdf）─┐
    │  │  presign → MinIO →      │
    │  │  POST /uploads/parse     │
    │  │  (异步解析任务→纯文本)    │
    │  └───────────────────────┘
    ▼
剧本原文（source_script_text 或 project 剧本字段）
                 ▼
创建项目 / 进入 Step1 → 点「开始 AI 拆解」（现状链路不动）
```

### D.2 前端交互（HomePage 上传区，对齐 A.1/A.2）

**状态机（上传区）**：`EMPTY（拖拽区）→ UPLOADING（进度）→ PARSING（解析中）→ FILE_READY（文件卡片）| PARSE_FAILED（失败卡片可重试）`

1. **拖拽区**：保持现 UI；标题右侧补 info 图标（tooltip 写格式支持与上限：`支持 txt / md / doc / docx / pdf，单文件 ≤ 20MB，文本内容 ≤ 5万字`）；`input accept=".txt,.md,.doc,.docx,.pdf"`
2. **格式互斥**（对齐设计点 1）：
   - 选择文件 → 清除输入框现有文本并置灰
   - 手动粘贴 → 清除已选文件（提示「已移除已上传文件」）
   - 上传成功后文案：「已上传剧本文件《xxx》，如需手动输入内容请先移除文件」
3. **文件卡片态**（对齐 A.2）：文件名 + 类型图标 + 绿色勾（txt/md 直读成功同样进入此态）+「移除」按钮；移除后回到拖拽区，恢复粘贴输入
4. **解析反馈**：
   - txt/md：直读立即回填（现状保留）
   - doc/docx/pdf：上传完成 → toast「文件已上传，正在解析文档内容…」→ 轮询解析状态（GET /uploads/{token}/parse-status，2s 间隔）→ 成功：回填文本 + 文件卡片态 + toast「文档解析完成，已生成剧本文本」；失败：卡片显示红色失败态 + 「重试」按钮
5. **示例剧本**：点击后走「文本填入」路径（现状保留），同时进入文件卡片态（显示「示例剧本」标识），与官网一致

### D.3 后端解析链路

**沿用现有预签名通道，新增「解析确认」端点**（不改 presign/complete 契约）：

| 端点 | 方法 | 说明 |
|------|------|------|
| `/uploads/presign` | POST | 现状；`biz_type=script_file`；新增约束 `file_name` 后缀 ∈ {txt,md,doc,docx,pdf}、`size ≤ 20MB` |
| `/uploads/complete` | POST | 现状；扩展 `biz_ref_id` 语义：传入 project_id（未创建项目时传 space_id，现状兜底） |
| `/uploads/parse` | POST | **新增**：`{ upload_token, file_name }` → 校验凭证已确认 → 创建解析任务（TASK type=`SCRIPT_FILE_PARSE`，Outbox）→ 返回 `task_uuid` |
| `/uploads/parse-status` | GET | **新增**：`?upload_token=` → 返回 `{ status: PENDING|PARSING|DONE|FAILED, text: string|nil, error: string|nil, chars: int }`；DONE 时携带解析纯文本 |
| `POST /projects` | POST | **扩展**：请求体新增可选 `script_file_upload_token`；存在时服务端优先用解析结果文本创建项目（对齐 luxreal 10号文档 script_file_upload_token 字段，正式启用） |

**解析任务执行（worker / 同步降级两案）**：

| 格式 | 方案 A：后端 Go 直接解析（推荐 M1） | 方案 B：前端库解析（兜底 M0） |
|------|-----------------------------------|------------------------------|
| txt/md | 无需任务，前端直读（现状） | 同左 |
| docx | Go 库 `github.com/nguyenthenguyen/docx` 或 unzip+xml 提取 document.xml 纯文本 | 前端 `mammoth.js` extractRawText，文本 POST 回传 |
| pdf | 纯文本型：`pdfcpu`/`unipdf` 抽取；扫描型返回「扫描件暂不支持，请使用 txt/docx」 | 前端 `pdfjs-dist` 抽取文本层 |
| doc | 不解析：返回「旧版 .doc 暂不支持，请另存为 .docx 或使用 txt」 | 同左 |

> **决策**：M0 采用**方案 B 兜底 + 方案 A 预留**——txt/md 前端直读（现状）；docx/pdf 前端解析（mammoth.js / pdfjs-dist，纯前端无新增后端服务），解析文本通过 `POST /projects` 的 `script_text` 提交；后端 `/uploads/parse` 系列端点在 M1 随 worker 一起启用，实现「文件入库 + 服务端解析」双通道。这样 M0 就能让用户「上传 docx 直接开始创作」，且不动现有 MinIO 链路。

### D.4 状态与数据模型

**projects 表扩展**（迁移文件 `migrations/xxx_add_script_file.up.sql`）：

```sql
ALTER TABLE projects
  ADD COLUMN script_file_object_key TEXT,          -- 剧本源文件（MinIO object_key）
  ADD COLUMN script_file_name     TEXT,            -- 原始文件名（展示用）
  ADD COLUMN script_file_parsed_at TIMESTAMPTZ;    -- 解析完成时间
```

**解析任务状态机**（复用 tasks/outbox 机制，参考 SCRIPT_SPLIT）：
`QUEUED → RUNNING → SUCCEEDED | FAILED(≤2 次重试)`

**解析失败降级**（对齐设计点 6）：解析失败不影响粘贴路径；前端失败卡片提供「重试」（重新 POST /uploads/parse）与「改用粘贴」（清除文件，输入框恢复）。

### D.5 边界与错误码

| 场景 | 处理 | 错误码（沿用 20004 体系） |
|------|------|--------------------------|
| 格式不支持 | presign 拒绝 | 400 `20004`「仅支持 txt/md/doc/docx/pdf」 |
| 超过 20MB | presign 拒绝 | 400 `20004`「文件过大，请压缩后上传（≤20MB）」 |
| 解析文本 > 5万字 | 解析任务失败或创建项目时拒绝 | 400 `20004`「解析文本超过 5 万字上限」 |
| 凭证未确认就 parse | parse 拒绝 | 409 `90005`「请先完成上传回执」 |
| 凭证过期 | parse/status 拒绝 | 410 `90005`「上传凭证已过期，请重新上传」 |
| .doc 旧格式 | presign 通过、parse 明确失败提示 | 任务 FAILED + 错误文案「旧版 .doc 暂不支持，请另存为 .docx」 |
| 扫描版 PDF | parse 失败 | 任务 FAILED + 错误文案「扫描件暂不支持文字提取，请使用 txt/docx」 |

### D.6 分期

| 里程碑 | 范围 |
|--------|------|
| **M0（当前补丁）** | 前端：格式互斥 + 文件卡片态 + 示例剧本卡片态 + info tooltip；txt/md 直读（现状）；docx/pdf 前端解析（mammoth.js/pdfjs-dist）→ 文本回填；移除按钮；字数校验 |
| **M1** | 后端 `/uploads/parse` + `/uploads/parse-status` 服务端解析任务（Go 解析 docx/pdf）；`POST /projects` 支持 `script_file_upload_token`；projects 表 3 字段；.doc 与扫描 PDF 的错误提示固化 |
| **M2** | .doc 转 docx 服务；扫描 PDF OCR（如 PaddleOCR）；多文件剧本包（zip 含多集 txt） |
