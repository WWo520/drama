## 一、结论摘要

### 1.1 一句话结论

LuxReal 的四步流水线本质是「**三层 LLM 提示词技能 + 一个结构化分镜契约 + 一套预演-生成机制**」：
拆分靠**场景/画面连贯性判据**切出最小拍摄单元（叙事单元），资产靠**先写提示词后确认生成**的半自动提取，视频靠**分镜生成→任务规划→提示词润色**三个可配置技能串联，成片靠**镜头块时间线 + 素材/时间线分离导出**。

### 1.2 三方对照速查表

| 维度 | LuxReal | ToonFlow | 本项目 duanju |
|------|---------|----------|--------------|
| 技能载体 | **模板级**（4-Tab 无代码配置，官方模板全公开可改可存） | 代码级（data/skills/*.md，183 个，fs.readFile 加载） | Go 硬编码 splitSystemPrompt + DB 技能种子 |
| 拆分层级 | 项目→集→叙事单元→镜头块→镜头（5 层） | 小说→剧本→集→场景段落→分镜片段→镜头 | 项目→集→叙事单元→镜头块→镜头（4 层） |
| 单元粒度实测 | 4 单元/127s（均值≈32s），另案 6 单元/集 | 片段 ≤15s 硬上限，4字/秒估时 | 实测均值 21s 但 max 120s、1.4 单元/集（失控） |
| 拆分判据 | 「按场景、画面连贯性切分的最小拍摄单元」 | 情绪转折/说话人切换/动作段落 | 仅"每集 3~6 个"数量约束 |
| 提示词分工 | 三层：拍什么→怎么排→怎么写 | 决策层/执行层/监督层多 Agent | 单层拆分 + 逐镜头润色 |
| 一致性机制 | 3D片场 + 排演视频关键帧回灌 + 资产变体库 | 每片段全员在场校验 + 参考图 | 集级资产参考图 |
| 重跑粒度 | 单叙事单元重规划 + 历史版本回滚 | 记录级重试 | 整项目重拆 |
| 成片导出 | MP4 合成 + XML 工程包（素材/时间线分离） | ffmpeg xfade 拼接 | 480/720p MP4 导出 |

### 1.3 对本项目最有价值的 5 个借鉴点（详见第八章）

1. **拆分判据显式化**：叙事单元 = "一集之中按场景、画面连贯性切分出的最小拍摄单元"，且它是下游资产关联、提示词撰写、视频生成的统筹单位——判据与下游职责要写进提示词。
2. **三层提示词流水线**：分镜生成（拍什么）→ 任务规划（怎么排、参考图怎么配）→ 提示词润色（这句话怎么写），各司其职、各自可换模板。
3. **8 字段镜头契约 + 尾部全局约束指令**：结构化输出格式作为硬契约，末尾追加一句不可删改的生成约束。
4. **预演-审核-生成**（智能镜头）：先低成本生成几秒排演视频，抽关键帧回灌参考图，再生成完整视频——烧积分前先验证"这条片子是否成立"。
5. **拆分结果行内可编辑、单单元可重跑、历史版本可回滚**：避免"改一句台词重拆全项目"。

## 二、整体架构：数据模型与流水线

### 2.1 五级数据模型

```
项目 Project（一语成谶）
 └── 集 Episode（第1集"一语成谶"，预设总时长可配）
      └── 叙事单元 Beat（陆言开场说书，50s；一集 4~6 个）
           └── 镜头块 HeroShotGroup（分镜1，10s，13 块/集，5~14s/块）
                └── 镜头 Shot（每块 2~4 个，单镜头 2~9s）
```

案例《一语成谶》3 集，第 1 集 4 叙事单元、13 镜头块、合计 127 秒；时间线刻度实测：10/13/14/13/11/9/8/7/6/5/12/9/10。

### 2.2 四步流水线与路由

| Step | 路由 | 职责 | 核心技能 |
|------|------|------|----------|
| 1 剧本拆分 | `/script` | 剧本→集→叙事单元→场景 | 拆分引擎（Lux Chat 5.2） |
| 2 资产生成 | `/assets` | 提取角色/场景/道具/智能镜头/通用素材并出图 | 资产图模型 Lux Banana 2 |
| 3 视频制作 | `/storyboard` | 叙事单元→8字段分镜→视频任务→生成 | 分镜生成技能 + 任务规划技能 + 润色技能 |
| 4 成片预览 | `/preview` | 时间线预览 + 合成导出 | ffmpeg 级合成 |

StepBar 右侧并列两入口：【创建/进入自由画布 Beta】（精修模式）与【Agent 技能配置】（4-Tab 技能面板）。

### 2.3 Agent 技能配置面板（提示词管理中枢）

| Tab | 内容 | 关键配置项 |
|-----|------|-----------|
| Tab1 基础参数 | 等价模型配置面板 | 画面风格、视频模型/分辨率/比例、每集时长、三类资产图独立参数 |
| Tab2 分镜脚本生成技能 | **核心引擎 Lux Chat 5.2** | 智能扩写开关、生成模板（默认「剧情细腻刻画」）、**高级：生成逻辑、预期镜头格式**、另存为 |
| Tab3 视频任务规划技能 | 分镜→视频生成任务 | 镜头规划模板（默认「剧情连贯编排」）、智能镜头模式（多宫格 Pro/Fast）、规划逻辑 |
| Tab4 单视频提示词润色技能 | **Lux Gem 3.0** | 润色模板（默认「通用模板」）、润色规则与要求 |

设计要点：**一次配置全流程沿用**（点"修改"才改）；官方模板全部可见可编辑，改后可另存为个人模板；团队内 Skill 可共享，经验沉淀为一键复用资产（官方口径：单集拆解省约 10 分钟，协同提效约 50%）。

### 2.4 模型矩阵

| 角色 | 模型 | 用途 |
|------|------|------|
| 分镜/拆分 LLM | **Lux Chat 5.2**（自研） | 剧本拆分、智能扩写、8 字段分镜输出 |
| 润色 LLM | **Lux Gem 3.0**（自研） | 单视频提示词优化 |
| 资产图模型 | Lux Banana 2（自研） | 角色/场景/道具参考图，1K/2K/4K |
| 视频模型 | Seedance 2.5 / 2.0 / 2.0 Fast / KlingO3 | 480P~1080P，30s 长镜直出，支持 30 分钟整剧 |
| 3D 底座 | Lux3D / SpatialGen（自研） | 3D 片场、空间一致性 |

## 三、Step1 剧本拆分：执行过程与提示词

### 3.1 执行链路

```
上传/粘贴剧本（长文档拖拽自动上传解析）
 → 选风格/比例/每集时长（可不选，Agent 自动配置）
 → 创建项目即异步触发拆分任务（前端显示"剧本拆分中"）
 → 产出 集 → 叙事单元 → 【场景】 结构
 → 用户在卡片上行内精修（无需重拆）
```

- **重试语义**：拆分失败可手动重触发；重拆会重置四层结构并**级联清空已有资产/生成任务**（有资产时需二次确认）。
- **实测粒度**：案例 1「一语成谶」第 1 集拆 4 个叙事单元共 127s（均值≈32s/单元）；另一实测案例拆出 6 个单元——即单元粒度在 **20~50s 区间、每集 4~6 个**，与 ToonFlow 的片段级 ≤15s 不同：LuxReal 的叙事单元是"拍摄调度单位"，更细的镜头切分放到 Step3 的镜头块/镜头层完成。

### 3.2 拆分判据（官方口径）

> 叙事单元是**一集之中按场景、画面连贯性切分出的最小拍摄单元**。LuxReal 用叙事单元来统筹规划后续的资产关联、提示词撰写、视频生成，实现最终视频的连贯。

两个要点：
1. 切分依据是**场景 + 画面连贯性**（不是字数也不是固定时长）；
2. 叙事单元不只是展示层级，它是**下游一切工作的统筹单位**——资产按单元关联、提示词按单元撰写、视频按单元生成、重跑按单元进行。

### 3.3 拆分结果的标记语法（输出契约）

拆分引擎输出带固定标记的结构化剧本文本，前端据此渲染，用户可继续编辑：

| 标记 | 含义 | 示例 |
|------|------|------|
| `【场景X：地点 — 时间】` | 场景切换 | 【场景1：早点摊 — 日】 |
| `▲ + 描述` | 镜头/环境/动作描述 | ▲早点摊老板掀开蒸笼冒出白汽 |
| `角色名（动作提示）：台词` | 对白 | 陆言（敲锣）：各位看官… |
| `（画外音）` | 画外音角色 | （画外音）：翌日清晨… |

### 3.4 时长控制机制（两级继承）

- **集级**：本集预设总时长（自动 / 1分钟 / 1-2 / 2-3 / 3-5 / 5-10 分钟），该集所有叙事单元自动继承；
- **单元级**：每个叙事单元可单独覆盖时长预设下拉；
- 时长预设是 Tab2 分镜生成技能的输入——「**按时长预设将剧本原文转换为包含详细镜头描述的分镜脚本**」。

### 3.5 提示词侧观察

- 拆分与分镜共用 **Lux Chat 5.2**，配「智能扩写」开关（推荐开启：优化为更适合视频生成的镜头描述）；
- 生成模板默认「剧情细腻刻画」，高级区暴露两个可微调维度：**生成逻辑**、**预期镜头格式**——即官方把提示词拆成"怎么想"（逻辑）与"输出长什么样"（格式契约）两个独立可调槽位；
- 拆分步骤未观察到硬编码时长公式（对比 ToonFlow 的 4字/秒），其粒度控制更依赖"场景/连贯性判据 + 时长预设继承"而非数学估时。

## 四、Step2 资产生成：执行过程与提示词

### 4.1 执行链路

```
Step1 完成 → 自动提取五类资产（角色/场景/道具/智能镜头/通用素材）
 → 系统为每个资产先写出提示词（描述文案）
 → 用户审阅：可直接上传替换 / 修改提示词 / 单个或批量生成
 → 批量生成弹窗确认（模型/分辨率/比例/范围/风格/积分预估）
 → 生成后资产进入参考图库，供 Step3 引用
```

关键点：**"先写提示词、后确认生成"**——资产提示词是先于图片产出的可见中间产物，用户可编辑后再生成，而不是黑盒直出。

### 4.2 提取与变体机制

- 五类资产 Tab：概览 / 角色 / 场景 / 道具 / 智能镜头 / 通用素材；剧集筛选栏支持跨集查看（识别"某资产在哪些集出现过"）；
- **角色变体**：同一角色多套服装（沈青禾→干练老板娘装；陆言→市井说书装），Tab 切换；同一人物不同状态（骑行/滑雪/家居）被整合，避免变脸；
- **场景日夜变体**：市井古街→白日闹市、陆言家小院→暮色夜景、陆言家屋内→夜间烛光；
- **道具**：道具图固定 **1:1 正方形**（与角色/场景的 16:9 不同）；
- **重新提取本集资产**：剧本修改后一键重跑提取，不必重走全流程。

### 4.3 批量生成弹窗（执行参数面）

| 区块 | 内容 |
|------|------|
| 资产图模型配置 | 角色/场景：Lux Banana 2 / 1K / 16:9；道具：Lux Banana 2 / 1K / **1:1** |
| 跨集说明 | "资产参演的所有剧集都会显示该资产的生成状态（**不会重复消耗积分**）" |
| 生成范围 | 按集复选框 + 全选，动态显示已选集数 |
| 风格 | 与风格库下拉联动（默认通用写实，风格库含 27 个公共风格：邵氏武侠/王家卫/徐克等） |
| 积分预估 | 选集后显示预计扣费 |

### 4.4 资产引用语法（进入 Step3 提示词的桥梁）

- **精准模式**：`@`显式指定素材用途（更可控）；
- **简化模式**：自然语言描述中提到角色名/场景名即自动匹配（官方提示："不用@资产，描述即可生效；需要发挥模型创造力时可不@，需要更好控制结果时用@指定用途"）；
- 参考图可拖拽绑定到具体镜头（"XX图片是镜头1的参考图"），**替换任一参考图会自动同步到下一轮视频制作流程**（资产联动）。

### 4.5 3D 片场（一致性锚点生产）

实抓纠正：3D 片场不是建模工具，是**场景光影参考图实时渲染引擎 + 空间调度台**：

```
场景图（生成/上传）→ 打开3D片场（/create 实时渲染页）
 ├─ 大Tab：场景 / 光影（环境/灯光/滤镜；风格/时段/更多）
 ├─ 放置人物白模 → 快捷键+鼠标调机位、焦距
 ├─ 画质增强把白模替换为真实人物资产
 └─ 【截取画面】→ 保存进通用素材 → 作为后续分镜的标准参考
输出：普通图 / 全景图，16:9 可选
```

作用：所有镜头共享同一三维空间基准，从物理层面减少穿帮——这是 LuxReal 区别于纯 2D 工具的一致性根基。

## 五、Step3 视频制作：执行过程与提示词（核心）

### 5.1 三层提示词流水线

这是 LuxReal 提示词工程的核心结构，三个技能职责正交、各自独立配模板：

```
叙事单元剧本原文 + 时长预设
   │  ① 分镜脚本生成技能（Lux Chat 5.2，模板「剧情细腻刻画」，智能扩写开关）
   ▼
8 字段分镜脚本（镜头1..N，历史版本可回滚）
   │  ② 视频任务规划技能（模板「剧情连贯编排」，智能镜头 Pro/Fast）
   ▼
多个视频生成任务（每任务 = 提示词 + 参考图集）
   │  ③ 单视频提示词润色技能（Lux Gem 3.0，模板「通用模板」）
   ▼
送入视频模型（Seedance/Kling）生成
```

官方对三层的分工描述（公开访谈口径）：
- **镜头提示词生成技能 ≈ 分镜编剧**：把剧本按时长拆成多个镜头，为每个镜头写清主体、场景、核心动作、台词——解决"**拍什么**"；
- **视频任务规划技能 ≈ 制片调度**：把多个镜头整理成实际送生成的任务，决定参考图怎么用、哪些镜头保持连续、哪些保持画风统一——解决"**怎么排**"；
- **单视频提示词润色技能**：补充镜头运动、动作节奏、画面细节，减少含糊表达——解决"**这句话怎么写**"，让视频模型更容易呈现预期。

### 5.2 8 字段镜头契约（结构化输出格式）

①层输出的每个镜头强制包含 8 个字段：

| 字段 | 典型取值（实测枚举） |
|------|---------------------|
| 【时长】 | 2s / 3s / 4s / 5s / 9s |
| 【景别】 | 特写 / 近景 / 中景 / 全景 / 远景 |
| 【运镜】 | 固定 / 慢慢推进 / 横移跟拍 / 升镜头 |
| 【视角】 | 平视 / 微仰拍 / 俯拍 / 过肩 / 平视侧面 / 平视正面 / 平视内侧 / 平视背面（9 种） |
| 【主体】 | 画面描述核心，含人物动作/表情/道具互动，可长达百字 |
| 【背景】 | 环境/场景名（市井古街 / 老槐树下） |
| 【台词】 | 【角色名 情感修饰】：台词；另有身份括注、画外音等 5 种格式 |
| 【环境音】 | 音效设计（铜锣"当当当"回响、人群脚步靠近） |

实例（第1集-叙事单元1-分镜1）：
```
镜头1：【时长3s】【景别中景】【运镜慢慢推进】【视角平视】
       【主体】早点摊老板掀开蒸笼冒出白汽...
       【背景】市井古街
       【台词】包子店老板吆喝：卖包子喽！！！
       【环境音】嘈杂的中国古代市井小巷背景音
```

### 5.3 尾部全局约束指令

每个分镜脚本结尾，Agent 自动追加一句不可删改的 LLM 约束：

> **严格按照分镜脚本进行生成，参考上传图的人物形象、场景和道具。不要生成字幕。**

这是"格式契约之外的一句话硬约束"，钉住三件事：忠于脚本、忠于参考图、禁字幕。

### 5.4 智能镜头：预演-审核-生成机制（一致性核心）

这是 LuxReal 区别于所有竞品的执行模式，被称为"视频届的 Harness"：

```
① 基于整集剧本先生成一段几秒~10秒的排演（预览）视频
   —— 在几秒内锁定全部人物与空间位置关系
② 用户审核排演视频（不满意提前修改，避免烧大额积分）
③ 从排演视频智能提取关键帧 → 作为参考图补进后续每个镜头的提示词
④ 再生成完整视频
```

两种模式（Tab3 配置）：

| 模式 | 原理 | 适用 | 参考图上限 |
|------|------|------|-----------|
| 多宫格 Pro（推荐） | 生成连续视频后提取关键画面帧，保持长镜头连贯 | 叙事性强的长镜头 | ≤9 张 |
| 多宫格 Fast | 生成多宫格拼图后拆分，确保多镜头画风高度统一 | 多人互动、画风统一要求高 | ≤10 张 |

对比传统九宫格参考图方案：九宫格各图之间场景布局会漂移，智能镜头的关键帧来自同一段连续视频，场景布局天然一致——**用"同一时间源"解决参考图互不一致的问题**。

辅助操作：抽帧（【提取当前帧】保存进智能镜头库）→ 替换指定镜头的参考图 → 自动同步后续流程；点击视频组放大查看全部参考图并逐张微调。

### 5.5 版本管理与重跑粒度

叙事单元头部标准 5 件套：`叙事单元N | 名称 | 时长XX秒 | 历史版本 | 重新规划 | 生成视频` + 剧本原文展开。

- **历史版本**：分镜脚本版本管理，可回滚到旧版本；
- **重新规划弹窗**（双 Tab）：Tab1「分镜脚本」直接编辑 ↔ Tab2「重生成分镜」重跑 Agent 参数；弹窗内展示单元信息（时长/关联资产数）+ 剧本原文默认展开；
- **单单元重跑**：只重跑当前叙事单元，无需全项目重跑——与本项目"重拆即清全项目"形成鲜明对比。

## 六、Step4 成片预览：执行过程

### 6.1 时间线结构

```
第1集 - 一语成谶（127秒）
├─ 13 个镜头块缩略卡片：00:10 | 00:13 | 00:14 | ...（带时长徽章）
```

## 七、提示词工程特征总结

### 7.1 与 ToonFlow / 本项目的机制对比

| 机制 | LuxReal | ToonFlow | duanju 现状 |
|------|---------|----------|------------|
| 提示词载体 | 产品内模板（无代码、UI 可编辑） | data/skills/*.md 文件，运行时加载 | Go 代码硬编码 + DB 技能种子 |
| 粒度控制手段 | 场景/连贯性判据 + 时长预设两级继承 + 8字段格式契约 | 数学铁律（≤15s、4字/秒、>20字拆镜） | 仅数量约束（3~6 单元/集） |
| 提示词分层 | 三层正交技能，各配独立模板与模型 | 决策/执行/监督三层 Agent | 单层 + 逐镜头润色 |
| 输出契约 | 8 字段文本模板 + 尾部一句话硬约束 | JSON 结构 + 铁律列表 | JSON schema（四层结构单次生成） |
| 一致性手段 | 排演视频关键帧回灌 + 3D 片场空间基准 | 全员在场校验 + 参考图 | 集级资产图 |
| 人工介入点 | 每层都有：行内编辑/参考图拖拽/模板另存 | 执行中 Socket.IO 交互 | 重拆全项目 |

### 7.2 LuxReal 提示词设计的四个可迁移原则

1. **判据 + 职责写进拆分提示词**：不只说"拆成几个"，而是说清"按什么切"（场景/画面连贯性）和"切出来的东西是谁的统筹单位"（资产关联、提示词撰写、视频生成）。判据明确后模型不会把一整集塞进一个单元。
2. **逻辑与格式分离配置**：「生成逻辑」和「预期镜头格式」是两个独立可调槽位——改输出格式不必动推理逻辑，反之亦然。对应到本项目：splitSystemPrompt 里的"结构规则"与"JSON 格式要求"也应分段组织。
3. **格式契约 + 尾部硬约束双保险**：结构化字段保证可解析，结尾一句话保证生成行为（忠于脚本、忠于参考图、禁字幕）。本项目润色环节可加等价的尾部约束。
4. **低成本预演替代直接生成**：在烧大钱（视频生成）之前，先用小成本产物（排演视频/关键帧）验证方向并回灌参考——这是"先验证再生成"的 Harness 思想在视频生产里的落地。

## 九、分集机制专项补充调研（2026-08-22）

> 针对三个问题的专项回答：① LuxReal 怎么分集；② 拆分提示词怎么写；③ 剧本拆分用了几层 LLM。

### 9.1 分集机制：「集 = 用户侧容器，AI 主攻集内拆分」的双轨制

**结论：LuxReal 的分集不是纯 AI 一步到位，而是「用户建集容器 + AI 拆集内单元」双轨并行，自动分集在其自身规划中也只是 P2 级功能。**

证据链：

| # | 证据 | 来源 |
|---|------|------|
| 1 | Step1 左侧剧集大纲导航：`第1集-{集名}（默认展开）→ 叙事单元1~N → 第2集/第3集（可折叠）→ +新增剧集 按钮` | 01号文档 011 条 |
| 2 | 本集操作按钮：`+新增剧集`（在项目下增加新的一集）+ 本集预设总时长下拉（自动/1分钟/1-2/2-3/3-5/5-10分钟） | 03号文档 035 条 |
| 3 | `+新增剧集` 按钮（`EpisodeSidebar-addEpisodeBtn_7b541`）在官方只读案例中静默；推断用户自建项目时弹出「剧本粘贴 + 集数命名 + 时长预设」配置弹窗——即**集是按集粘贴/命名的用户容器** | 07号文档 104 条 |
| 4 | 需求清单 B1.1.8：「智能剧集自动切分（按剧情转折点+长度自动分第1/2/3集）🟢**P2**；M0 强制单集（1 project = 1 episode），用户手动建多集」——**官方自己也把 AI 自动分集排到最后优先级** | 09号文档 B1.1.8 |
| 5 | 官方案例「一语成谶」实为 3 集：第1集一语成谶（4 叙事单元 127s）/ 第2集连环谶言 / 第3集错位捉鳖 | 06号文档 108 条 |
| 6 | 集标题格式 `第1集 - 一语成谶`；episodes 表含 `preset_total_duration`（NULL=自动）与 `original_script_text`（该集剧本原文，Step1 剧本框展示）——**每集自带原文与时长预设** | 08/10号文档 |
| 7 | 公开实测文章口径：「Agent 对剧本做自动解析，拆成分集剧本」「自动把剧（一）集按情节切分成几个叙事单元」——长剧本上传后确有自动分集表现，但短内容以集内拆单元为主 | 向阳乔木/短剧自习室（经 AITNT 等转载） |

机制解读：

1. **短剧本（单集场景）**：用户上传后 AI 只在集内切叙事单元，不产生多集——对应 M0 主路径；
2. **长剧本（整部短剧）**：Agent 自动解析并按「剧情转折点 + 长度」切分多集（B1.1.8 描述的 P2 能力），每集再各自拆叙事单元；
3. **手动兜底**：任何时候用户可 `+新增剧集` 手动补集，为每集独立粘贴原文、命名、设时长预设——分集结果不是黑盒，集是显式可编辑的容器对象；
4. **时长是两级继承的预设而非硬公式**：集级预设（自动/1/1-2/2-3/3-5/5-10 分钟）→ 单元继承 → 单元可单独覆盖；时长预设最终作为 Tab2 分镜技能的输入（「按时长预设将剧本原文转换为分镜脚本」），**不在拆分阶段做数学估时**（对比 ToonFlow 的 4字/秒公式）。

### 9.2 拆分提示词的写法特征

LuxReal 闭源，提示词正文不可得；但产品把模板全量公开可编辑，可还原到「结构 + 槽位 + 契约」粒度：

1. **判据句 + 职责声明**（拆分粒度的核心）：官方口径「叙事单元是一集之中按场景、画面连贯性切分出的最小拍摄单元，用来统筹规划后续的资产关联、提示词撰写、视频生成」——即提示词不只说"拆成几个"，而是写清**按什么切**（场景/画面连贯性）与**切出来的东西是谁的统筹单位**；
2. **逻辑与格式双槽位**：Tab2 高级区暴露两个独立可调槽位——「生成逻辑」（怎么想）与「预期镜头格式」（输出长什么样），改格式不动逻辑、反之亦然；
3. **标记语法输出契约**：拆分输出为带固定标记的结构化剧本文本（`【场景X：地点—时间】` / `▲描述` / `角色名（动作）：台词` / `（画外音）`），前端据此渲染、用户可继续行内编辑——输出格式本身是渲染契约；
4. **时长预设作为输入参数**而非估时公式：粒度控制靠「场景判据 + 时长预设两级继承」，未见字数÷语速类数学公式；
5. **智能扩写开关**：可选把剧本原文优化为更适合视频生成的镜头描述（推荐开启）；
6. **尾部硬约束**（分镜/生成环节）：「严格按照分镜脚本进行生成，参考上传图的人物形象、场景和道具。不要生成字幕。」——一句话不可删改的全局约束。

### 9.3 剧本拆分用了几层 LLM

**结论：拆分环节本身是单次 LLM 调用（1 层）；「三层」指的是 Step3 视频制作的三个提示词技能，不属于剧本拆分。**

- **Step1 拆分 = 1 次 Lux Chat 5.2 调用**：创建项目后异步触发一个拆分任务，单次调用产出「集 → 叙事单元 → 【场景】」整棵结构（实测 4~6 单元/集、20~50s/单元），失败可整体重触发；不存在「先分集、再拆单元、再写场景」的多级 LLM 链；
- **全流程共 2 个自研 LLM**：Lux Chat 5.2（拆分 + 智能扩写 + 8 字段分镜输出）与 Lux Gem 3.0（单视频提示词润色）；资产图走 Lux Banana 2（图像模型，不算 LLM 层）；
- **容易混淆的「三层」**：分镜脚本生成技能（拍什么，Lux Chat 5.2）→ 视频任务规划技能（怎么排、参考图怎么配）→ 单视频提示词润色技能（这句话怎么写，Lux Gem 3.0）——这三个可配置技能属于 **Step3 视频制作**，是提示词流水线分层，不是剧本拆分的 LLM 分层；
- **更细的镜头层不在拆分阶段**：镜头块/镜头（5~14s/块、2~4 镜头/块）是 Step3 分镜技能对叙事单元的二次展开，Step1 只拆到叙事单元 + 场景标记。

### 9.4 对本项目分集实现的对照

| LuxReal 做法 | duanju 现状（本轮改造后） | 评价 |
|--------------|--------------------------|------|
| 集=用户容器，AI 自动分集仅 P2 | LLM 拆分 + 确定性后处理（NormalizeEpisodeCount/SplitOversizedUnits/mergeTinyEpisodes）保底分集 | 我们的后处理方案等价于其「手动建集兜底」的自动化版本，方向一致 |
| 按剧情转折点+长度分集 | minEpisodes 量化公式（总字数÷4秒 ÷ 每集时长）+ 单元边界贪心均分 | LuxReal 靠转折点语义，我们靠体量均衡；后续可在后处理中引入转折信号（场景切换点）作为下刀偏好 |
| 每集时长预设两级继承，无数学估时 | 4字/秒估时 + ≤120字/单元摘录铁律 | 我们更偏 ToonFlow 式硬约束，两者互补，无需改动 |
| 拆分单次调用出整树 | 同为单次 LLM 调用出四层结构 | 架构一致，无需引入多级 LLM 链 |
