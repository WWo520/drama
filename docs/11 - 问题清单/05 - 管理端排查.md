# 05 - 管理端排查（web-admin ↔ /admin/* 后端）

> 创建日期：2026-08-22
> 定位：排查管理端（apps/web-admin）对后端 `/admin/*` 接口的覆盖度、假数据回退风险与桩点，问题编号 A 系列。LuxReal 无公开管理端文档，本清单以"后端能力 vs 前端覆盖"自身对齐为基准。

## 二、后端已有但前端零覆盖的接口

| 接口 | 能力 | 风险 |
|------|------|------|
| `/admin/reports` | 举报列表 | 🔴 用户侧举报无处审核，合规风险 |
| `/admin/audit-logs` | 审计日志 | 🔴 管理操作无审计回溯页面 |
| `/admin/spaces` + `PUT /:id/status` | 空间列表/封禁 | 违规空间无法处置 |
| `/admin/queues`、`/admin/statistics` | 队列监控/统计 | 运营盲区 |
| `/admin/agent-skills`、`/agent-memory`、`/directive-skills`、`/think-levels` | Agent 配置管理 | 只能直连 API 改 |
| `/admin/activities`、`/categories`、`/comments`、`/courses`、`/hints`、`/languages` | 运营内容域 | S5 coverage 端点，前端未暴露 |
| `/admin/auth/permissions`、`/admin/roles` | RBAC 管理 | 角色分配只能改库 |

## 三、问题清单（A 系列）

| # | 优先级 | 问题 | 现状证据 | 建议 |
|---|--------|------|---------|------|
| A1 | 🔴 P1 | **接口失败回退假数据（管理端高危模式）** | 用户/订单/套餐/作品/任务/Dashboard 全部有 `FALLBACK_ROWS`（"李逍遥 U100001"等设计稿数据）；虽标 `real:false` 禁操作，但管理端展示假余额/假订单极易误导运营决策 | 至少资金与用户相关页面改为错误态+重试；静态回退只允许保留在纯展示卡 |
| A2 | 🔴 P1 | 举报审核页缺失 | 后端 `GET /admin/reports` 已有，前端无页面 | 新 tab 或独立页，接审核流转 |
| A3 | 🟡 P1 | 审计日志页缺失 | 后端 `GET /admin/audit-logs` 已有，前端无页面 | 合规审计必需 |
| A4 | 🟡 P2 | 空间管理页缺失 | 后端 `/admin/spaces` + 状态更新已有 | 违规空间处置能力 |
| A5 | 🟡 P2 | 任务操作桩 | "置顶"桩但后端 `PUT /tasks/:id/priority` **已存在**，纯接线；"查看/下载"桩 | 置顶直接接线 |
| A6 | 🟡 P2 | 支付配置/协议管理占位 | AdminPaymentPanel 字段齐全（含 pay_mock_enabled）但无保存通路；协议需新表 | 支付配置可复用 `PUT /admin/platform/config` 通用键值存储（纯接线）；协议管理需后端新增 |
| A7 | 🟢 P2 | Agent/运营内容域页面全缺 | agent-skills/activities/categories/comments/courses/hints/languages/statistics/queues 等 10+ 只读接口零暴露 | 按需评估：agent-skills 与 S3 团队技能共享（清单02）合并规划 |
| A8 | 🟢 P2 | GPU 利用率/节点网格为静态假数据 | TasksPage 注释明示"无后端数据源" | 接 worker 真实指标或先下线该卡 |
| A9 | 🟢 P2 | 外观定制只读 | 后端 `PUT /themes/:id`、`/style-library/:id` 已有，前端只读展示 | 纯接线 |

## 四、结论

1. **管理端整体完成度高于用户端**：核心运营面（用户/作品/审核/计费/模型/公告）已全部真数据化，模型密钥管理甚至超出设计稿。
2. **最大风险是 A1 假数据回退**——与用户端"桩"性质不同，管理端假数据是**主动误导**，资金相关页面必须优先改掉。
3. **合规两件套（A2 举报 + A3 审计日志）后端现成**，纯前端页面工作，建议与批次 A 一起排入。
