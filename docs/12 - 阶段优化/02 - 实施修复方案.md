## 阶段 12.3 一致性核心（U5 + F10 + F11 + F7）🔴 本方案最大改动

**现状事实**：`characters` 仅 `origin_episode_id`（集级），`narrative_units.linked_asset_count` 无关联表支撑，`shots` 无任何资产引用字段——三层断链。

### 新迁移（一张表解决寻址，一张表解决参考图）

```sql
-- 叙事单元 ↔ 资产链接（U5 寻址基础）
CREATE TABLE nu_asset_links (
  id BIGSERIAL PRIMARY KEY,
  narrative_unit_id BIGINT NOT NULL REFERENCES narrative_units(id) ON DELETE CASCADE,
  asset_kind asset_kind_enum NOT NULL,          -- CHARACTER/SCENE/PROP
  asset_id BIGINT NOT NULL,                      -- characters/scenes/props.id
  variant_id BIGINT NULL,                        -- 指定形象，NULL=默认形象
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  UNIQUE (narrative_unit_id, asset_kind, asset_id)
);
-- 镜头级参考图覆盖（F10；默认继承 nu 级，可镜头级覆盖）
CREATE TABLE shot_asset_refs (
  id BIGSERIAL PRIMARY KEY,
  shot_id BIGINT NOT NULL REFERENCES shots(id) ON DELETE CASCADE,
  asset_kind asset_kind_enum NOT NULL,
  asset_id BIGINT NOT NULL,
  variant_id BIGINT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  UNIQUE (shot_id, asset_kind, asset_id)
);
```

### 实施步骤
1. **U5 自动建链**：拆分完成→资产提取后，按 nu 内容中出现的角色/场景/道具名匹配写入 `nu_asset_links`；`linked_asset_count` 改为该表 COUNT 物化
2. **F10 参考图注入**：`storyboards/generate` 与 `beats/:id/generate-videos` 组装提示词时，读取 shot 级 refs（无则回退 nu 级 links）→ 取 variant 对应资产图 URL 注入"参考图"槽位；Step3 前端 chips 从占位色块改为真实资产缩略图，点击弹"替换形象"（换 variant_id）
3. **F11 单镜头重生成**：封装 `POST /shots/:id/regenerate`（内部走现有 shots/batch），Step3 镜头卡"重新生成"桩接线
4. **F7 上传替换资产图**：复用 asset engine presign → 上传 → `PATCH /characters/:id` 更新 `asset_id`
5. **验收**：同一角色跨 3 集各抽 2 镜头人工比对一致性；nu 级资产索引随机抽查 10 个单元寻址准确

## 阶段 12.4 分集精修（Q1/Q2/F4/Q4/F9/F5/F3）

### 迁移

### 接口与规则（决策点已定案，见文末）
| 项 | 新接口 | 规则 |
|----|--------|------|
| Q1 | `POST /projects/:id/episodes`（title/script_text/duration_preset_sec） | 手动集**追加到末尾**；MANUAL 集**不过确定性后处理**，直接进资产提取 |

| F9 | `POST /episodes/:id/assets/re-extract` | 复用提取管线，限定集范围 |
| F5 | Step1 设置条 4 chip 写回 `settings_json`；拆分/生成时读取 | 改设置后提示"对后续生成生效" |
| F3 | `POST /projects/:id/duplicate` | 深拷贝剧集/单元/资产元数据；生成物引用同一 S3 对象（不复制文件） |

**验收**：手动建集→拆单元→生成资产全链路可走通；单单元重拆不影响其他单元；单元行内编辑后版本号递增。

## 阶段 12.5 支付闭环（G1 + U7 + U8 + A6 + G3）

### G1 Idempotency-Key 中间件（先行，支付依赖它）
- 新建 `internal/middleware/idempotency.go`：读 `Idempotency-Key` 头 → Redis `idem:{uid}:{key}` 存响应快照（TTL 60s，对齐 LuxReal）→ 命中直接回放上次响应
- 白名单挂载：`POST /orders`、`/projects/:id/split-script`、`/assets/batch-generate`、`/exports`、支付回调
- 验收：同 Key 重复提交返回相同响应且只执行一次（并发双发测试）

### U7 微信/支付宝真实对接
- `internal/domain/billing/pay/` 新增 Provider 接口：`CreateOrder / VerifyCallback / QueryOrder / Refund`
- 实现 wxpay（Native 扫码）+ alipay（电脑网站支付）；回调验签 + 订单号幂等（叠加 G1）
- 配置存储走 `platform/config`（**A6 支付面板同步接线**，同一次完成）；`pay_mock_enabled` 在 production 启动强制校验=false
- 验收：沙箱全链路（下单→扫码→回调→积分到账）；回调重放不产生重复入账

### U8 积分充值入口
- 充值页档位读取 `GET /point-packages`（管理端 upsert 实时生效 ✅）→ 下单 → 扫码/跳转
- 与套餐订阅并列展示

### G3 积分有效期（先决策）
- 决策项：实现过期扣减（新增过期扫描 cron + POINT_EXPIRATION_DEDUCT 流水）**或**明示"积分长期有效"。建议后者起步，前者等首轮融资对账需求再做
