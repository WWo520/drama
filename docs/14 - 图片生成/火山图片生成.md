# 火山引擎（即梦）图片生成接入方案

## 概述

资产生成（CHAR_IMAGE_GEN / SCENE_IMAGE_GEN / PROP_IMAGE_GEN）接入火山引擎即梦 API，使用**异步任务模式**：POST 创建任务 → 轮询查询 → 提取结果 URL。

当前后端架构已前置支持：`async_provider.go` 实现了通用异步 Provider（兼容火山/可灵两种形态），`cmd/worker/main.go` 已注册 `volcengine` Provider，`AssetHandler` 已注入 `ModelEngine` 并调用 `GenerateImage`。管理端已具备厂商/模型/密钥 CRUD 界面。接入火山引擎只需**管理端配置**即可激活真实调用链。

---

## 1. 管理端配置

进入管理后台 → **平台配置** → **AI 模型配置** Tab，完成以下三步。

### 1.1 新增厂商

| 字段 | 值 |
|------|--------|
| **标识名** | `volcengine`（必须与 worker 注册的 Provider 名匹配，见 `cmd/worker/main.go:71`） |
| **显示名** | `火山引擎` |
| **能力** | 勾选 `T2I 文生图` + `I2I 图生图`（如需视频也勾选 `T2V` + `I2V`） |
| **Base URL** | `https://ark.cn-beijing.volces.com`（火山方舟 API 网关） |

> **Base URL 说明**：
> - 火山方舟 Ark API：`https://ark.cn-beijing.volces.com`（Workers 注册的 Provider 使用 `/api/v3/contents/generations/tasks` 端点）

### 1.2 新增模型

| 字段 | 值 |
|------|--------|
| **所属厂商** | 选择 `火山引擎` |
| **模型 Key** | 模型标识，如 `jimeng-4.0`（对应即梦 4.0 模型）或 `general-3.0`（通用 3.0） |
| **显示名称** | `即梦 4.0` |
| **能力** | `T2I 文生图` |
| **单次积分** | 建议 `10`（与 `CHARACTER_VARIANT` 默认成本一致） |

> 可根据需要新增多个模型 Key，如 `jimeng-3.0`、`jimeng-3.1` 等，Engine 按 `model_key` 匹配请求参数。

### 1.3 新增 API 密钥

| 字段 | 值 |
|------|--------|
| **所属厂商** | 选择 `火山引擎` |
| **密钥名称** | 如 `火山生产密钥1` |
| **API Key** | 从火山引擎控制台获取的 API Key（密文入库，创建后不可再查看） |
| **RPM** | 建议 `60`（火山即梦常规限速：4-20 RPM 取决于模型） |
| **QPS** | 建议 `5` |
| **并发上限** | 建议 `2`（异步任务轮询占连接，不宜过高） |
| **优先级** | `50` |

> 可新增多个密钥实现**多 Key 负载均衡与故障切换**：Engine 按 priority 顺序选取，429/5xx 自动冷却 30s 切下一个 Key。

### 2.2 详细步骤

#### 步骤 1：用户前端触发生成

用户在 [Step2 资产生成页](../../apps/web-user/src/pages/Step2Page.tsx) 点击"批量生成"或单资产"重新生成"：

```typescript
// Step2Page.tsx:694
const data = await assetsApi.batchGenerate({
  episode_id: activeEpisode,
  items: [{ kind: "CHARACTER_VARIANT", target_id: charId }],
});
```

#### 步骤 2：后端创建任务

[AssetService.BatchGenerate](../../duanju-backend/internal/domain/creation/asset_service.go#L335) 收到请求后：

1. 校验剧集归属与项目访问权限
2. 循环 items，调用 `CreateAssetTaskWithGen()` 创建 `generation_tasks` 行（状态 `QUEUED`）
3. 计费引擎 `Freeze()` 冻结积分
4. Dispatcher（Redis Outbox 扫描）将任务 ZADD 到 Redis 延迟队列

任务参数 `request_params_json` 结构：

```json
{
  "target_kind": "CHARACTER_VARIANT",
  "target_id": 42,
  "gen": {
    "prompt": "临时提示词（可选）",
    "model_code": "jimeng-4.0",
    "aspect_ratio": "R9_16",
    "resolution": "1K"
  }
}
```

#### 步骤 3：Worker 领取执行

[Worker.Run](../../duanju-backend/internal/engine/task/worker.go#L64) 循环消费：

1. `Queue.Claim()` → Redis Lua 原子取出到期任务
2. `Store.ClaimForRun()` → DB CAS：`QUEUED → RUNNING`（仅状态匹配才成功）
3. 启动心跳 goroutine（30s 续租）
4. `resolveHandler()` → 匹配到 `AssetHandler`

#### 步骤 4：AssetHandler 调用 ModelEngine

[AssetHandler.Execute](../../duanju-backend/internal/engine/agent/asset_handler.go#L83)：

1. 解析 `request_params_json` 获取 `target_kind`、`target_id`、`gen` 参数
2. `LoadAssetTarget()` 加载资产提示词（`characters.description_notes` / `scenes.base_prompt` / `props.description`）
3. 弹窗参数优先（`gen.prompt` > 资产默认提示词）
4. 调用 `h.engine.GenerateImage(ctx, model.CapT2I, &model.ImageRequest{...})`

```go
// asset_handler.go:120
resp, gerr := h.engine.GenerateImage(ctx, model.CapT2I,
    &model.ImageRequest{
        Prompt:      prompt,
        AspectRatio: aspect,     // "R9_16"
        Resolution:  resolution, // "1K"
    })
```

#### 步骤 5：ModelEngine 路由

[ModelEngine.GenerateImage](../../duanju-backend/internal/engine/model/engine.go#L82)：

1. `KeyStore.AvailableKeys(ctx, CapT2I, "")` → 查 `model_keys` 表，返回 `provider_name=volcengine` 且 `enabled=true` 的 Key 列表（按 priority 排序）
2. 查 `providers` 表获取 `base_url`，查 `models` 表获取 `model_key`
3. 匹配 Provider：`volcengine` → `AsyncTaskProvider`
4. 信号量并发控制（`acquire/release`）
5. 调用 `volcengine.GenerateImage()`

#### 步骤 6：AsyncTaskProvider 调用火山 API

[AsyncTaskProvider.GenerateImage](../../duanju-backend/internal/engine/model/async_provider.go#L77)：

**创建任务请求**：

```
POST {base_url}/api/v1/images/generations
Content-Type: application/json
Authorization: Bearer {api_key}

{
  "model": "{model_key}",     // 如 "jimeng-4.0"
  "prompt": "{生成的提示词}",
  "size": "R9_16"             // 可选：R16_9/R9_16/R1_1
}
```

火山返回：

```json
{
  "model": "{model_key}",     // 如 "jimeng-4.0"
  "prompt": "{生成的提示词}",
  "size": "R9_16"             // 可选：R16_9/R9_16/R1_1
}
```

火山返回：

```json
{
  "task_id": "xxxxxxxxx",       // ← 注意字段名为 task_id（不是 id）
  "status": "submitted"
}
```

**轮询查询**（每 5s 一次，图片超时 10min）：

```
GET {base_url}/api/v1/images/generations/{id}
Authorization: Bearer {api_key}
```

火山返回（运行中）：

```json
{
  "status": "running"
}
```

火山返回（成功）：

```json
{
  "status": "succeeded",
  "content": [
    {
      "url": "https://...生成的图片URL"
    }
  ]
}
```

火山返回（失败）：

```json
{
  "status": "failed",
  "error": {
    "code": "...",
    "message": "..."
  }
}
```

#### 步骤 7：结果入库

成功时，`AssetHandler.Execute` 调用 `SaveGeneratedImage()`：

- 事务写入 `generated_images` 表
- 更新业务表（`character_variants.main_image_url` / `scenes.main_image_url` / `props.main_image_url`）
- 写入 `asset_usage_logs`（跨集复用豁免依据）
- 返回结果 JSON：`{"image_url": "...", "target_kind": "CHARACTER_VARIANT", "target_id": 42, "is_mock": false}`

#### 步骤 8：计费结算

Worker 的 `Settler` 回调：

- 成功 → `billingEngine.Settle(taskID, deliverable=true)` → 冻结转扣费
- 失败（死信后）→ `billingEngine.Settle(taskID, deliverable=false)` → 全额解冻

#### 步骤 9：前端刷新

前端 `loadAssets()` 重新请求 `GET /episodes/:id/characters|scenes|props`，获取最新的 `main_image_url` 展示生成图片。

## 3. 火山引擎 API 详细说明

### 3.1 即梦图片生成 4.0 API

| 项目 | 说明 |
|------|--------|
| **创建任务端点** | `POST {base_url}/api/v3/contents/generations/tasks` |
| **查询任务端点** | `GET {base_url}/api/v3/contents/generations/tasks/{id}` |
| **鉴权方式** | `Authorization: Bearer {api_key}` |
| **图片超时** | 配置 10min（`ImageTimeout`），一般 30s-2min 完成 |
| **轮询间隔** | 5s |
| **可用模型** | `jimeng-4.0`（即梦4.0）、`jimeng-3.1`、`jimeng-3.0`、`general-3.0`（通用3.0） |
| **size 参数** | `R16_9`（横屏16:9）、`R9_16`（竖屏9:16）、`R1_1`（正方形） |
| **分辨率** | 模型自动决定（即梦4.0支持1K/2K输出） |

### 3.2 与现有 async_provider 的兼容性

`async_provider.go` 已内置火山格式支持：

| 特性 | 匹配状态 |
|------|----------|
| 成功状态值 `succeeded` | ✅ 在 `pollTask()` 的 switch 中处理 |
| 结果提取 `content[0].url` | ✅ 已在 `extractResultURL()` 中解析 |
| 创建任务返回 `task_id` | ✅ 已在 `createTask()` 中解析（兼容 `task_id` 与 `id`） |
| 失败状态转换为 `RetryableError` | ✅ 任务失败返回 `NewRetryableError` |
| 429/5xx 自动切换 Key | ✅ Engine 路由层已支持 |

### 3.3 各模型差异（即梦 API）

| 模型 | 说明 | 适用场景 |
|------|------|----------|
| `jimeng-4.0` | 即梦4.0，文生图能力最强 | 角色变体图（需要高质量人像） |
| `jimeng-3.1` | 即梦3.1，性价比高 | 场景图/道具图 |
| `jimeng-3.0` | 即梦3.0 | 通用 |
| `general-3.0` | 通用3.0 | 快速生成 |

> 可在管理端新增多个模型 Key，分别配置不同积分成本。前端弹窗可让用户选择模型（通过 `gen.model_code` 传入）。

## 4. 鉴权与安全说明

### 4.1 API Key 安全

- 火山 **API Key** 在管理端创建时密文入库（AES-GCM 加密）
- 运行时从 DB 加载后解密，通过 `KeyCredential.APIKey` 传入 Provider
- 加密密钥 `MODEL_KEY_ENC_SECRET` 通过环境变量注入，缺失时回退 `JWT_SECRET`（仅开发期可用）
- 管理端创建密钥后明文仅展示一次，展示后不可再查看

### 4.2 注意事项

1. **生产环境强制真实模型**：`asset_handler.go` 中 `env=production` 且 `engine==nil` 或 `prompt==""` 时直接报错，不降级 mock
2. **异步任务计费安全**：火山异步任务已提交但轮询失败时，`RetryableError` 触发的 Key 切换不会重建厂商任务（见 `async_provider.go` 08 审查 Major#17 注释），避免重复计费
3. **提示词为空**：如果资产未配置 `description_notes` / `base_prompt` / `description`，生成请求会报错，需确保剧本拆分后资产有完整描述

## 6. 故障排查

| 症状 | 原因 | 解决 |
|------|------|------|
| 资产图仍为 mock 占位图 | `model_providers` 未配置 `volcengine` 或 disabled | 检查管理端厂商配置 |
| Worker 日志 `no available key` | `model_keys` 无匹配 Key 或全部冷却 | 检查密钥配置与火山 Key 有效性 |
| Worker 日志 `task 失败: provider error 401` | API Key 无效 | 检查管理端密钥是否正确 |
| Worker 日志 `task 失败: provider error 429` | 超出 RPM/QPS 限速 | 检查限流设置或新增备用 Key |
| Worker 日志 `任务超时(10m0s)` | 火山生成超时 | 检查火山服务状态，通常 30s-2min |
| Worker 日志 `任务成功但无结果 URL` | 火山响应格式不兼容 | 检查 `extractResultURL()` 解析逻辑 |
