# 资产提示词优化方案

## 一、问题诊断

### 1.1 当前系统的提示词来源

**剧本拆分阶段** (`split_handler.go`):
```go
// 角色拆分示例：
{q: "这是一个漂亮的女生，穿着红色裙子，站在一个漂亮的房间里"}
→ 输出：
description_notes: "年轻女性，红色裙子，室内环境"

// 场景拆分示例：
{q: "豪华宴会厅"}
→ 输出：
base_prompt: "一间豪华宴会厅"

// 道具拆分示例：
{q: "手机"}
→ 输出：
description_prompt: "一部智能手机"
```

**核心问题**:
- ✗ 拆分阶段生成的提示词过于简略（通常 20-30 字）
- ✗ 缺少视觉元素的详细描述（材质、色彩、光影、工艺等）
- ✗ 没有强制要求填写结构化字段（如服装材质、时间设定）

### 1.2 与 LuxReal 的差距对比

| 维度 | LuxReal 实现 | 当前系统 | 差距 |
|------|-------------|---------|------|
| **角色描述** | "沈心怡，中国现代亚洲黄种人，富家千金，青年（23-26 岁），身形高挑；面容娇艳精致，五官锐利；浓密卷发，妆容浓艳；正红色真丝露背晚礼服，暗金刺绣..." (150+ 字) | "年轻女性，红色裙子，室内环境" (15 字) | ⚠️ **严重不足** |
| **场景描述** | "豪华宴会厅，广角镜头展现完整空间全貌，挑高极高，施华洛世奇水晶吊灯光芒流泻，意大利进口米白色大理石倒映金碧辉煌景象..." (120+ 字) | "一间豪华宴会厅" (8 字) | ⚠️ **严重不足** |
| **道具描述** | "iPhone 15 Pro Max，钛金属边框，黑色玻璃面板，6.7 英寸显示屏，三摄像头模组..." (40+ 字) | "一部智能手机" (6 字) | ⚠️ **严重不足** |

## 二、根因分析

### 2.1 LLM System Prompt 不够详细

**当前拆分指令** (`split_handler.go` 第 23 行):
```text
{"characters":[{"code":"角色编码","name":"角色名","tags":"标签逗号分隔","description_notes":"角色描述","origin_episode_id":1}]}
```
- ❌ 未指定 `description_notes` 的详细程度
- ❌ 未要求包含具体视觉元素（材质、色彩、光影等）
- ❌ 无示例参考，LLM 自由发挥空间过大

### 2.2 缺失结构化字段引导

**场景表实际有结构化字段但未利用**:
- `scenes.time_of_day_variant` (DAY_BRIGHT/DUSK/NIGHT) - 时间段
- `scenes.weather` (SUNNY/RAINY/SNOWY) - 天气
- `scenes.extra_prompt_for_variant` - 额外提示词

但生成时未将这些字段合并到 `base_prompt`:
```sql
-- 当前：仅使用 base_prompt
SELECT base_prompt FROM scenes WHERE id = $1;

-- 应改为：合并结构化字段
SELECT 
  base_prompt || 
  CASE time_of_day_variant 
    WHEN 'NIGHT' THEN '。夜晚，城市夜景灯光' 
    ELSE '' 
  END ||
  CASE weather 
    WHEN 'RAINY' THEN '。细雨朦胧' 
    ELSE '' 
  END
FROM scenes WHERE id = $1;
```

### 2.3 AI 优化功能尚未完全启用

**后端已实现** (`asset_dialog_service.go`):

- ❌ `s.llm == nil` 时的 fallback 机制只是原样返回
- ❌ 未注入真实模型引擎（生产环境需配置 OPENAI_COMPAT_BASE_URL 等）

### P1.2 提示词质量评估系统

新建服务 `internal/domain/creation/prompt_quality.go`:

```go
type PromptQuality struct {
    Score         float64  // 总分 (0-100)
    VisualElements int     // 视觉元素数量 (目标≥5)
    ClarityScore  float64  // 清晰度 (0-1)
    Specificity   int      // 具体性评分 (1-5)
    Suggestions   []string // 改进建议
}

func Evaluate(content string, kind string) *PromptQuality {
    q := &PromptQuality{}
    
    // 视觉元素检测
    elements := []string{}
    if strings.ContainsAny(content, "真丝/棉麻/皮革/丝绸/羊毛") {
        elements = append(elements, "材质")
    }
    if strings.ContainsAny(content, "红/蓝/绿/黄/黑/白/金/银") {
        elements = append(elements, "色彩")
    }
    if strings.ContainsAny(content, "光/影/亮/暗/明/暗") {
        elements = append(elements, "光影")
    }
    if strings.ContainsAny(content, "厘米/m/cm/mm") {
        elements = append(elements, "尺寸")
    }
    q.VisualElements = len(elements)
    
    // 长度评分 (基础分 40)
    length := float64(len(content))
    switch {
    case kind == "CHARACTER" && length >= 80:
        q.Score += 40
    case kind == "SCENE" && length >= 100:
        q.Score += 40
    case kind == "PROP" && length >= 40:
        q.Score += 40
    default:
        q.Score += length / 2 // 线性加分
    }
    
    // 清晰度：避免模糊词
    vagueWords := []string{"漂亮", "豪华", "好看", "很", "非常", "特别"}
    vagueCount := 0
    for _, word := range vagueWords {
        if strings.Contains(content, word) {
            vagueCount++
        }
    }
    q.ClarityScore = float64(10-vagueCount) / 10
    
    // 生成改进建议
    if q.VisualElements < 3 {
        q.Suggestions = append(q.Suggestions, "增加材质、色彩、光影等视觉元素描述")
    }
    if q.ClarityScore < 0.8 {
        q.Suggestions = append(q.Suggestions, "替换空泛形容词为具体视觉元素")
    }
    if length < minLength(kind) {
        q.Suggestions = append(q.Suggestions, fmt.Sprintf("扩展描述至%d字以上", minLength(kind)))
    }
    
    q.Score = q.Score * q.ClarityScore * float64(q.VisualElements) / 5
    if q.Score > 100 {
        q.Score = 100
    }
    
    return q
}

func minLength(kind string) int {
    switch kind {
    case "CHARACTER":
        return 80
    case "SCENE":
        return 100
    case "PROP":
        return 40
    default:
        return 50
    }
}
```

## 六、风险与挑战

### 6.1 技术风险

- ⚠️ **API 成本**: AI 优化每次调用约$0.01，假设百万次调用=$10000
  - 对策：仅对主动优化的用户收费，或限制每日免费次数
  
- ⚠️ **响应延迟**: LLM 调用增加 2-5 秒等待
  - 对策：异步优化（用户点击后立即提交后台队列，完成后通知）
  
- ⚠️ **质量波动**: 不同模型输出的稳定性
  - 对策：温度设为 0.3-0.5，固定 temperature=0.5

### 6.2 用户体验风险

- ⚠️ **过长提示词**: 可能超出某些模型的 token 限制
  - 对策：设置最大长度截断（角色≤300 字，场景≤400 字，道具≤150 字）
  
- ⚠️ **过度拟合**: 模板导致创意受限
  - 对策：允许用户完全自定义，模板仅作为 AI 优化的参考
