# 排查结论（先说答案）

**Mock 图片产生的确切原因：管理端配置的厂商"标识名"是中文 `火山`，而 Worker 代码注册的火山引擎 Provider 名是英文 `volcengine`。模型路由引擎按 `model_providers.name` 精确匹配 Provider 失败后，回退到 `openai-compat`（一个只支持 LLM 的 Provider），其 `GenerateImage` 直接返回"不支持图片生成"错误；该错误传回 `AssetHandler` 后，非生产环境分支触发 mock 降级，生成 `asset-placeholder.png` 占位图。**

关键证据：`d:\develop\a_work\duanju\test-volcano-image-generation.md` 第 8-9 行明确记录用户配置 `Provider Name: 火山`；而 `d:\develop\a_work\duanju\duanju-backend\cmd\worker\main.go` 第 75 行注册名为 `"volcengine"`。管理端表单（`AdminModelsTab.tsx` 第 611-619 行）虽然提示"标识名（英文短名，创建后不可改）、如 openai / volcengine"，但没有强制校验，用户填了中文，且创建后不可修改。
