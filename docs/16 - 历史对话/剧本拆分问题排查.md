## 总体判断：流程"线性程度"

### 硬阻塞环节（前后端双重门控）
| 边界 | 阻塞条件 | 证据 |
|---|---|---|
| Step1→Step2 | 拆分必须成功（PARTIAL_ASSETS） | useStepState L26；split_store.go L199 |
| Step2→Step3 | **前端要求资产全部就绪（ALL_ASSETS_READY）** | useStepState L28-29（不含 PARTIAL_ASSETS）+ Step3Page L927-941 遮罩 |
| Step3→Step4 | 全部镜头 SUCCESS（ALL_VIDEOS_READY） | video_store.go L150-163 + useStepState L30 |
| 导出触发 | ALL_VIDEOS_READY / PARTIAL_VIDEOS / COMPLETED | Step4Page L39 + 后端 export_service 守卫 |

### 实际可并行的环节
1. **资产生成完全非阻塞**：单个/分类批量/部分生成/失败重试自由组合，单个资产失败不影响其他资产推进（CheckAssetsReady 只在"全部就绪"那一刻转移状态）
2. **视频生成为 beat（叙事单元）粒度分批**：GenerateVideos 按单元提交、非 SUCCESS 镜头逐个建任务，单元间可先后进行；PARTIAL_VIDEOS 允许只重试失败镜头
3. **参考图缺失不阻断视频生成**：SQL 层过滤空 URL + handler 层 `refURLs = nil` 降级，无参考图的镜头照样能出视频（纯文生视频）
4. **后端保留"部分资产开视频"通道**：PARTIAL_ASSETS → VIDEO_GENERATING 在状态机（state.go L57）、任务创建（repo.go L399-404）、幂等推进（video_store.go L142-148）三处均支持——只是被前端 UI 封锁，直调 API 可启用
5. **PARTIAL_VIDEOS 可导出**：未全部完成也允许合成成片
6. **任意回退**：Step1 永远可回；PARTIAL_ASSETS/ALL_ASSETS_READY 均可 force 重新拆分（service.go L224-229）；版本回滚可从视频阶段退回资产阶段

### 核心矛盾点（值得关注）
前后端对"Step3 门槛"的定义不一致：后端状态机与 API 均允许 PARTIAL_ASSETS 直接触发视频生成（设计意图见 state.go L57 注释"可直接进 Step3（部分资产可用时）"），但前端 `STEP_UNLOCK[3]` 收紧为 ALL_ASSETS_READY，且 Step3Page 有整页遮罩兜底。**当前实际生效的是前端的严格线性门控**；若产品要放开"边生成资产边出视频"，前端只需把 PARTIAL_ASSETS 加入 STEP_UNLOCK[3] 并移除遮罩即可，后端无需改动。另注意 repo 层部分转移（video_store/asset_store 的直接 SQL UPDATE）绕过了 state.go 的 ValidateTransition 单一真源，存在双轨维护风险（如版本回滚 PARTIAL_VIDEOS→PARTIAL_ASSETS 在 state.go 转移表中并无此边）。

## 三、视频制作环节（Step3）

**实测证据（最重要）**：即使在 **Step2 资产尚未生成图片** 的状态下，`/storyboard` 页**完全可达**，且第 1 集 4 个叙事单元各自独立展示一个"生成分镜脚本"的完整工作卡：

```
叙事单元1 异常的存储助手
  脚本生成阶段 待生成
  关联资产  办公 我 办公 1 +      ← 按名称引用 + 数量占位
  自动        历史            生成分镜脚本
  剧本原文 …
叙事单元2 …  关联资产 我 办公 茶水 2 +
叙事单元3 …  关联资产 仓鼠 我 老板 4 +
叙事单元4 …  关联资产 我 办公 仓鼠 3 +
Agent 技能配置  生成分镜脚本 (4)
```

**关键结论：**
- **"关联资产"是名称引用占位**，不是图片实体的强依赖。每个单元展示它引用了哪些资产（角色/道具的**名称 + 数量**），即使这些资产**还没有生成图片**也能正常显示并进入分镜脚本生成。
- **分镜脚本以叙事单元为粒度独立生成**——每个单元有自己的"生成分镜脚本"按钮、时长、历史版本。**单单元可重跑/回滚**，不会因某一单元资产未就绪而阻塞其他单元。
- 参考图是**运行时绑定**的：`@资产` 或自然语言自动匹配；"替换任一参考图会自动同步到下一轮视频制作流程"（资产联动）。

**三层提示词流水线**（来自既有文档 §5.1）：分镜脚本生成（拍什么）→ 视频任务规划（怎么排、参考图怎么配）→ 单视频提示词润色（怎么写），三技能正交、各自独立配模板与模型。**8 字段镜头契约** + **尾部全局硬约束**。

## 四、成片预览环节（Step4）

**实测证据**：`/preview` 页**同样可达**，左侧为叙事单元导航，右侧主区显示"**暂未生成完整视频**"占位文案 + `去生成` 按钮（跳转到生成）。

**实施方式**（结合既有文档 §6）：
- **镜头块时间线**：13 个镜头块缩略卡（带时长徽章），每块独立时间刻度播放器（整集分解为多个可单独预览的片段）。
- **素材与时间线分离导出**：`合成视频`（MP4）与 `导出工程文件`（XML 时间线 + Media 素材文件夹），交付给剪辑软件继续编辑。
- **版本管理**：分镜脚本历史版本可回滚。
- **降级策略**：无成片时显示占位 + 引导生成，而不是报错或封锁。

## 五、核心对比：LuxReal 的平行可达 vs 我方严格线性

这是用户最关心的部分。把三方资料对齐后，差异**不是我方没有"部分资产生成"能力，而是门控层级放错了位置**。

### 5.1 LuxReal：全步骤平行导航 + 单元级占位

| 维度 | LuxReal 做法 |
|------|-------------|
| **步骤可达性** | 四步 StepBar **任何时候都可见、可点**，无前置状态硬门控 |
| **原子单位** | **叙事单元**是管线原子单位，一步推进以"单元"为单位而非"整项目" |
| **跨步依赖** | 资产用**名称引用占位**，视频制作用**参考图运行时绑定**，图片未生成不阻塞 |
| **未就绪表现** | 优雅占位：Step4 显示"暂未生成完整视频"+去生成；Step3 显示"待生成"+生成分镜脚本 |
| **重跑粒度** | 单单元重规划/回滚，不级联清空兄弟单元 |
| **并行浏览** | 四步页可来回切换、逐集/逐单元展开、跨集查看资产 |

### 5.2 我方 duanju：前后端门控断层（现状）

| 层 | 现状 | 问题 |
|----|------|------|
| **前端** `useStepState.ts` | `STEP_UNLOCK`：Step3 视频制作**不含 `PARTIAL_ASSETS`**，`Step3Page.tsx` L927-941 整页遮罩"视频制作尚未解锁" | **前端严格线性**：`PARTIAL_ASSETS` 时无法进入 Step3 |
| **后端** `state.go` L57 | 允许 `StatusPartialAssets → StatusVideoGenerating`（"可直接进 Step3（部分资产可用时）"） | **后端双轨设计**：支持部分资产开视频 |
| **数据层** `video_store.go` | `LoadShotRefs` 两级 SQL 都带 `main_image_url IS NOT NULL AND != ''` 过滤；`video_handler.go` L85-90 参考图加载失败 → `refURLs=nil` 降级 | 已支持"无参考图降级" |
| **前端 Step4** | 跳过未完成镜头（**过滤而非占位**） | 无占位，直接少镜头 |

**核心矛盾**：**后端已经支持"部分资产 → 视频制作"，前端 UI 却按严格线性把 Step3 锁死**。这不是能力缺失，是**门控不一致**——实际生效的是前端严格线性，导致后端双轨能力被浪费，正如你此前遇到"卡在 SCRIPT_SPLITTING""资产生成只完成部分单元就进不了视频"类问题的根因。

## 六、你问的关键场景：资产仅完成部分叙事单元时，视频制作如何继续

### LuxReal 的三件套方案（已实测验证）

1. **资源占位（Reference Placeholder）**：视频制作页每个叙事单元展示"关联资产"时为**名称 + 数量**引用（如 `关联资产 仓鼠 我 老板 4 +`），而非必须存在的图片 URL。图片是**后续运行时才有**的可选增强项，不是 Step3 的前置强依赖。→ 对应我方应改为：`关联资产`按单元映射**资产 ID/名称**展示，而非要求图片已生成。

2. **部分渲染/按单元推进（Per-Unit Independent Progress）**：分镜脚本、视频任务、成片都**以叙事单元为粒度**独立生成。某单元资产未好，该单元先占位"待生成"，**其他单元的"生成分镜脚本"仍可点**。→ 对应我方应改为：Step3 门控从"整项目 `ALL_ASSETS_READY`"放宽到"**可进入，按单元判断是否可生成**"。

3. **动态更新（Runtime Asset Binding / 资产联动）**：参考图在生成时绑定（`@资产` 或自然语言匹配），"替换任一参考图会自动同步到下一轮视频制作流程"。资产后补生成后，**自动进入后续流程**，无需用户重走。→ 对应我方应改为：资产生成完成的事件回调去更新对应单元/镜头的参考图状态，实现"补图后自动可生成"。

### 我方建议的最小改动路径（对齐 LuxReal，不动架构）

| 优先级 | 改动 | 位置 |
|--------|------|------|
| P0 | 前端 `STEP_UNLOCK`：让 Step3 解锁条件加入 `PARTIAL_ASSETS`；移除 `Step3Page.tsx` 整页遮罩，改为**逐单元**"待资产就绪"提示 | `useStepState.ts` + `Step3Page.tsx` |
| P0 | Step3 页"关联资产"改为按单元展示**资产名称+数量占位**（复用现有「集→资产」映射），而非空引用 | `Step3Page.tsx` |
| P1 | 资产生成事件回写对应单元参考图状态，实现"补图自动可生成"（对齐 LuxReal 资产联动） | video_handler / dispatch 事件 |
| P1 | 镜头级参考图缺失时前端显示占位而不是静默跳过（对齐 LuxReal 优雅降级，取代"Step4 过滤跳过"） | Step4 |

## 七、结语

**你要的答案**：LuxReal **确实做到了"剧本拆分完成后，即使只生成部分叙事单元资产，视频制作和成片预览也能正常进行"**。手段不是"等全部资产就绪"，而是把**叙事单元设为管线原子单位**，用**名称引用占位（关联资产）+ 单元级独立生成 + 运行时参考图绑定/资产联动**三件套，把"部分资产"变成"该单元先占位、其他单元照常推进、补图后自动可生成"。

我方**后端已具备**部分能力（`state.go` L57 + `LoadShotRefs` 空 URL 过滤 + `video_handler` 降级），**真正缺口在前端门控**（`USE_STEP`/`Step3Page` 把 `PARTIAL_ASSETS` 锁死）。**改动方向是把前端门控与后端双轨对齐**，而非新增引擎能力。这与 Phase 1 修复"脚本拆分时好时坏"是同一个问题的两个不同侧面——管线要能在"未完全就绪"时仍可推进。
