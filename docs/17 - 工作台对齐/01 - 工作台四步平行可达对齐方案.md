# 工作台四步平行可达对齐方案（对齐 LuxReal）

> **目标**：对齐 LuxReal 工作台的"四步全阶段平行可达 + 未就绪优雅降级"体验，替换我方当前的"严格线性步骤门控"。
>
> **核心问题**：LuxReal 剧本拆分（含资产提取）完成后即可自由浏览资产 / 视频制作 / 成片预览 3 个页面；我方必须 `ALL_ASSETS_READY` 才能进 Step3、`ALL_VIDEOS_READY` 才能进 Step4，一步一步线性推进。

---

## 一、LuxReal 实测行为基线（对齐标准）

来源：`docs/16 - 历史对话/剧本拆分问题排查.md` 第二段调研（项目 3FO4K57R875D《逃离云端的人》浏览器实地采集）+ `docs/10 - 剧本skills/02 - LuxReal全流程执行过程与提示词调查报告.md`。

| 维度 | LuxReal 行为 |
|---|---|
| 步骤可达性 | StepBar 四步**任何时候都可见、可点**，无前置状态硬门控 |
| 原子单位 | **叙事单元**是管线原子单位，推进以"单元"为单位而非"整项目" |
| 跨步依赖 | 资产用**名称引用占位**（`关联资产 仓鼠 我 老板 4 +`），图片未生成不阻塞分镜/视频 |
| 未就绪表现 | 优雅占位 + 引导 CTA：Step4 "暂未生成完整视频" + `去生成`；Step3 "脚本生成阶段 待生成" + `生成分镜脚本` |
| 重跑粒度 | 单单元重规划/回滚，不级联阻塞兄弟单元 |
| 实测场景 | **资产未出图时 `/storyboard` 完全可达**，每单元独立展示关联资产占位并可直接生成分镜脚本 |

## 二、我方现状与差距（代码证据）

### 2.1 前端门控：严格线性（当前实际生效）

**`apps/web-user/src/hooks/useStepState.ts`**：

```
STEP_UNLOCK = {
  1: ["*"],                                          // Step1 永远可回
  2: [PARTIAL_ASSETS 起的全部后置状态],                // 拆分成功才可进
  3: [ALL_ASSETS_READY 起的全部后置状态],              // ★ 不含 PARTIAL_ASSETS
  4: [ALL_VIDEOS_READY 起的全部后置状态],              // ★ 视频全部完成才可进

```

- `canClick`（L54-58）按上表判定；`goStep`（L60-63）未解锁**静默 return**，无任何提示。
- `WorkbenchShell.tsx` L131-132：未解锁步骤 `disabled` 样式 + 不可点击。

**`Step3Page.tsx` L927-941**：第二层整页遮罩兜底——`!canClick(3)` 时全屏遮罩"视频制作尚未解锁，请先在 Step2 完成全部资产生成"，堵住了 URL 直达的后门。

### 2.2 后端：早已支持部分推进（双轨能力被前端浪费）

| 能力 | 代码证据 |
|---|---|
| `PARTIAL_ASSETS → VIDEO_GENERATING` | `duanju-backend/internal/domain/creation/state.go` L57（注释："可直接进 Step3（部分资产可用时）"） |
| 任务创建含 PARTIAL_ASSETS | `repo.go` L398-405：`WHERE status IN ('PARTIAL_ASSETS','ALL_ASSETS_READY')` |
| 参考图缺失自动降级 | `video_store.go` LoadShotRefs 两级 SQL 过滤空 `main_image_url`；`video_handler.go` L85-90 加载失败 `refURLs=nil` 继续纯文生视频 |
| 部分视频可导出 | Step4 `canExport` 含 `PARTIAL_VIDEOS`，对齐后端 export_service 守卫 |

### 2.3 差距总结

| 环节 | LuxReal | 我方现状 |
|---|---|---|
| 拆分完成后浏览 Step3 | ✅ 直接可进，单元级占位 | ❌ 需 `ALL_ASSETS_READY`（遮罩拦截） |
| 拆分完成后浏览 Step4 | ✅ 可进，"暂未生成"占位 + 去生成 | ❌ 需 `ALL_VIDEOS_READY` |
| Step3 关联资产展示 | 名称 + 数量引用占位 | 假渐变色 chips（"视觉保真占位"，无数据） |
| 未解锁点击反馈 | 无此概念（全可点） | 静默拦截 / 整页遮罩 |

**结论**：这不是能力缺失，是**门控层级放错**——把"步骤级硬门控"改为"页面内优雅降级 + 操作级（单元级）软门控"，后端几乎无需改动。

## 三、对齐目标与设计原则

### 3.1 目标体验（与 LuxReal 高度一致）

1. **四步永远可见、可点**：项目进入工作台后，StepBar 四步无 disabled 态（当前步骤高亮除外）。
2. **未就绪 = 占位 + 引导，不是封锁**：
   - Step2 在 DRAFT（未拆分）：空态引导"先完成剧本拆分，资产将自动提取"+ CTA 跳 Step1。
   - Step3 在资产未就绪：可自由浏览分镜结构，关联资产显示**名称占位**；单元级生成按钮按该单元资产就绪度给出提示（仍允许生成，走纯文生视频降级，对齐后端能力）。
   - Step4 在视频未完成：占位"暂未生成完整视频"+ `去生成` CTA 跳 Step3。
3. **门控下沉到操作级**：真正的约束放在"生成/导出"等按钮的语义上（如未拆分不能生成资产、无任何完成镜头不能导出），而不是页面入口上。
4. **自动跟随保留**：后端状态推进时，若用户未手动切换过步骤，当前步骤仍自动跟随（保留现有 `useStepState` 的 A.5 行为）。

### 3.2 设计原则

- **后端零改动优先**：利用既有双轨能力（state.go L57、LoadShotRefs 降级、PARTIAL_VIDEOS 可导出），本次只动前端。
- **渐进式披露**：页面可达 ≠ 功能全开；未就绪时功能按钮给出明确原因提示（ LuxReal 的"待生成"标记）。
- **不破坏既有状态机语义**：`STATUS_TO_STEP` 映射、WS 推送、状态轮询逻辑全部保留。

## 四、详细改动方案

### 4.1 P0-1：`useStepState.ts` 门控全开

**文件**：`apps/web-user/src/hooks/useStepState.ts`

**改动**：

```ts
// 对齐 LuxReal：四步全阶段平行可达，未就绪由页面内优雅降级处理
const STEP_UNLOCK: Record<number, string[]> = {
  1: ["*"],
  2: ["*"],
  3: ["*"],
  4: ["*"],
};
```

- `canClick` 对任意 step 返回 true（status 为 null 即项目未加载完成时，维持不可点防止闪烁）。
- `goStep` 不再拦截，直接导航。
- **保留** `STATUS_TO_STEP` 与自动跟随 effect（L66-70），后端状态推进时无手动路由仍自动跟随。
- **语义调整**：`STEP_UNLOCK` 表若担心未来需要回收，可保留表结构但值全为 `["*"]`；更彻底的做法是删除表、简化 `canClick` 为 `() => status !== null`。**推荐后者**（避免死代码），但保留 hook 对外接口不变（`canClick/goStep/backendStep/currentStep`），调用方零改动。

### 4.2 P0-2：移除 Step3Page 整页遮罩，改为页面内降级

**文件**：`apps/web-user/src/pages/Step3Page.tsx` L926-941

**改动**：删除整页遮罩块，替换为两档页面内状态：

1. **未拆分（DRAFT / SCRIPT_SPLITTING / SCRIPT_SPLIT_FAILED / CANCELLED）**：
   主区渲染空态引导卡（复用遮罩卡的视觉，但非全屏、可离开）：
   - 文案："完成剧本拆分后，可在此按叙事单元生成分镜与视频"
   - 按钮 `前往剧本拆分` → `goStep(1)`
2. **已拆分（PARTIAL_ASSETS 及之后）**：正常渲染页面（现有逻辑不变）。数据加载本身依赖拆分产物，天然安全。

> 注意：Step3Page 现有数据流以"集 + 叙事单元"为骨架，未拆分时列表为空，需在空列表分支处理引导态，避免渲染空壳。

### 4.3 P0-3：Step4Page 解锁浏览 + 保留导出门控

**文件**：`apps/web-user/src/pages/Step4Page.tsx`

**现状**：已有优雅占位（L601-607 "完成 Step3 视频生成后可预览成片"），但入口被 `STEP_UNLOCK[4]` 锁死，用户根本看不到这个占位。

**改动**：
- 入口放开后（P0-1），现有占位即生效，仅需把占位文案区加一个 `去生成` CTA 按钮 → `goStep(3)`（对齐 LuxReal preview 页的 `去生成`）。
- `canExport` 与合成按钮 `disabled` 逻辑**保持不变**（`ALL_VIDEOS_READY / PARTIAL_VIDEOS / COMPLETED` 才可导出）——这是操作级门控，继续生效。

### 4.4 P0-4：Step2Page DRAFT 空态引导

**文件**：`apps/web-user/src/pages/Step2Page.tsx`

**改动**：DRAFT 等未拆分状态进入时，主区渲染空态引导：
- 文案："剧本拆分完成后，将自动提取角色 / 场景 / 道具资产"
- 按钮 `前往剧本拆分` → `goStep(1)`
- 已拆分状态（PARTIAL_ASSETS 起）行为不变（现有部分生成/单个重试已完备）。

### 4.5 P1-1：Step3 关联资产改为真实名称占位（对齐 LuxReal"关联资产"）

**文件**：`apps/web-user/src/pages/Step3Page.tsx`（ShotCard L78-79 假渐变 chips、L139-147 chips 区）

**改动**：
- 数据源：单镜头详情已返回 `reference_images / linked_assets`（`storyboard_service.go` L245-253），前端把假渐变 chips 替换为**按名称 + 类型角标**的占位 chips：
  - 已就绪资产（有 main_image_url）：显示缩略图。
  - 未就绪资产：显示名称首字/类型图标的占位块 + "待生成"角标（对齐 LuxReal `关联资产 仓鼠 我 老板 4 +` 的名称引用语义）。
- 点击 chips：toast 升级为"跳转到该资产（Step2）"或保留"后续版本开放"，**推荐前者**（跨步联动，强化平行工作台心智）。

### 4.6 P1-2：单元级生成按钮的资产就绪提示（软门控）

**文件**：`apps/web-user/src/pages/Step3Page.tsx`（单元级"生成视频"按钮 L748 附近）

- 增加**单元级就绪度徽标**：本单元关联资产 `n/m 已就绪`；未全就绪时生成前 toast 确认："本单元有 X 个资产未生成参考图，将使用纯文生视频模式，是否继续？"——对齐后端 LoadShotRefs 降级行为，让用户知情。
- 后端 `GenerateVideos` 在 PARTIAL_ASSETS 下已可建任务（repo.go L399-404），**无需后端改动**。

### 4.7 P1-3：WorkbenchShell 步骤条视觉对齐

**文件**：`apps/web-user/src/layouts/WorkbenchShell.tsx` L129-139

**改动**：
- `canClick` 全 true 后 disabled 分支自然失效；顺手移除 `disabled` class 的死样式（或保留 class 定义不动，仅不再触发）。
- 对齐 LuxReal：当前步骤高亮、已完成步骤带 ✓、其余步骤正常可点（若现有样式已有 ✓ 逻辑则零改动）。

## 七、结论

我方后端自第一天起就为"部分资产开视频"预留了完整通道（state.go 注释原文："可直接进 Step3（部分资产可用时）"），只是被前端 `STEP_UNLOCK` + 整页遮罩锁死。本方案以**前端 7 处改动、后端零改动**实现与 LuxReal 高度一致的工作台体验：

> **步骤级硬门控 → 页面内优雅降级 + 操作级软门控；叙事单元为原子单位，未就绪资产名称占位、补图自动可用。**
