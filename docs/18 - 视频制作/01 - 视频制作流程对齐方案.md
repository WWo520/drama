# 视频制作流程对齐方案（LuxReal vs 本系统）

> 目标流程（对齐基准）：
> 1. 根据原文（叙事单元剧本）进行提示词生成分镜脚本；
> 2. 根据分镜脚本生成分镜镜头视频，且参考图引用前面的资产（角色/场景形象图）。
>
> 排查时间：2026-08-25。排查范围：LuxReal 参考文档（00-参考文档/02-luxreal、10-剧本skills、11-问题清单）+ 当前代码库（duanju-backend、apps/web-user）。

---

## 一、LuxReal 视频制作的实际流程

LuxReal 采用**三层正交提示词流水线**，视频制作为工作台 Step3（路由 `/storyboard`）：

```
叙事单元剧本原文 + 时长预设（集级→单元级两级继承）
   │  ① 分镜脚本生成技能（Lux Chat 5.2，模板「剧情细腻刻画」，智能扩写开关）
   ▼
8 字段分镜脚本（镜头1..N，支持历史版本回滚、单叙事单元重跑）
   │  ② 视频任务规划技能（模板「剧情连贯编排」，智能镜头 Pro/Fast）
   ▼
多个视频生成任务（每任务 = 润色后提示词 + 参考图集）
   │  ③ 单视频提示词润色技能（Lux Gem 3.0，模板「通用模板」）
   ▼
送入视频模型（Seedance/Kling）生成 → 镜头块拼接 → Step4 合成
```

### 1.1 分镜脚本的生成（①）

- **输入**：叙事单元剧本原文 + 时长预设（每集 4~6 个叙事单元，单单元 20~50s）。
- **输出契约：8 字段镜头格式**（每个镜头强制包含）：

| 字段 | 典型取值 |
|------|---------|
| 【时长】 | 2s / 3s / 4s / 5s / 9s |
| 【景别】 | 特写 / 近景 / 中景 / 全景 / 远景 |
| 【运镜】 | 固定 / 慢慢推进 / 横移跟拍 / 升镜头 |
| 【视角】 | 平视 / 微仰拍 / 俯拍 / 过肩 等 9 种 |
| 【主体】 | 画面核心描述，含人物动作/表情/道具互动 |
| 【背景】 | 环境场景名 |
| 【台词】 | `【角色名 情感修饰】：台词` 等 5 种格式 |
| 【环境音】 | 音效设计 |

- **尾部全局约束指令**（Agent 自动追加、不可删改）：
  > "严格按照分镜脚本进行生成，参考上传图的人物形象、场景和道具。不要生成字幕。"
- **五级数据模型**：`项目 → 集 → 叙事单元 Beat → 镜头块 HeroShotGroup（5~14s，每集约13块）→ 镜头 Shot（每块 2~4 个，单镜头 2~9s）`。

### 1.2 分镜镜头的生成与资产引用（②③）

- **资产引用双模式**：
  - 精准模式：`@` 显式指定素材用途（如 `@陆言-市井说书装`）；
  - 简化模式：自然语言提到角色名/场景名即自动匹配（"不用@资产，描述即可生效"）。
- **参考图拖拽绑定**：每个分镜卡有可拖拽参考图区域，可拖入资产图或 @引用标签。
- **资产联动**：替换任一参考图自动同步到下一轮视频生成。
- **智能镜头（预演-审核-生成）**：先基于整集剧本生成几秒排演视频锁定人物与空间关系 → 用户审核 → 从排演视频抽帧作为参考图补进每个镜头提示词 → 再生成完整视频。参考图上限：Pro ≤9 张、Fast ≤10 张。
- **生成粒度**：单镜头 / 镜头块批量（「全部生成」）/ 整集；块内镜头全部 SUCCESS 后「拼接成段」。

### 1.3 LuxReal Step3 关键 API（接口文档 v1.0）

| 接口 | 说明 |
|------|------|
| `POST /episodes/{id}/step3/plan-storyboard` | 触发分镜规划（beats→shot_groups→shots），返回 task_uuid + ws_room |
| `POST /shots/{id}/generate-video` | 单镜头生成；**镜头未绑定引用图返回 400 code=6002**（引导回 Step2） |
| `POST /shot-groups/{id}/generate-all-shots` | 块内批量顺序生成，同块保持 seed 连续 |
| `POST /shot-groups/{id}/concat` | 块拼接（FFmpeg copy，<5s）；块内有未 SUCCESS 镜头返回 409 code=6003 |
| `GET /episodes/{id}/step3/summary` | "X/Y 镜头已完成"总览 |

## 二、本系统当前实现现状

### 2.1 当前链路总览

```
剧本（projects.source_script_text）
  │  ① SCRIPT_SPLIT（SplitHandler，单次 LLM 调用）
  │     一次性产出四层结构：episodes → narrative_units → shot_groups → shots
  │     + 集级资产 characters/scenes/props（含 AI 扩写提示词）
  │     + 逐镜头润色出 prompt_refined（内联完成，非独立技能）
  ▼
  ② Step2 资产生成（AssetHandler）→ assets.main_image_url
  ▼
  ③ Step3：POST /beats/:id/generate-videos（单元级批量）
  │     每个非 SUCCESS 镜头创建 VIDEO_SEGMENT_GEN 任务
  │     Worker: VideoHandler → LoadShotRefs（恒为空，见 2.2#2）
  │     → ModelEngine.GenerateVideo（实际纯 T2V）→ shots.generated_video_url
  ▼
  ④ Step4：前端连播 + FINAL_VIDEO_COMPOSE 导出合成
```

**核心事实：分镜（shots）不是独立生成阶段，而是 SCRIPT_SPLIT 拆分时一次性产出；"根据原文生成分镜脚本"这一环节在当前系统中实际不存在独立落地。**

### 2.2 关键代码位置

| 模块 | 文件 | 现状 |
|------|------|------|

| 生成分镜端点 | `internal/domain/creation/storyboard_service.go` | `GenerateStoryboards`（L192）为**幂等 mock**：只 COUNT 现有 shots 返回 `is_mock:true` |
| 视频生成入口 | `internal/domain/creation/service.go` | `GenerateVideos`（L270）单元级批量；`RegenerateShot`（L346）单镜头重生成（后端有、前端未接） |
| 任务创建 | `internal/domain/creation/repo.go` | `CreateVideoTasks`（L363）：INSERT VIDEO_SEGMENT_GEN + outbox（queue='video'） |

| 前端 Step4 | `apps/web-user/src/pages/Step4Page.tsx` | 跨单元展平 SUCCESS 镜头连播 + 合成导出；已可用 |

### 2.3 任务类型现状（task_type_enum）

| 类型 | 状态 |
|------|------|
| SCRIPT_SPLIT / CHAR·SCENE·PROP_IMAGE_GEN / VIDEO_SEGMENT_GEN / FINAL_VIDEO_COMPOSE | ✅ 已实现且走 outbox→Redis 派发 |
| STORYBOARD_PLAN_V1_LUXCHAT | ⚠️ 仅枚举定义，无 handler、无创建入口（**可作独立分镜生成阶段的落地点**） |

## 三、差距清单（按目标两步流程对照）

### 目标步骤 1：根据原文生成分镜脚本

| # | 差距 | 说明 |
|---|------|------|
| G1 | 无独立分镜脚本生成阶段 | 分镜由 SCRIPT_SPLIT 一次性直出（拆分 prompt 内嵌 shot 结构）。`GenerateStoryboards` 为 mock；`STORYBOARD_PLAN_V1_LUXCHAT` 枚举已定义但零实现。LuxReal 是"拆分→剧本"与"剧本→分镜"两个独立技能，各自可配模板、可单独重跑 |
| G2 | 无分镜历史版本与重跑 | `narrative_unit_versions` 快照表已有且支持回滚（前端"历史版本"已接），但"重新规划"（BEAT_REPLAN）为枚举外 mock，重跑链路不通 |
| G3 | 8 字段已对齐但无尾部全局约束指令 | shots 表已有 shot_size/camera_movement/camera_angle/subject/background/light/dialogue/ambient_sound 八字段；缺 LuxReal 的"严格按脚本生成、参考上传图、禁字幕"尾部硬约束注入视频 prompt |

### 目标步骤 2：根据分镜脚本生成镜头视频 + 引用资产参考图

| # | 差距 | 说明 |
|---|------|------|
| G4 | **资产↔镜头建链完全断裂（最关键）** | `nu_asset_links` / `shot_asset_refs` 全库无写入方；拆分时资产按"集"抽取（origin_episode_id），从不关联叙事单元/镜头；shots.linked_assets_json 也不写。导致 `LoadShotRefs` 恒返回空，视频生成实际永远是纯 T2V。前端"相关镜头将使用纯文生视频降级"文案即为此兜底 |
| G5 | **多参考图传参断点** | `AsyncTaskProvider.GenerateVideo` 只转发单张 `RefImageURL`（image_url 首帧），`RefImageURLs` 列表被忽略。即使 G4 补齐数据，多参考图也到不了厂商 API |
| G6 | 镜头级操作为占位/mock | 单镜头"生成视频"前端按钮未接（后端 `RegenerateShot` 已有）；镜头块拼接 VIDEO_GROUP_CONCAT 创建入口不投递 outbox |
| G7 | 生成参数未落库 | 弹窗中模型（Seedance 2.5/2.0/1.5）/分辨率/帧率纯 UI 不提交；shots.ai_model 闲置；VideoHandler 硬编码 Resolution="P720" |
| G8 | 分镜图（storyboard image）机制空转 | generated_images 表与 JOIN 存在，但生成任务链路（STORYBOARD_IMAGE_GEN 枚举外）不通 |

## 四、对齐方案

### 总体思路

不推翻现有 SCRIPT_SPLIT 骨架，按"**补链路而非改架构**"分三阶段实施。数据模型（四层结构 + 八字段 + 两张关联表 + 版本快照表）已与 LuxReal 五级模型基本同构，缺的是写入方和执行链路。

```
阶段一（P0）：打通资产参考图链路 —— 让"引用资产"成立
阶段二（P0）：独立分镜脚本生成阶段 —— 让"先生成分镜脚本"成立（可重跑/可重生成）
阶段三（P1）：镜头级操作与参数落库 —— 对齐 LuxReal 生成粒度
```

### 阶段一：打通资产参考图链路（G4 + G5，目标步骤 2 的前提）

**1. 资产自动建链（写入方）**

- 位置：`SplitHandler.Execute` 拆分入库成功后（`SaveSplitResult` 事务内或紧随其后）。
- 规则（对应 LuxReal"简化模式：描述即生效"）：
  - 遍历每个叙事单元，对其覆盖的 shots 的 `subject_description` / `background_description` / 台词角色名做实体匹配（角色名/场景名/道具名，与 characters/scenes/props 表按集 + 别名匹配）；
  - 命中即写 `nu_asset_links`（单元级，unit_id + asset_type + asset_id + 出现频次）；
  - 镜头级命中再细化写 `shot_asset_refs`（shot_id + asset_id + 用途标签 subject/background），对应 LuxReal `@` 精准指定用途；
  - 同时回写 `shots.linked_assets_json`（供前端 chips 直接渲染）。
- 已有存量项目：提供一次性回填（可复用同一匹配函数，按 episode 扫描补链）。

**2. 多参考图传参打通（G5）**

- `AsyncTaskProvider.GenerateVideo`：`RefImageURLs` 非空时按厂商规范转发——火山 Seedance 使用首帧 `image_url` + 参考图列表字段（以 ark 实际字段为准，如 `reference_images`）；单图时保持现状 `image_url`。
- `VideoHandler`：`LoadShotRefs` 返回多图时按"角色图优先、场景图次之"排序，截取上限（对齐 LuxReal ≤9 张）；同时把尾部全局约束指令（G3）追加到 prompt_refined 之后：
  > "严格按照分镜脚本进行生成，参考上传图的人物形象、场景和道具。不要生成字幕。"

**3. 参考图未就绪的门控（对齐 LuxReal code=6002）**

- `GenerateVideos` 提交前检查：镜头命中了资产关联但资产 `main_image_url` 为空 → 返回明确错误码引导回 Step2（替代现在的前端软文案提示）；资产全部就绪或镜头本无关联资产才允许纯 T2V。

**验收标准**：
- 新拆分项目：`nu_asset_links`/`shot_asset_refs` 有数据；Worker 日志出现参考图 URL（refURLs 非空）；生成视频带首帧/参考图（is_mock=false 且非纯 T2V）。
- 前端 Step3 镜头卡参考图 chips 渲染真实 `assets.main_image_url`（替换渐变占位，数据源 `GET /episodes/:id/asset-links` 已有）。

### 阶段二：独立分镜脚本生成阶段（G1 + G2，目标步骤 1）

**1. 落地 STORYBOARD_PLAN_V1_LUXCHAT 任务（复用已定义枚举）**

- 创建入口：改造 `GenerateStoryboards`（现为 mock）→ 真实创建 STORYBOARD_PLAN 任务 + outbox 投递（queue 复用 'split'，LLM 类任务）。
- 新增 `StoryboardPlanHandler`（Worker 'split' role 或全能 role 注册）：
  - 输入：叙事单元剧本原文（narrative_units.script_text）+ 时长预设 + 单元已关联资产清单（阶段一的 nu_asset_links，注入到 prompt 中供 LLM 在分镜里显式引用资产名）；
  - LLM Prompt：参照 LuxReal「剧情细腻刻画」模板结构——按目标时长拆镜头数、每镜头强制 8 字段、台词格式约束、尾部全局约束指令；
  - 后处理：复用现有 `SplitOversizedUnits` 的时长/镜头数校验逻辑；
  - 写入：事务内 DELETE 该单元旧 shots（软删）→ INSERT 新 shots + shot_groups → 写 `narrative_unit_versions` 新版本快照（对齐 LuxReal 历史版本可回滚）；
  - 版本回滚端点已有，补"回滚即恢复该版快照的 shots"逻辑。
- 覆盖 `ReplanBeat`（BEAT_REPLAN 枚举外）：统一收敛到 STORYBOARD_PLAN 任务，删除枚举外硬编码 INSERT。

**2. 与 SCRIPT_SPLIT 的关系（关键设计决策）**

- SCRIPT_SPLIT 保持"拆分即出初版分镜"（现状不动，作为 v1 版本）；
- STORYBOARD_PLAN 作为"对单个叙事单元重新生成分镜脚本"的独立技能（v2+ 版本），对应 LuxReal「重新规划弹窗：Tab2 重生成分镜」；
- 这样既保留现有可用链路，又满足"根据原文（单元剧本）生成分镜脚本"的目标流程，且天然获得版本管理。

**验收标准**：
- Step3 页面对某叙事单元点"重新规划/生成分镜脚本" → 创建 STORYBOARD_PLAN 任务 → WS 推送 → 新版分镜入库 → 历史版本列表出现 v2 → 可回滚 v1；
- 单镜头 8 字段完整、镜头总时长落在单元时长预设 ±20% 内。

### 阶段三：镜头级操作与参数落库（G6 + G7 + G8，P1）

- 单镜头"生成视频"：前端接 `RegenerateShot`（后端已有），走 VIDEO_SEGMENT_GEN 单任务 + outbox；
- 镜头块批量：修 `GenerateShotGroupVideo`，补 outbox 投递，复用 VIDEO_SEGMENT_GEN（同块顺序生成可后置 seed 连续性优化）；
- 镜头块拼接：修 `ComposeBeatVideo` 的 VIDEO_GROUP_CONCAT 创建入口补 outbox（handler 已覆盖）；
- 参数落库：生成弹窗提交 video_model/resolution → 写 `shots.ai_model` + 任务参数，VideoHandler 优先读 shot.ai_model（去掉硬编码 P720）；
- 枚举清理：STORYBOARD_IMAGE_GEN/EDIT、TTS_VOICE_GEN 若暂不做，从 storyboard_service 移除对应 mock 端点（避免 DB 枚举错误）；若做则先扩 task_type_enum 迁移。

### 实施顺序与依赖

```
阶段一.1 资产建链（无外部依赖，先行）
   ├─→ 阶段一.2 多参考图传参（依赖建链数据才能验证）
   │       └─→ 阶段一.3 门控
   └─→ 阶段二 分镜重生成（prompt 中引用资产清单，依赖建链）
           └─→ 阶段三 镜头级操作（独立，可并行）
```

### 风险与注意事项

| 风险 | 应对 |
|------|------|
| 实体匹配误命中（角色名撞词） | 匹配限定"按集抽取的资产清单"内 + 别名表；频次阈值；单元级先于镜头级，可人工在 Step3 调整（前端已有 asset-links 数据源） |
| 厂商多参考图字段差异 | 阶段一.2 先以火山 Seedance 为唯一验证对象（项目已走通 ark 图片链路）；其余 provider 保持单图兼容 |
| 重生成删除旧 shots 的外键/任务残留 | 软删 + 拒绝对存在 RUNNING 视频任务的单元重规划（409，对齐 LuxReal code=6003 思路） |
| 存量项目无资产链 | 提供一次性回填脚本；回填前存量项目维持纯 T2V 现状不回归 |

- **阶段二验证**：`narrative_unit_versions` 版本号递增；任务表出现 STORYBOARD_PLAN_V1_LUXCHAT 记录且 status=SUCCESS；回滚后 shots 与 v1 快照一致。
- **回归项**：SCRIPT_SPLIT 既有项目（如项目 89/81）拆分流程不受影响；积分冻结/豁免逻辑（freezeNeeded）在单镜头重生成下正确。
